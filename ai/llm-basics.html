大模型基础概念 ​

前端工程师不需要会推导 Attention 公式，但必须建立对大模型的「工程直觉」——知道 Token 怎么算、上下文为什么会满、幻觉为什么无法根除、模型调用为什么要绕到 BFF。本文按「前端为什么要懂 → 基本原理 → 核心概念 → 能力与局限 → 模型生态 → 调用链路 → Prompt 工程 → 常见坑」组织。流式交互落地见 流式渲染与 AI 交互界面，多厂商接入见 多模型接入与前端 SDK。

覆盖 JD 对应点：#9 今天国际把「AI 协作能力」列为硬性第 2 条、#10 欣农互联要求 AI 产品前端（问答/Agent/RAG）、#3 腾讯外包涉及 AI Agent 界面与 AI 研发提效。

一、前端为什么要懂大模型 ​

面试里问「Token 是什么」「上下文窗口满了怎么办」，考的不是你会不会调 API，而是你能不能为 AI 产品的工程决策负责：

业务决策需要的大模型知识
会话历史要不要裁剪、怎么裁上下文窗口、Token 计费
回答不准，是换模型还是加 RAG幻觉根因、知识截止、RAG 链路
打字机效果为什么不能直接改 DOM自回归生成、增量 delta
用户问「你这答案哪来的」引用溯源、Embedding 相似度
API Key 该放哪模型调用链路、鉴权边界
要不要给模型加工具Function Calling / Agent 循环

一句话：AI 产品前端的复杂度不在「画聊天框」，而在「理解模型边界并把它翻译成可用的交互」。

二、LLM 基本原理 ​

2.1 Transformer 直觉 ​

2017 年《Attention Is All You Need》提出的 Transformer 是现代大模型骨干，核心是自注意力（Self-Attention）：序列中每个 Token 都会与其他所有 Token 计算相关性权重，从而捕捉长距离依赖。工程上有两个直接后果：

  • 注意力计算量随序列长度近似平方增长 → 上下文窗口不可能无限大，长上下文的成本与延迟都陡增。
  • KV Cache 是流式输出的前提：已生成 Token 的 Key/Value 被缓存，后续每步只算新 Token，否则每吐一个字都要全量重算。

2.2 预训练与推理 ​

  • 预训练（Pre-training）：在海量语料上做「预测下一个 Token」的自监督训练，产出基座模型。此阶段模型学到的是语言规律与世界知识的统计分布，不是「事实数据库」。
  • 对齐（Alignment）：SFT（监督微调）+ RLHF/DPO 让模型学会遵循指令、拒绝有害请求、输出更有用的格式。
  • 推理（Inference）：用户请求时前向计算，逐 Token 采样输出。推理是无状态的——模型本身不记得上一轮，所有「记忆」都靠把历史消息重新拼进请求。

2.3 自回归生成：流式的根因 ​

输入: "今天天气"
第 1 步 → 采样出 "很"
第 2 步 → 把 "今天天气很" 作为新输入 → 采样 "好"
第 3 步 → "今天天气很好" → 采样 "，"
... 直到生成 <EOS> 或达到 max_tokens

关键结论：模型天然是一个 Token 一个 Token 蹦出来的，不是算完再返回。所以 stream: true 不是「优化技巧」，而是对生成方式的如实暴露——这也是前端必须用 SSE / Fetch Stream 接收的根本原因。

三、核心概念 ​

3.1 Token 与分词（Tokenizer） ​

模型不处理字符，而是先把文本用 BPE（Byte Pair Encoding） 之类的算法切成 Token，每个 Token 映射到一个整数 ID。

文本大致 Token 数（GPT 系列 tiktoken）说明
hello world2英文常见词约 1 词 1 Token
你好，世界4–6中文 1 字约 1–2 Token，标点也占
Vue.js 是一个渐进式框架12–15中英混排按子词切分
"12345678"2–3数字串常被合并为少数 Token

前端做用量预估可用官方 tiktoken（JS 版 @dqbd/tiktoken / js-tiktoken）：

ts
// 发送前预估 Token，用于裁剪与成本提示
import { encoding_for_model } from 'js-tiktoken'

const enc = encoding_for_model('gpt-4o-mini')
export function countTokens(text: string): number {
  return enc.encode(text).length
}

// 线性近似兜底：中文字符加权，省去加载分词表
export function approxTokens(text: string): number {
  const cjk = (text.match(/[\u4e00-\u9fa5]/g) ?? []).length
  const others = text.length - cjk
  return Math.ceil(cjk * 1.6 + others * 0.3)
}

注意：不同厂商分词器不同，DeepSeek / 通义对中文分词做过优化，同一段中文的 Token 数可能比 OpenAI 少。跨厂商做预算时按各家口径算，别拿一个数到处套。

3.2 上下文窗口（Context Window） ​

模型一次请求能处理的最大 Token 数（输入 + 输出共用）。典型档位：

档位代表模型适用场景
8KGPT-3.5 早期简单问答
32KGPT-4 标准长文档问答
128KGPT-4o / Claude 3 / DeepSeek-V3代码库分析、长合同
200K+Claude 3.5 / Kimi整本书、超大仓库

多轮为什么会「遗忘」：模型无记忆，每轮把全部历史重发。第 20 轮把 20 轮消息全拼上就可能超窗——要么报错，要么被静默截断早期消息，用户感知就是「AI 忘了刚才说的话」。

前端裁剪策略（面试高频）：

ts
// 按 Token 预算裁剪：保留 system + 最近 N 轮，从最早的消息开始丢
function trimByBudget(
  messages: { role: string; content: string }[],
  budget: number,
  counter: (s: string) => number,
) {
  const system = messages.filter((m) => m.role === 'system')
  const rest = messages.filter((m) => m.role !== 'system')
  const used = system.reduce((n, m) => n + counter(m.content), 0)

  const kept: typeof rest = []
  // 从最新往旧累积，超预算即停（保证最近上下文一定存在）
  for (let i = rest.length - 1; i >= 0; i--) {
    const cost = counter(rest[i].content)
    if (used + cost > budget) break
    kept.unshift(rest[i])
  }
  return [...system, ...kept]
}

3.3 温度与采样：temperature / top_p ​

模型输出不是取「概率最高的词」，而是按分布采样，两个关键旋钮：

  • temperature：对 logits 缩放。0 近似贪心（最确定、易重复），0.7 平衡，>1 更随机。技术问答/代码建议用 0–0.3，创意文案用 0.8–1.0。
  • top_p（核采样）：只在累积概率达到 p 的最小词集里采样。0.9 表示砍掉尾部 10% 的长尾词。
  • 工程约定：两者通常只调一个（官方建议改 temperature 就别动 top_p），同时调会互相干扰、难以复现问题。
ts
const body = {
  model: 'deepseek-chat',
  messages,
  temperature: 0.2, // 结构化输出、代码补全场景压低温度
  // top_p 保持默认，不叠加
}

3.4 Embedding、向量与相似度 ​

Embedding 模型把文本映射为固定维度向量（如 1536 维 float 数组），语义相近则向量方向相近。

"猫"  → [0.12, -0.45, 0.78, ...]  ┐
"狗"  → [0.15, -0.42, 0.81, ...]  ├─ 方向接近
"汽车" → [-0.82, 0.33, -0.11, ...] ┘ 方向背离

相似度用余弦相似度（只关注方向、不关注模长，故对文本长度更鲁棒）：

ts
export function cosineSimilarity(a: number[], b: number[]): number {
  let dot = 0, na = 0, nb = 0
  for (let i = 0; i < a.length; i++) {
    dot += a[i] * b[i]
    na += a[i] * a[i]
    nb += b[i] * b[i]
  }
  return dot / (Math.sqrt(na) * Math.sqrt(nb) || 1)
}

前端用到它的位置：检索结果按分数排序与色阶展示、语义去重、相似问题推荐。

3.5 RAG（检索增强生成） ​

RAG 给模型「外挂开卷材料」，解决四类问题：幻觉（提供事实依据）、知识截止（注入最新文档）、私域知识（把内部文档向量化）、可溯源（返回引用）。

离线索引: 文档 → 切分 chunk（如 500 字/段，带重叠） → Embedding → 写入向量库
在线检索: 问题 → Embedding → 向量库 Top-K → 拼进 Prompt 作为 context → LLM 生成（附引用）

前端的活：文档上传与解析进度、知识库管理、召回结果高亮、回答角标 [1] 与底部来源卡片联动。详见 Agent 编排与 RAG 界面。

3.6 Agent 与 Function Calling / Tool Calling ​

普通对话是「文本进、文本出」；Agent 是「感知 → 规划 → 执行 → 观察 → 再规划」的循环，模型能主动调用外部工具。

Function Calling（工具调用）是 Agent 的基石：

1. 请求里声明工具: tools: [{ type:'function', function:{ name, description, parameters } }]
2. 用户: "查一下北京明天天气"
3. 模型返回: tool_calls: [{ id, function: { name: 'get_weather', arguments: '{"city":"北京"}' } }]
   —— 注意 arguments 是 JSON 字符串，需 JSON.parse
4. 后端/前端执行真实 API，得到结果
5. 以 role:'tool' + tool_call_id 把结果回传
6. 模型基于结果生成自然语言回答

前端职责：声明可用工具、把 tool_calls 渲染成可视化步骤卡、高风险工具加 Human-in-the-loop 确认、把结果按约定格式回传。finish_reason: 'tool_calls' 意味着本轮不是最终答案，要等工具结果再发起下一轮。

3.7 多模态（Multimodal） ​

现代主流模型原生支持文本 + 图片 + 音频混合输入，请求里把图片按 base64 或 URL 放进 content 数组：

ts
const messages = [{
  role: 'user',
  content: [
    { type: 'text', text: '这张图里的报错是什么原因？' },
    { type: 'image_url', image_url: { url: 'data:image/png;base64,iVBORw0...' } },
  ],
}]

前端关注点：图片压缩（手机原图动辄数 MB，先降采样再传）、按视觉 token 计费、图片跨域与鉴权（URL 形式要签临时链接）。

四、模型能力与局限 ​

局限根因前端缓解手段

核心认知：幻觉无法根除，只能工程缓解。产品要做的不是「让模型不说错」，而是「让用户能判断这句能不能信」。

六、前端视角的模型调用链路 ​

错误做法：浏览器直接 fetch('https://api.openai.com/v1/chat/completions')，把 Key 打进前端产物。

错误: 浏览器 ──(携带真实 API Key)──► 模型厂商
      问题: Key 出现在 JS 产物与 Network 面板；多数厂商不支持 CORS 直连；无鉴权无审计无法限流

正确做法：走自家 BFF（Backend For Frontend）。

浏览器 ──(Session/JWT)──► BFF ──(注入 Key)──► 模型厂商
                            ├─ 鉴权（登录态校验）
                            ├─ 限流（按用户/租户配额）
                            ├─ Key 注入（从环境变量/KMS 读）
                            ├─ 审计（requestId、模型、token 用量）
                            ├─ 敏感词过滤 / 内容合规
                            └─ SSE 透传 + 心跳保活 + 失败降级

要记的边界：前端只持有短期会话凭证，永不持有模型厂商 Key；开发期为了演示放的「Key 输入框」在生产必须禁用。

七、Prompt 工程基础 ​

前端的 Prompt 工程不是写小说，而是把自然语言请求变成稳定可解析的结构化契约。四个要素：

  1. 角色（Role）：system 里定义身份与边界（「你是电商客服助手，只回答订单与物流问题，其他一律转人工」）。
  2. 指令（Instruction）：动词明确、单次单目标（「提取字段」而不是「理解并处理这段文本」）。
  3. 少样本（Few-shot）：给 1–3 组「输入 → 期望输出」示例，比大段描述更有效。
  4. 结构化输出（Structured Output）：用 JSON Schema 约束，前端直接可解析，避免正则抠文本。
ts
// 用 JSON Schema 约束模型输出，前端拿到即可渲染
const responseFormat = {
  type: 'json_schema',
  json_schema: {
    name: 'ticket_classify',
    strict: true,
    schema: {
      type: 'object',
      properties: {
        category: { type: 'string', enum: ['物流', '退款', '咨询', '其他'] },
        urgency: { type: 'integer', minimum: 1, maximum: 5 },
        summary: { type: 'string', maxLength: 60 },
      },
      required: ['category', 'urgency', 'summary'],
      additionalProperties: false,
    },
  },
} as const

前端消费时要防御式解析——即便声明了 strict，仍要校验：字段缺失、枚举越界、JSON 截断都真实发生。

八、实战要点与常见坑 ​

  1. 拿一个分词器算所有厂商的 Token：会算偏，尤其中文。至少区分「OpenAI 系」与「国产优化分词」两类。
  2. 上下文窗口按输入算、忘了输出：输入 + 输出共用窗口，还要给 max_tokens 留位置，否则报 context_length_exceeded。
  3. arguments 当对象用：Function Calling 返回的是 JSON 字符串，必须 JSON.parse 并 try/catch。
  4. temperature 和 top_p 同时调：问题难复现，工程上二选一。
  5. 把幻觉当成 bug 修：幻觉是概率生成的固有属性，正确姿势是加溯源与提示，而非指望「换个模型就好」。
  6. 前端直连厂商：Key 泄露 + CORS + 无审计，生产一律走 BFF。
  7. 长会话不裁剪：用户聊到第 30 轮突然「AI 失忆」或直接报错，提前做 Token 预算。
  8. 结构化输出不做二次校验：模型偶尔会多带 markdown 围栏或截断，前端必须兜底。
  9. 忽略 finish_reason：tool_calls / length / content_filter 的分支处理缺一个就出线上问题。

面试要点 ​

  1. 大模型为什么是流式输出的？ 因为自回归生成——逐个 Token 采样，stream:true 只是如实暴露生成过程，前端据此做增量渲染。
  2. Token 和字符是什么关系？中文为什么更贵？ Token 是分词后的子词单位；中文一个汉字常被切成 1–2 Token，同样语义消耗约为英文的 1.5–2 倍，故更贵。
  3. 上下文窗口满了怎么办？ 滑动窗口、摘要压缩、按 Token 预算裁剪，或直接提示开启新会话；工程上推荐「system + 早期摘要 + 最近 N 轮」组合。
  4. temperature 和 top_p 有什么区别？ temperature 缩放概率分布改随机性，top_p 截断长尾按累积概率采样；两者通常只调一个。
  5. Embedding 是什么？为什么用余弦相似度？ 把文本映射到高维向量，语义近则方向近；余弦只看方向不看模长，对文本长度更鲁棒。
  6. RAG 怎么缓解幻觉？ 检索权威文档作为事实依据注入 Prompt 并返回引用，把「模型记忆」换成「可查证来源」。
  7. Agent 和普通对话的本质区别？ Agent 是「感知-规划-执行-观察」循环，模型能输出结构化工具调用指令，具备「手」（工具）和「眼」（工具结果）。
  8. Function Calling 的完整流程？ 声明 tools → 模型返回 tool_calls → 执行工具 → 以 role:'tool' 回传结果 → 模型生成最终回答；arguments 是 JSON 字符串。
  9. 为什么前端不能直连模型 API？ Key 会被打进产物、出现在抓包；CORS 与鉴权缺失；无法限流审计。必须走 BFF 代理。
  10. 幻觉为什么无法根除？ 模型训练目标是生成「像人话」的文本而非「正确」的文本，概率生成本身就会填补未知，只能靠 RAG、引用、确认等工程手段缓解。
