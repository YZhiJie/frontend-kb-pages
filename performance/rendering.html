渲染性能优化 ​

对应 JD 的「渲染性能 / 虚拟滚动 / re-render 治理 / 长列表」要求。本页把"做过"升级为"讲得清原理、说得清取舍"。

一、浏览器渲染流水线 ​

JS/CSS → Style（样式计算）→ Layout（布局/重排）→ Paint（绘制）→ Composite（合成）
          重绘只需 Paint+Composite；重排需从 Layout 走完全流程
阶段触发条件代价
Style选择器匹配、类名变化低
Layout几何属性变化（width/height/top/font-size/padding）高，可能整棵渲染树重排
Paint视觉属性变化（color/background/box-shadow/visibility）中
Composite仅 transform/opacity，且已提升为合成层低（GPU）

1.1 触发重排的典型操作 ​

  • 读写几何属性：offsetTop、offsetWidth、scrollTop、clientHeight、getBoundingClientRect()、getComputedStyle()、scrollWidth。
  • 修改 width/height/margin/padding/border/font-size/line-height/display/position。
  • 增删 DOM 节点、改 innerText/textContent、window.resize、scroll 中同步读取布局。

1.2 读写分离与规避重排 ​

js
// 坏例：读-写-读-写交替，每次都强制同步布局（layout thrashing）
for (const el of items) {
  const h = el.offsetHeight;        // 读 → 触发 layout
  el.style.height = h + 10 + 'px';  // 写 → 作废布局缓存
}
// 好例：读写分离（batch）
const heights = items.map((el) => el.offsetHeight);                     // 集中读
items.forEach((el, i) => { el.style.height = heights[i] + 10 + 'px'; }); // 集中写
// 更好：改 class 或 CSS 变量，让浏览器一次算完
items.forEach((el) => el.classList.add('expanded'));
css
.card { will-change: transform; }
.card:hover { transform: translate3d(0, -4px, 0); opacity: 0.96; } /* 跳过 Layout/Paint */
.animating { will-change: transform, opacity; }                    /* 只在动画期间开启 */

1.3 合成层与 will-change ​

  • 提升合成层的常见触发：will-change、transform: translateZ(0)、backface-visibility: hidden、filter、opacity < 1。
  • 合成层由 GPU 独立绘制，动画只走 Composite；但层数过多会吃显存并增加栅格化开销，移动端尤其明显。
  • will-change 不要常驻：给长列表每项都加反而更慢；正确做法是动画前临时添加，结束置 will-change: auto。
  • 用 DevTools → Layers 面板查看层数与慢层（Paint count 高、缺 GPU 栅格化）。

1.4 强制同步布局（FSL） ​

一次 JS 任务里"写样式后立刻读几何属性"会强制浏览器立即计算布局，例如 el.style.width = '200px'; const w = el.clientWidth;。规避方式是把读取挪到下一帧，此时布局已批量完成：el.style.width = '200px'; requestAnimationFrame(() => { const w = el.clientWidth; });。

1.5 rAF、批量更新与 rIC ​

js
// requestAnimationFrame：与刷新率对齐，每帧只跑一次；后台标签页会自动暂停
function animate() {
  el.style.transform = `translateX(${x++}px)`;
  if (x < 300) requestAnimationFrame(animate);
}
requestAnimationFrame(animate);
// 批量更新：把多次状态变更合并到一帧内执行，避免抖动
let pending = false;
function scheduleRender(fn) {
  if (pending) return;
  pending = true;
  requestAnimationFrame(() => { pending = false; fn(); });
}
// requestIdleCallback：浏览器空闲时执行低优先级任务（Safari 需 setTimeout 兜底）
requestIdleCallback((deadline) => {
  while (deadline.timeRemaining() > 0 && tasks.length) doTask(tasks.shift());
  if (tasks.length) requestIdleCallback(handleIdle, { timeout: 1000 });
}, { timeout: 2000 });

二、长任务与时间切片 ​

js
// 采集：主线程单次占用 > 50ms 即长任务，会阻塞输入与下一帧
new PerformanceObserver((list) => {
  for (const e of list.getEntries()) console.warn('longtask', e.duration, e.attribution);
}).observe({ type: 'longtask', buffered: true });
// 时间切片：每片 ≤5ms，中间让出主线程
const schedule = window.requestIdleCallback ?? ((cb) => setTimeout(() => cb({ timeRemaining: () => 0 }), 0));
function chunkRun(items, handler, chunkMs = 5) {
  let i = 0;
  (function run() {
    const start = performance.now();
    while (i < items.length && performance.now() - start < chunkMs) handler(items[i++]);
    if (i < items.length) schedule(run);
  })();
}
// React 18 并发特性：把非紧急更新标记为可中断（内部 Scheduler 把渲染切成 5ms 片）
function onSearch(kw: string) {
  setKeyword(kw);                              // 紧急：输入框立即回显
  startTransition(() => setList(filter(kw)));  // 非紧急：可被打断
}
const deferred = useDeferredValue(list);       // 延迟非关键渲染

三、虚拟滚动 ​

原理：只渲染可视区 + 缓冲区的 DOM，用一个撑高的占位元素维持滚动条长度。

总高度 = itemCount × itemHeight
可视区索引 = [floor(scrollTop / itemHeight) - buffer, ceil((scrollTop + viewportH) / itemHeight) + buffer]
偏移渲染 = translateY(startIndex × itemHeight)

3.1 固定高度实现 ​

ts
interface Options { itemHeight: number; buffer?: number; container: HTMLElement; total: number }
class VirtualList {
  private start = 0; private end = 0;
  private buffer: number;
  constructor(private opts: Options) {
    this.buffer = opts.buffer ?? 3;
    opts.container.addEventListener('scroll', this.onScroll, { passive: true });
  }
  private onScroll = () => {
    const { container, itemHeight } = this.opts;
    const visible = Math.ceil(container.clientHeight / itemHeight);
    const start = Math.max(0, Math.floor(container.scrollTop / itemHeight) - this.buffer);
    const end = start + visible + this.buffer * 2;
    if (start !== this.start || end !== this.end) { this.start = start; this.end = end; this.render(); }
  };
  render() {
    const { container, itemHeight, total } = this.opts;
    container.querySelector('.phantom')!.style.height = `${total * itemHeight}px`; // 撑高占位
    const inner = container.querySelector('.viewport') as HTMLElement;
    const html = [];
    for (let i = this.start; i < Math.min(this.end, total); i++) {
      html.push(`<div class="row" style="height:${itemHeight}px">${this.renderItem(i)}</div>`);
    }
    // 用 transform 平移而非改 top，避免重排
    inner.style.transform = `translateY(${this.start * itemHeight}px)`;
    inner.innerHTML = html.join('');
  }
  renderItem(_i: number): string { return ''; }
}

3.2 动态高度 ​

两种主流方案：

  1. 预估 + 测量回填（推荐）：初始给 estimatedHeight，渲染后用 ResizeObserver 测量真实高度写回缓存，并修正总高与偏移。
  2. 二分查找定位：维护 offsets（每项起始位置前缀和），用二分在 scrollTop 上定位 startIndex，复杂度 O(log n)。
ts
function findIndex(offsets: number[], scrollTop: number) {
  let lo = 0, hi = offsets.length - 1;
  while (lo < hi) {
    const mid = (lo + hi + 1) >> 1;
    if (offsets[mid] <= scrollTop) lo = mid; else hi = mid - 1;
  }
  return lo;
}
// 测量回填：ResizeObserver 拿到真实高度，delta 局部修正前缀和与总高
const ro = new ResizeObserver((entries) => {
  for (const e of entries) {
    const i = Number((e.target as HTMLElement).dataset.index);
    const old = measured[i] ?? estimated;
    measured[i] = e.contentRect.height;
    if (measured[i] !== old) rebuildOffsetsFrom(i);
  }
});

3.3 缓冲区与双端复用 ​

  • buffer 取 2–5 个视口项：太小快速滚动会露白，太大失去虚拟化收益；滚动监听 { passive: true }，回调内只算索引，DOM 变更放 requestAnimationFrame。
  • 平移用 transform，不要逐项改 style.top。
  • 逻辑下沉 shared 层：把"索引计算 / 高度缓存 / 二分定位 / 总高修正"抽成与框架无关的 VirtualCore，React/Vue/RN 各写薄适配层。RN 的 FlatList/FlashList 需要 getItemLayout（固定行高）才能精确跳转。

四、re-render 治理 ​

4.1 React：memo / useMemo / useCallback ​

tsx
const Row = React.memo(function Row({ data, onSelect }: RowProps) {
  return <div onClick={() => onSelect(data.id)}>{data.name}</div>;
});
const onSelect = useCallback((id: string) => setSelected(id), []);        // 稳定引用，否则 memo 失效
const filtered = useMemo(() => heavyFilter(list, kw), [list, kw]);       // 缓存昂贵计算
{list.map((it) => <Row key={it.id} data={it} onSelect={onSelect} />)}    // key 用稳定 id，勿用 index

注意：useMemo/useCallback 自身有开销，只在"计算昂贵"或"引用需稳定"时用；React.memo 只做浅比较，传入对象/数组字面量每次都是新引用，等于白 memo。

4.2 Zustand 精确 selector 订阅 ​

ts
import { create } from 'zustand';
import { useShallow } from 'zustand/react/shallow';

const useStore = create<State>((set) => ({ count: 0, text: '', inc: () => set((s) => ({ count: s.count + 1 })) }));

const count = useStore((s) => s.count);                                     // 只订阅 count
const { count: c, text } = useStore(useShallow((s) => ({ count: s.count, text: s.text }))); // 返回对象必须浅比较

原理：Zustand 基于 useSyncExternalStore 订阅 store，每次变更跑一遍 selector，只有返回值 Object.is 不等才触发订阅组件重渲染，所以 selector 必须最小粒度。

4.3 Vue：shallowRef / v-memo ​

vue
<script setup lang="ts">
import { shallowRef } from 'vue';
// 大对象只做浅响应，避免 Proxy 深代理的遍历开销（如 1w 条 IoT 数据）
const rows = shallowRef<Row[]>([]);
function setRows(next: Row[]) { rows.value = next; } // 整体替换触发；push 不会触发，需 triggerRef
</script>
<template>
  <!-- v-memo：依赖数组不变时整块子树跳过更新 -->
  <div v-for="item in rows" :key="item.id" v-memo="[item.id, item.status]"><Row :data="item" /></div>
</template>

Vue 3 的 reactive 是 Proxy 深代理，深层读写会触发大量依赖收集/触发；超大列表改 shallowRef + 整体替换最省。v-memo 仅在"列表项多且更新频繁"时有收益。

4.4 避免 Context 全量重渲染与状态提升 ​

tsx
// 坏例：整个对象丢下去，任一字段变化都重渲染所有消费者
<AppCtx.Provider value={{ user, theme, count }}>{children}</AppCtx.Provider>
// 好例：拆多个 Context 按变化频率分离，value 用 useMemo 稳定引用
const value = useMemo(() => ({ user, theme }), [user, theme]);
<UserCtx.Provider value={user}><ThemeCtx.Provider value={theme}>{children}</ThemeCtx.Provider></UserCtx.Provider>

状态提升原则：把"变化的部分"下移到最贴近消费者的组件，用本地 state 而非全局；store 只放真正的跨组件共享状态。

六、内存泄漏排查 ​

泄漏源修复
未移除的事件监听存引用解绑，或 AbortController 批量解绑
未清理的定时器clearInterval / useEffect 返回值清理
闭包持有大对象缩小闭包捕获范围、卸载后置 null
全局引用未分离用 WeakMap/WeakRef，卸载时删除
未断开的订阅/Observerstore 订阅、WebSocket、ResizeObserver 统一 destroy()
ts
useEffect(() => {
  const ac = new AbortController();
  window.addEventListener('scroll', onScroll, { passive: true, signal: ac.signal });
  fetch('/api', { signal: ac.signal });
  const ro = new ResizeObserver(onResize); ro.observe(ref.current!);
  const timer = window.setInterval(tick, 1000);
  return () => { ac.abort(); ro.disconnect(); clearInterval(timer); };
}, []);

排查手法：DevTools Memory 面板 → 交互前后各拍 Heap Snapshot → Comparison 视图看 Detached DOM tree 与对象增长；Performance Monitor 看 JS Heap 曲线是否一直涨不回落。

七、Performance 面板实战与火焰图 ​

  • 录制流程：Performance → 录制 → 复现 3–5s 操作 → 停止。
  • 看火焰图（Main 轨道）：横向宽度=耗时，纵向=调用栈深度；找 Long Task（红色三角） 与最宽的堆栈块。
  • 常见诊断：Recalculate Style 频繁 → 类名频繁切换或选择器过复杂；Layout 反复 → 读写布局交替（FSL）；Scripting 占比高 → 长任务拆时间切片或挪 Worker；帧超 16.7ms → 掉帧。
  • 用 Bottom-Up / Call Tree / Event Log 定位具体函数，配合自定义标记：
ts
performance.mark('list-render-start');
renderList();
performance.mark('list-render-end');
performance.measure('list-render', 'list-render-start', 'list-render-end');

面试要点 ​

  1. 简述渲染流水线，哪些阶段可跳过？ 答：JS/CSS → Style → Layout → Paint → Composite；只改 transform/opacity 且已合成层时可跳过 Layout 与 Paint，只走 Composite。
  2. 什么是强制同步布局（FSL），怎么避免？ 答：一次 JS 任务里"写样式后立刻读几何属性"会强制立即布局；应读写分离（集中读→集中写）或把读取挪到下一帧/rAF。
  3. will-change 有什么坑？ 答：会提升合成层，滥用吃显存并增加栅格化开销；只在动画期间临时添加，结束置 auto，避免长列表每项常驻。
  4. 从零实现虚拟滚动，关键步骤？ 答：占位元素撑总高、按 scrollTop 算可视索引区间、translateY 平移渲染窗口、给缓冲区、滚动回调 passive 且变更放入 rAF。
  5. 动态高度虚拟滚动怎么做？ 答：预估高度 + ResizeObserver 测量回填修正前缀和与总高；或用 offset 前缀和 + 二分查找定位 startIndex，做到 O(log n)。
  6. React 里 memo 为什么经常失效？ 答：props 传对象/数组字面量或内联函数导致每次都是新引用，浅比较必然不等；需配合 useCallback/useMemo，key 用稳定 id。
  7. Zustand 精确 selector 的原理？ 答：基于 useSyncExternalStore 订阅，selector 返回值 Object.is 变化才触发订阅组件更新；返回对象要用 useShallow 浅比较。
  8. Vue 3 里大列表为什么偏好 shallowRef？ 答：reactive 是 Proxy 深代理，深层读写触发大量依赖收集/触发；shallowRef 仅浅响应、整体替换赋值，配合 triggerRef 手动触发，开销更低。
  9. 长任务怎么治理？ 答：longtask Observer 定位；用时间切片（每片 ≤5ms，rIC/setTimeout 让出主线程）、React 并发特性（useTransition/useDeferredValue）、或把纯计算挪到 Web Worker。
  10. 如何排查内存泄漏？ 答：Heap Snapshot 前后对比看 Detached DOM 与对象增长、Performance Monitor 看 Heap 曲线是否持续上升；常见源为未解绑监听/定时器/闭包/全局引用/未 dispose 的订阅。
