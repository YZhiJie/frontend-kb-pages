加载性能优化 ​

对应 JD 的「首屏优化 / 懒加载 / 前端监控 SDK」A 级必守项。目标：既能答"LCP 怎么做到 2.5s 内"，也能独立交付一个可上线的监控 SDK。

一、核心 Web 指标 ​

指标含义良好需改进差
FP首次绘制（不含内容）———
FCP首次内容绘制≤ 1.8s1.8–3.0s> 3.0s
LCP最大内容元素绘制完成≤ 2.5s2.5–4.0s> 4.0s
CLS累计布局偏移≤ 0.10.1–0.25> 0.25
INP交互到下一次绘制（2024 取代 FID）≤ 200ms200–500ms> 500ms
TBT主线程阻塞总时长（Lab）≤ 200ms——
TTI可交互时间≤ 3.8s3.8–7.3s> 7.3s
  • LCP 元素：视口内面积最大的 img/image/video poster/背景图，或块级文本节点；SPA 路由切换后的 LCP 不计入。
  • CLS 只统计输入前 500ms 内且用户不可见的偏移，图片无尺寸、字体切换、动态插入内容是三大元凶。
  • INP 取 P75 分位（非平均），单次长任务就会拉高。

二、指标采集 ​

2.1 PerformanceObserver ​

js
let lcpValue = 0, clsValue = 0;
// LCP：生命周期内可能多次上报，取最后一次
new PerformanceObserver((list) => {
  const e = list.getEntries().at(-1);
  lcpValue = e.startTime;
  console.log('LCP element:', e.element, e.url); // 定位是谁拖慢了 LCP
}).observe({ type: 'largest-contentful-paint', buffered: true });
// CLS：累加非输入触发的 layout-shift；INP：观察交互到下一次绘制的耗时
new PerformanceObserver((list) => {
  for (const e of list.getEntries()) if (!e.hadRecentInput) clsValue += e.value;
}).observe({ type: 'layout-shift', buffered: true });
new PerformanceObserver((list) => {
  for (const e of list.getEntries()) report('inp', e.duration);
}).observe({ type: 'event', durationThreshold: 40, buffered: true });
// 卸载时才上报，避免中途值被覆盖
document.addEventListener('visibilitychange', () => {
  if (document.visibilityState === 'hidden') { report('lcp', lcpValue); report('cls', clsValue); }
}, { capture: true });

结构：采集层 → 处理层（采样/合并/去重）→ 上报层。

3.1 全局异常捕获 ​

ts
// 1. JS 运行时错误：window.onerror 能拿到 error 对象
window.onerror = (message, source, lineno, colno, error) => {
  sdk.track('error', { type: 'js', message: String(message), source, lineno, colno, stack: error?.stack ?? '' });
  return false; // 返回 true 会阻断控制台默认打印，一般不拦
};
// 2. 未处理的 Promise rejection
window.addEventListener('unhandledrejection', (e) => {
  const r = e.reason;
  sdk.track('error', { type: 'promise', message: r instanceof Error ? r.message : String(r),
    stack: r instanceof Error ? r.stack : '' });
});
// 3. 资源加载错误：用捕获阶段监听才能拿到 target，靠 tag 区分以免与 onerror 重复
window.addEventListener('error', (e) => {
  const el = e.target as HTMLElement, tag = el?.tagName?.toLowerCase(); // 'img' | 'script' | 'link'
  if (!tag) return;
  sdk.track('resource-error', { type: tag, url: (el as HTMLImageElement).src });
}, true);
// 4. Vue 全局错误（Vue 3；Vue 2 需 errorHandler + config.errorHandler 双保险）
app.config.errorHandler = (err, _instance, info) =>
  sdk.track('error', { type: 'vue', message: err.message, stack: err.stack, info });
// 5. React 错误边界：兜底隔离而非全量上报
class ErrorBoundary extends React.Component {
  componentDidCatch(error: Error, info: React.ErrorInfo) {
    sdk.track('error', { type: 'react', message: error.message, stack: error.stack,
      componentStack: info.componentStack });
  }
  render() { return this.state.hasError ? <Fallback /> : this.props.children; }
}

3.2 fetch 与 XHR 包装 ​

ts
// 包装 fetch：保留原始引用避免递归
const originalFetch = window.fetch;
window.fetch = async function (input, init) {
  const url = typeof input === 'string' ? input : (input as Request).url;
  const start = performance.now();
  try {
    const res = await originalFetch.apply(this, [input, init]);
    sdk.track('request', { url, duration: performance.now() - start, status: res.status, ok: res.ok });
    return res;
  } catch (err) {
    sdk.track('request-error', { url, duration: performance.now() - start });
    throw err;
  }
};
// 包装 XHR：第三方 SDK/老库常走 XHR，只包 fetch 会漏数据
const XHR = XMLHttpRequest.prototype, rawOpen = XHR.open, rawSend = XHR.send;
XHR.open = function (method, url, ...rest) {
  (this as any).__sdk = { method, url };
  return rawOpen.call(this, method, url, ...rest);
};
XHR.send = function (...args) {
  const info = (this as any).__sdk ?? {}, start = performance.now();
  this.addEventListener('loadend', () =>
    sdk.track('request', { ...info, duration: performance.now() - start, status: this.status }));
  return rawSend.apply(this, args);
};

另需行为数据：慢资源、白屏时间、PV/UV（visibilitychange 上报）、点击埋点（捕获阶段事件委托）。

3.3 上报通道：sendBeacon + 采样 + 重试 + 合并 ​

ts
class Reporter {
  private queue: QueueItem[] = [];
  private timer: number | null = null;
  private MAX_BATCH = 20;   // 单次合并条数
  private FLUSH_MS = 3000;  // 最长攒批时间
  private MAX_QUEUE = 100;  // 队列上限，超出丢最旧，防雪崩
  private RATE = { error: 1, resource: 0.3, perf: 0.1 }; // 采样率
  push(url: string, data: { type: string; [k: string]: unknown }) {
    if (Math.random() >= (this.RATE[data.type] ?? 1)) return;
    this.queue.push({ url, data, retry: 0 });
    if (this.queue.length > this.MAX_QUEUE) this.queue.shift();
    data.type === 'error' ? this.flush() : this.schedule(); // 错误立即报，其余攒批
  }
  private schedule() { if (!this.timer) this.timer = window.setTimeout(() => this.flush(), this.FLUSH_MS); }
  flush() {
    if (this.timer) { clearTimeout(this.timer); this.timer = null; }
    if (!this.queue.length) return;
    const batch = this.queue.splice(0, this.MAX_BATCH);
    const byUrl = new Map<string, unknown[]>();
    batch.forEach((it) => byUrl.set(it.url, [...(byUrl.get(it.url) ?? []), it.data])); // 同 url 合并成一次
    byUrl.forEach((list, url) => this.send(url, list, batch));
  }
  private send(url: string, list: unknown[], origin: QueueItem[]) {
    const body = JSON.stringify(list);
    // sendBeacon 由浏览器接管，页面关闭也能送出；超 64KB 返回 false 需降级
    if (navigator.sendBeacon?.(url, new Blob([body], { type: 'application/json' }))) return;
    fetch(url, { method: 'POST', body, keepalive: true, headers: { 'Content-Type': 'application/json' } })
      .catch(() => { // 失败重试：指数退避，最多 3 次
        origin.forEach((it) => it.retry < 3 && this.queue.push({ ...it, retry: it.retry + 1 }));
        window.setTimeout(() => this.flush(), 2 ** (origin[0]?.retry ?? 1) * 1000);
      });
  }
}

sendBeacon 与 keepalive fetch 都有 64KB 上限；卸载时机优先 visibilitychange。

3.4 Source Map 还原与 Sentry 概念 ​

js
// 构建侧：生成 map 但不上 CDN（'hidden' 模式不写 sourceMappingURL 注释，避免暴露源码）
export default { build: { sourcemap: 'hidden' } };
// 服务端：source-map 库按行列号还原原始位置（用文件名 hash 索引对应 .map）
const { SourceMapConsumer } = require('source-map');
async function resolveStack(rawStack, mapFile) {
  const consumer = await SourceMapConsumer(mapFile);
  const out = rawStack.split('\n').map((line) => {
    // 形如 at fn (https://cdn/app.3f2a1.js:1:23456)
    const m = line.match(/\(?(.*?):(\d+):(\d+)\)?$/);
    if (!m) return line;
    const pos = consumer.originalPositionFor({ line: +m[2], column: +m[3] });
    return `${pos.source}:${pos.line}:${pos.column}  ${pos.name ?? ''}`;
  });
  consumer.destroy();
  return out.join('\n');
}

Sentry 类方案要点：init（DSN/release/environment/tracesSampleRate/beforeSend 脱敏）、captureException/captureMessage、addBreadcrumb（面包屑上限 100）、setUser/setTag；性能侧自动生成 transaction/span；beforeSend 里删 request.headers.cookie 并按正则替换手机号/身份证。部署时把 .map 存私有对象存储并用 release 对齐版本。

四、加载优化手段 ​

4.1 懒加载与代码分割 ​

ts
// Vue Router：按路由分包
{ path: '/dashboard', component: () => import(/* webpackChunkName: "dashboard" */ '@/views/Dashboard.vue') }
// React Router v6
const Dashboard = React.lazy(() => import('@/pages/Dashboard'));

首屏关键路径组件不要懒加载（多一个 RTT 反而拖慢 LCP）；分割粒度按业务路由/大型第三方库/低频功能，分太细会带来大量小请求与 HTTP/2 头部开销。

4.2 Tree Shaking 与压缩 ​

ts
// Vite 默认 ESM + rollup：用 import { debounce } from 'lodash-es'（勿用 lodash 全量）；
// package.json 设 sideEffects: false；避免 CommonJS 入口（会退化为整体引入）
import viteCompression from 'vite-plugin-compression';
export default { plugins: [viteCompression({ algorithm: 'brotliCompress', ext: '.br', threshold: 10240 })] };

brotli 比 gzip 平均小 15–20%；静态资源用 br（构建期 quality 11），动态接口用 gzip 或低级别 br。

4.4 preload / prefetch / preconnect 与缓存 ​

html
<link rel="preconnect" href="https://api.example.com" crossorigin />  <!-- 提前建连 -->
<link rel="dns-prefetch" href="https://cdn.example.com" />

nginx

location ~* \.html$ { add_header Cache-Control "no-cache"; etag on; }

升级链路：带 hash 资源强缓存 + immutable，HTML 协商缓存，CDN 多节点与边缘压缩；进一步用 Service Worker（Workbox precacheAndRoute + staleWhileRevalidate）做离线缓存。

五、构建分析、首屏与慢请求排查 ​

bash
npx vite build && npx vite-bundle-visualizer       # Vite
npx webpack-bundle-analyzer dist/stats.json        # Webpack

按收益排序的排查清单：

  1. 首屏 JS > 200KB（gzip）：定位大依赖（moment→dayjs、lodash→lodash-es、全量 antd→按需），并检查 manualChunks/splitChunks 与 pnpm dedupe 消除重复依赖。
  2. 图片/字体未压缩或未转格式：确认 CDN 处理与 AVIF/WebP。
  3. 同步阻塞脚本：加 defer/async 或改 ESM。
  4. 白屏：SSR/预渲染 + 骨架屏 + 关键 CSS 内联。

慢请求排查：ttfb 判断网络还是后端；resource 瀑布定位慢资源；检查串行请求（改 Promise.all 并行）、冗余预检（OPTIONS）、可合并接口；前端看 P75，服务端看 P95/P99。

面试要点 ​

  1. FCP/LCP/CLS/INP 各衡量什么，目标值多少？ 答：FCP 首内容绘制 ≤1.8s；LCP 最大内容元素 ≤2.5s；CLS 累计布局偏移 ≤0.1；INP 交互到下一次绘制 ≤200ms，均按 P75 口径。
  2. LCP 怎么采集，为什么卸载时才上报？ 答：PerformanceObserver 观察 largest-contentful-paint 取最后一条；LCP 在生命周期内会多次更新，visibilitychange 隐藏时才稳定。
  3. CLS 的三大来源？ 答：图片/iframe 无尺寸、字体切换（FOUT/FOIT）、动态插入内容回流；需预留宽高或用 size-adjust 对齐字体度量。
  4. window.onerror 与 addEventListener('error') 的区别？ 答：前者捕 JS 运行时错误且能拿 error 对象；后者在捕获阶段能拿资源加载错误（img/script/link）的 target，两者需配合且避免重复上报。
  5. 为什么 fetch 和 XHR 都要包装？ 答：第三方 SDK 与部分库走 XHR，只包 fetch 会漏数据；XHR 需在 open 记元信息、send 挂 loadend 才能拿耗时与状态。
  6. sendBeacon 相比 fetch 上报的优势与限制？ 答：由浏览器接管、页面关闭也能发出且不阻塞卸载；限制是 64KB 体积上限、返回 false 时需降级为 keepalive fetch。
  7. 为什么上报要采样+合并+重试？ 答：采样防数据爆炸（错误 100%、性能 10%）；合并减少请求数与头部开销；重试用指数退避保证弱网不丢，队列设上限防雪崩。
  8. Source Map 还原的完整链路？ 答：构建 sourcemap:'hidden' 生成 map 但不上 CDN；map 上传私有存储并绑定 release；服务端用 source-map 的 originalPositionFor 按行列号还原，并用 release 对齐版本。
  9. preload/prefetch/preconnect/modulepreload 怎么选？ 答：当前页关键资源用 preload/modulepreload（高优先级），下一页用 prefetch（空闲），跨域接口提前握手用 preconnect，只解析 DNS 用 dns-prefetch。
  10. 首屏白屏怎么系统性治理？ 答：关键 CSS 内联 + 骨架屏 + 预渲染/SSR，控制首屏 JS 预算（gzip 约 200KB），图片给尺寸与 priority，关键路径不懒加载，并用 bundle 分析持续验证。
