组件库建设与发布 ​

组件库是「双栈同构 + 对外交付」这条主线的核心资产，命中 7 份 JD 的「组件库/SDK/公共能力建设」要求。本文按「设计目标 → 契约架构 → API/样式/打包 → 类型与文档 → 体积与发布 → 踩坑」组织。构建细节见 构建工具：Vite / Webpack，仓库与发版见 pnpm workspace 与 Monorepo、CI/CD 与自动化发布。

一、设计目标与边界 ​

目标（用一句话说清组件库的价值）：

  1. 一致性：视觉与交互统一，避免「同一个按钮十种实现」。
  2. 复用与提效：常用能力开箱即用，业务只写差异。
  3. 可维护：API 稳定、有类型、有文档、可测试、可回归。
  4. 双栈同构：React 与 Vue 两套适配层共享同一份「契约与样式」，而非各写一遍。

边界（明确「不做什么」比「做什么」更重要）：

  • 只做通用原子/分子组件与主题能力，不承接强业务耦合组件（如「某业务的订单表格」）。
  • 不绑定特定数据层/请求库；不内置路由与全局状态。
  • 通过 peerDependencies 声明宿主框架（react/vue），自身不打包框架。

二、ComponentSpec 契约驱动架构 ​

核心思想：组件的属性、事件、插槽、默认值、样式钩子先定义成一份与框架无关的「契约（ComponentSpec）」，再由此生成双端适配、类型、文档与测试。这样「契约」是唯一真源（single source of truth）。

ts
// specs/button.ts —— 框架无关的契约
export interface ComponentSpec {
  name: string;
  props: {
    variant?: { type: 'enum'; values: ['primary', 'secondary', 'ghost']; default: 'primary' };
    size?: { type: 'enum'; values: ['sm', 'md', 'lg']; default: 'md' };
    disabled?: { type: 'boolean'; default: false };
    value?: { type: 'string' };                  // 受控
    onValueChange?: { type: 'event'; payload: 'string' }; // 受控回调
  };
  slots: Array<'icon' | 'default'>;
  expose: Array<'focus' | 'blur'>;               // 命令式 API
  tokens: ['--btn-bg', '--btn-fg', '--btn-radius']; // 可覆盖的 CSS 变量
}

export const buttonSpec: ComponentSpec = { /* ... */ };

从 Spec 派生的产物：

派生ReactVue
组件签名interface ButtonPropsdefineProps<...>()
事件onValueChange@update:value / emit
默认值组件内 const { variant = 'primary' } = propswithDefaults
文档表格由 Spec 渲染 props 表同一 Spec，同一文档

收益：改一次默认值/新增枚举值，双端与文档同步更新，避免「React 改了 Vue 漏了」的漂移。

三、API 设计约定 ​

3.1 受控 value + onValueChange ​

统一「受控 / 非受控」双模式，命名一致：

tsx
// React：受控判断用 value !== undefined，非受控用 defaultValue
interface InputProps {
  value?: string;              // 受控
  defaultValue?: string;       // 非受控初值
  onValueChange?: (v: string) => void;
}
function Input({ value, defaultValue = '', onValueChange }: InputProps) {
  const isControlled = value !== undefined;
  const [inner, setInner] = React.useState(defaultValue);
  const current = isControlled ? value : inner;
  const emit = (v: string) => { if (!isControlled) setInner(v); onValueChange?.(v); };
  return <input value={current} onChange={(e) => emit(e.target.value)} />;
}
vue
<!-- Vue：用 v-model 双绑，内部 emit update:value -->
<script setup lang="ts">
const props = withDefaults(defineProps<{ value?: string; defaultValue?: string }>(), { defaultValue: '' });
const emit = defineEmits<{ 'update:value': [v: string] }>();
const inner = ref(props.value ?? props.defaultValue);
const current = computed(() => props.value ?? inner.value);
function emitChange(v: string) {
  if (props.value === undefined) inner.value = v;  // 非受控才改内部
  emit('update:value', v);
}
</script>

约定：受控/非受控二选一，不要同时生效；受控模式组件不改内部状态，只回调。

3.2 默认值单一来源 ​

默认值只写在一处（Spec 或组件参数默认值），文档表格与类型从同一处派生。散落的字面量默认值是双端漂移的根源。

3.3 命令式 ref API 统一暴露 ​

需要「调用而非渲染」的能力（聚焦、校验、滚动）用 ref：

tsx
// React：forwardRef + useImperativeHandle
const Dialog = React.forwardRef<DialogHandle, DialogProps>((props, ref) => {
  React.useImperativeHandle(ref, () => ({ open, close }), [open, close]);
  return /* ... */;
});
// 使用：<Dialog ref={dialogRef} />; dialogRef.current?.open()
ts
// Vue：defineExpose（无需 forwardRef）
defineExpose({ open, close });
// 使用：dialogRef.value?.open()

约定：命令式方法名统一（open/close/focus/blur/validate/reset/scrollTo），返回值语义一致（validate() 返回布尔而非 throw）。

3.4 className/style 透传 ​

tsx
// React：合并而非覆盖，允许业务追加类名与内联样式
<div className={cx('ui-btn', `ui-btn--${variant}`, className)} style={style} />
vue
<!-- Vue：透传 attrs，注意 class/style 天然透传到根元素，可覆盖 inheritAttrs -->
<template><button class="ui-btn" :class="[`ui-btn--${variant}`, $attrs.class]"><slot /></button></template>

约定：业务传入的 className 追加在库类名之后（保证可被覆盖），style 与主题变量合并，data-*/aria-* 一律透传根元素。

3.5 插槽映射 ​

同一能力双端命名对齐，写进契约避免歧义：

契约插槽ReactVue
iconicon prop（ReactNode）<slot name="icon">
defaultchildren默认 <slot>
footerfooter prop<slot name="footer">

四、样式体系：BEM + CSS 变量三层主题 ​

4.1 BEM 命名 ​

block__element--modifier，与用户类名空间隔离（前缀 ui-）：.ui-btn、.ui-btn__icon、.ui-btn--primary。状态类用 is-*（.is-disabled）而非 modifier，便于 JS 切换。

4.2 CSS 变量三层主题 ​

第 1 层：全局预设（组件自带，:root 或组件根）
第 2 层：全局 token 覆盖（宿主 :root 改 --ui-color-primary）
第 3 层：组件级 style 透传（单实例临时覆盖）
css
/* 第 1 层：组件预设默认值，变量带兜底 */
.ui-btn {
  --btn-bg: var(--ui-color-primary, #1677ff);
  --btn-fg: #fff;
  --btn-radius: var(--ui-radius-base, 6px);
  background: var(--btn-bg);
  color: var(--btn-fg);
  border-radius: var(--btn-radius);
  transition: background-color .15s ease, color .15s ease; /* 双端一致 */
}
/* 第 2 层：宿主在 :root 覆盖，全站生效 */
:root { --ui-color-primary: #7c3aed; }
html
<!-- 第 3 层：单实例内联覆盖（优先级最高，仅此实例） -->
<button class="ui-btn" style="--btn-bg: #ea4c89">Pink</button>

优先级机制：内联 style 的 CSS 变量 > 宿主 :root 覆盖 > 组件预设默认。依赖 CSS 变量而非 !important，让覆盖可控且不破坏可维护性（Stylelint 的 no-descending-specificity 相关坑见 代码规范与静态检查）。

五、打包方案 ​

ts
// packages/ui/vite.config.ts（library mode）
export default defineConfig({
  build: {
    lib: { entry: 'src/index.ts', formats: ['es', 'cjs', 'umd'], name: 'YourUI',
           fileName: (f) => ({ es: 'index.mjs', cjs: 'index.cjs', umd: 'index.umd.js' }[f]) },
    cssCodeSplit: false,                 // 组件库常合并为单份 CSS，便于一次引入
    rollupOptions: {
      external: ['react', 'react-dom', 'react/jsx-runtime', 'vue'],  // 关键：框架 external
      output: { globals: { react: 'React', vue: 'Vue' } },
    },
  },
});
关注点做法
三种格式ESM（现代打包器）+ CJS（Node/旧工具）+ UMD（CDN <script>）
external必须排除 react/vue/react/jsx-runtime，避免宿主出现两份运行时
CSS 注入ESM/CJS 默认输出独立 CSS，由宿主引入；UMD 可用 vite-plugin-css-injected-by-js 注入
tree shakingESM + sideEffects: ["**/*.css"] + 具名导出
产物预览publint / arethetypeswrong 校验 exports 与类型是否自洽

六、类型声明与双端类型 re-export ​

ts
// dist/index.d.ts 由 vite-plugin-dts 生成
export type { ButtonProps } from './components/button';
export type { ComponentSpec } from './specs';
  • 双端类型 re-export：把框架无关的契约类型从主入口与两端子入口同时导出，宿主无论用 React 还是 Vue 都能拿到同一份契约类型。
  • exports 的 types 条件必须放最前，且要与 import/require 分支各配一份 .d.ts（.d.mts/.d.cts），否则 moduleResolution: node16 下拿不到类型。
  • 契约类型与运行时实现解耦：类型只描述「是什么」，不泄漏实现细节（不要 re-export 内部 hook 类型）。

七、文档站建设（VitePress） ​

7.1 结构化元数据驱动 ​

把 Spec 转成文档数据源，页面不手写 props 表，而是读元数据渲染，保证文档与代码同源：

ts
// docs/.vitepress/data/button.ts
import { buttonSpec } from '@your-org/ui/specs';
export const props = Object.entries(buttonSpec.props).map(([name, def]) => ({
  name, type: def.type, default: String(def.default ?? '-'),
}));

7.2 双端 demo 切换 ​

一个 demo 同时提供 React/Vue 实现，页面用 tab 切换：

vue
<Tabs :items="['React', 'Vue']">
  <template #React><CodeBlock lang="tsx" :code="reactCode" /></template>
  <template #Vue><CodeBlock lang="vue" :code="vueCode" /></template>
</Tabs>

7.3 双语、三态主题、锚点 ​

  • 双语：名词键 + zh/en 两套文案，组件 API 描述也从 Spec 的 i18n 字段取。
  • 三态主题：light / dark / auto（跟随系统），用 data-theme 属性切换 CSS 变量，与组件库的 token 层复用同一套变量。
  • CodeBlock 复制的国际化：复制按钮文案按当前语言显示（「复制」/「Copy」），成功提示也本地化。
  • 锚点 scroll-margin-top：标题被固定顶栏遮挡的经典问题——给 h2/h3 设 scroll-margin-top: calc(var(--vp-nav-height) + 16px)，点击锚点跳转时标题不会被挡住。
css
/* 锚点跳转不被固定导航遮挡 */
.vp-doc :is(h2, h3, h4) { scroll-margin-top: calc(var(--vp-nav-height) + 16px); }

八、体积预算与 check-bundle-size ​

给每个组件的产物设体积上限，超了 CI 直接失败，防止体积悄悄膨胀：

json
// .size-limit.json
[
  { "path": "packages/ui/dist/index.mjs", "limit": "60 kB", "gzip": true },
  { "path": "packages/ui/dist/index.mjs", "import": "{ Button }", "limit": "3 kB" }
]
yaml
# CI 中
- run: pnpm dlx size-limit --json > size.json
- run: pnpm exec check-bundle-size size.json   # 自定义脚本对比基线，超预算 exit 1

要点：gzip（或 brotli）体积才算有效指标；按单组件按需引入设更小预算；与上一版基线对比（增长超过 X kB 才报警），避免只看绝对值。

九、发布流程（指纹管理 + Changesets + 联动） ​

  • 指纹管理：产物文件名带 内容指纹（index.a1b2c3.mjs）或 exports 稳定路径二者取一。CDN 缓存场景用指纹文件名；库入口用稳定文件名 + 版本号控制缓存（@version）。变更同一基线要同时更新 package.json、CDN 与文档站。
  • Changesets：每个 PR 写 changeset，合并 version PR 时自动升版本、改 CHANGELOG、发 npm（详见 pnpm workspace 与 Monorepo、CI/CD 与自动化发布）。
  • 联动发布：主包 ui 与 icons、tokens 用 changeset 的 linked 同步版本；tokens 变了要触发 ui minor 并更新文档站主题变量。

十、组件库踩坑合集 ​

  1. Vue 响应式解构：const { value } = props 会丢失响应性（拿的是当次快照）。必须 const value = toRef(props, 'value') 或全程 props.value。
  2. React 引用更新竞态：受控组件里缓存旧 props 闭包会导致「回调里读到旧值」。受控回调应每次渲染读最新 props（或把回调放进 useRef 更新），避免 useCallback([]) 造成的 stale closure。
  3. 样式覆盖顺序：产物 CSS 与宿主 CSS 的加载顺序不确定，靠 CSS 变量与更高优先级选择器，而非 !important 硬顶。
  4. 契约测试：为同一个 Spec 写一组跨端共享的契约用例（行为断言：受控/非受控、默认值、事件 payload、插槽渲染），跑在 React 与 Vue 两套实现上，保证「两端行为一致」。
  5. SSR 不安全：组件里直接用 window/document 会在 SSR 崩溃，需 typeof window !== 'undefined' 守卫或 onMounted/useEffect 内使用。
  6. 多余实例：忘了 external 掉 react/vue 或 react/jsx-runtime，宿主出现两份运行时，hooks 报 Invalid hook call。
  7. 样式丢失：只引入 JS 未引入 CSS（或 sideEffects 误把 CSS 摇掉），组件「无样式渲染」。
  8. 类型入口错位：exports 的 types 顺序不对或未分 .d.mts/.d.cts，下游 TS 报「找不到类型声明」。

面试要点 ​

  1. 为什么用 ComponentSpec 契约驱动？ 契约是唯一真源，双端适配、类型、文档、测试都从它派生，杜绝「改一端漏一端」的漂移。
  2. 受控与非受控如何统一？ 用 value !== undefined 判定受控，受控只回调不改内部状态；Vue 用 update:value + computed 实现同样语义。
  3. 命令式 ref API 两端怎么对齐？ React forwardRef + useImperativeHandle，Vue defineExpose，方法名与返回语义统一。
  4. CSS 变量三层主题的优先级？ 组件级内联 style > 宿主全局 token 覆盖 > 组件预设默认，靠变量而非 !important 实现可控覆盖。
  5. library mode 打包最容易犯的错？ 忘记 external react/vue（含 react/jsx-runtime），导致宿主加载两份运行时。
  6. 双端类型 re-export 解决什么？ 让 React 与 Vue 宿主共享同一份契约类型，且 exports 的 types 条件要放最前并分 mts/cts。
  7. 文档站如何避免文档与代码不同步？ 用结构化元数据（Spec）驱动 props 表渲染，代码即文档。
  8. 体积预算是怎么做的？ 用 size-limit 按 gzip/brotli 设单组件预算，CI 中对比基线，超阈值失败。
  9. Vue 响应式解构的坑是什么？ const { x } = props 丢失响应性，应改用 toRef 或直接访问 props.x。
  10. 契约测试的价值？ 用同一组行为断言跑两端实现，保证 React/Vue 行为一致，是可回归的一致性保障。
