AntV 生态（G2/G6/X6） ​

AntV 命中 3 份 JD 的可视化要求，其中 **X6/G6 的「流程编排 / 资源拓扑」**是 #2 四方精创（算力调度）、#9 今天国际（AI 协作 + 架构）、#4 中科创达（IoT OS）中差异化最强的加分项，也是简历里可视化部分相对空白的一环。本页按「体系概览 → 选型 → G2 图形语法 → G6 关系图 → X6 图编辑 → 编排界面 → 性能 → 坑」组织。ECharts 的细节见ECharts 图表开发，地图与三维见地图与三维数字孪生。

一、AntV 体系概览 ​

AntV 是蚂蚁集团的可视化技术栈总称，按「使用场景」分层，不要把它们当成竞品：

库定位典型场景
G2统计图表（图形语法）折线/柱状/饼/散点等业务图表
G2Plot基于 G2 的开箱即用图表库（已并入 G2 v5 的 plot 模式）快速出图
G6图可视化（关系/拓扑）资源拓扑、知识图谱、流向图
X6图编辑引擎（可交互编辑）工作流画布、DAG、低代码编排
S2多维透视表格明细表 / 透视表 / 交叉表
L7地理空间可视化大规模地理数据渲染
F2移动端图表H5 / 小程序轻量图表
AVA可视化分析智能自动推荐图表
Ant Design Charts / Graphin面向 React 的封装（G2 / G6）在 React 业务里更快接入

一句话记忆：G2 画「统计图」，G6 画「关系图」，X6 编「流程图」，S2 画「表格」，L7 画「地图」。

二、G2 图形语法（Grammar of Graphics）与选型 ​

2.1 图形语法的构成 ​

G2 v5 的核心是语法化 API：把可视化表达拆成「数据 → 视觉通道 → 几何标记 → 尺度 → 坐标系 → 统计变换 → 分面」：

ts
import { Chart } from '@antv/g2';

const chart = new Chart({ container: 'container', autoFit: true, theme: 'classicDark' });

chart
  .data(rows)                                  // 数据
  .encode('x', 'time')                         // 视觉通道 x
  .encode('y', 'value')
  .encode('color', 'line')                     // 分组颜色
  .scale('y', { nice: true, zero: true })      // 尺度（值域映射）
  .transform({ type: 'stackY' })               // 统计变换
  .coordinate({ type: 'cartesian' })           // 坐标系（也可 polar/theta）
  .interval()                                  // 几何标记：柱
  .style({ radiusTopLeft: 4 })
  .axis('x', { title: '时间' })
  .legend('color', { position: 'top' })
  .tooltip({ items: [{ channel: 'y' }] });

chart.render();

关键概念：

  • 几何标记（mark）：interval（柱/条）、line、area、point、cell（网格色块/热力）、rect、text、path、image、polygon、schema（K 线）。
  • 视觉通道（encode）：x、y、color、size、shape、opacity、series、key；encode 决定「数据列 → 视觉属性」的映射。
  • 坐标系（coordinate）：cartesian、polar、theta（饼/玫瑰）、radial、helix（螺旋）。
  • 分面（facet）：facetRect / facetCircle 一行代码做小倍数（small multiples）。
  • 组合标记（composite mark）：view/spaceLayer 把多个 mark 叠加到一张图。

2.2 G2 与 ECharts 的选型对比 ​

维度G2（图形语法）ECharts（配置式）
心智模型声明式语法链，组合性强一个大 option 对象
出图速度简单图稍慢，复杂定制更强开箱即用快，内置图表多
交互/联动通过 view、interaction 手动搭内置 toolbox/dataZoom/brush 丰富
生态与 AntV 图/表格一脉相承独立，文档与社区极大
体积可 tree-shaking 按需同样支持 echarts/core 按需
大屏暗色主题有 classicDark 等主题需自定义主题

选型结论：业务中后台的常规图表（指标卡、趋势、占比）优先 ECharts（出图快、生态全）；需要高度定制、与 G6/X6 联动、或团队已有 AntV 技术栈时用 G2。两者不互斥，但同一项目尽量统一，避免引入两套渲染引擎徒增包体。

三、G6 关系图 / 拓扑 ​

G6 面向「节点 + 边」的关系数据，内置大量布局算法与交互行为：

ts
import { Graph } from '@antv/g6';

const graph = new Graph({
  container: 'mount',
  width: 900, height: 600,
  autoFit: 'view',
  data: {
    nodes: [
      { id: 'n1', data: { label: '主控' }, style: { fill: '#2f8cff' } },
      { id: 'n2', data: { label: '采集器' } },
    ],
    edges: [{ source: 'n1', target: 'n2', data: { label: '上报' } }],
  },
  node: { type: 'circle', style: { labelText: (d) => d.data.label } },
  edge: { type: 'line', style: { endArrow: true, labelText: (d) => d.data.label } },
  layout: { type: 'dagre', rankdir: 'LR', nodesep: 40, ranksep: 80 }, // 层级布局
  behaviors: ['drag-canvas', 'zoom-canvas', 'drag-element', 'click-select', 'hover-activate'],
  plugins: [{ type: 'grid-line' }],
});
graph.render();

常用布局与适用场景：

布局适用
force / d3-force无明确层级的关系网、知识图谱
dagre有向无环的流程/依赖（拓扑、任务流）
circular / concentric环形/同心圈，强调分组
grid / radial整齐排布、雷达辐射
combo-force / antv-dagre带分组（combo）的复合图

节点/边交互要点：

  • **behaviors（交互行为）**是插件化列表：drag-element（拖动节点）、zoom-canvas、drag-canvas、click-select、brush-select（框选）、hover-activate（悬停高亮关联）、collapse-expand（树/组合折叠）。
  • 状态（state）驱动样式：给节点/边设 selected、active、highlight 等状态，behaviors 触发状态切换，样式按状态渲染，比手动改 attribute 更声明式。
  • 事件：graph.on('node:click', (e) => ...)、canvas:click、edge:click；graph.on('afterrender') 可做首屏加载结束回调。

G6 v5 的渲染层基于 @antv/g，可切换 Canvas / SVG / WebGL 渲染器（WebGL 用于超大规模图）。

四、X6 图编辑引擎 ​

X6 面向「可编辑的图」——节点、连线、连接桩，是工作流 / DAG / 低代码编排画布的首选。

ts
import { Graph } from '@antv/x6';

const graph = new Graph({
  container: document.getElementById('graph')!,
  grid: { size: 10, visible: true, type: 'dot' },
  panning: { enabled: true },
  mousewheel: { enabled: true, modifiers: ['ctrl', 'meta'] },
  connecting: {
    router: 'manhattan',        // 正交路由，连线自动绕行
    connector: { name: 'rounded' },
    anchor: 'center',
    allowBlank: false,          // 不允许连到空白（必须落在连接桩）
    allowLoop: false,           // 禁止自环
    snap: { radius: 20 },
    createEdge() {
      return this.createEdge({ attrs: { line: { stroke: '#5b8ff9', targetMarker: { name: 'block' } } } });
    },
    validateConnection({ sourceCell, targetCell }) {
      return sourceCell?.id !== targetCell?.id;  // 业务校验：禁止连到自己
    },
  },
});

// 连接桩（ports）：定义可选连接位置
graph.addNode({
  id: 'node-1', x: 80, y: 80, width: 120, height: 40,
  label: '数据清洗',
  ports: {
    groups: {
      in: { position: 'left', attrs: { circle: { r: 4, magnet: true, stroke: '#8f8f8f' } } },
      out: { position: 'right', attrs: { circle: { r: 4, magnet: true, stroke: '#8f8f8f' } } },
    },
    items: [{ group: 'in' }, { group: 'out' }],
  },
});
graph.addEdge({ source: { cell: 'node-1', port: 'node-1-out' }, target: 'node-2' });

X6 的关键能力（工作流画布的「基础设施」）：

能力API / 插件说明
拖拽创建Dnd 插件 + Stencil 模板面板从左侧物料面板拖到画布生成节点
撤销重做History 插件graph.undo() / graph.redo()，也可自定义
对齐辅助线Snapline 插件拖动时吸附并对齐
框选 / 变换Selection、Transform多选、缩放旋转
复制粘贴Clipboard、KeyboardCtrl+C/V
小地图MiniMap大画布导航
序列化graph.toJSON() / fromJSON()保存/加载画布，对接后端 DSL

自定义节点是核心：继承 Node 或用 Graph.registerNode 注册带端口、状态、渲染逻辑的节点类型，把「业务节点的外观与行为」沉淀为可复用物料。

五、React Flow 与 X6 / G6 的对比 ​

维度React FlowX6G6
技术栈React 专用（声明式组件）框架无关（命令式 API）框架无关
定位流程图 / 节点编辑器企业级图编辑引擎关系图可视化与分析
上手极简，几行 <ReactFlow>中等（画布编程模型）中等
布局算法需自接 dagre/elk内置不多，靠插件/自接布局算法最全

选型：React 技术栈 + 编辑需求且要快速交付 → React Flow；要企业级、框架无关、强自定义 → X6；偏分析展示（非编辑）、布局复杂 → G6。G6 v5 与 X6 同属 AntV、心智接近，团队统一 AntV 时二者可组合使用。

六、可视化编排与节点配置界面实现要点 ​

一个完整的「节点编排」编辑器通常是三栏布局：

tsx
// 左：物料面板（Dnd 拖拽源）  中：画布（X6）  右：属性面板（受控表单）
export function WorkflowEditor() {
  const graphRef = useRef<Graph>();
  const [selectedId, setSelectedId] = useState<string | null>(null);
  const [nodeData, setNodeData] = useState<Record<string, NodeConfig>>({});

  useEffect(() => {
    const graph = new Graph({ container: containerRef.current!, /* ... */ });
    graphRef.current = graph;

    // 选中节点 → 右侧属性面板
    graph.on('node:click', ({ node }) => {
      setSelectedId(node.id);
    });
    graph.on('blank:click', () => setSelectedId(null));

    // 节点数据变化 → 写回画布
    return () => graph.dispose();
  }, []);

  // 属性面板改值 → 同步到画布与全局状态
  const updateNode = (id: string, patch: Partial<NodeConfig>) => {
    setNodeData((prev) => ({ ...prev, [id]: { ...prev[id], ...patch } }));
    graphRef.current?.getCellById(id)?.setData(patch); // 触发重绘
  };

  return (
    <div className="grid grid-cols-[220px_1fr_320px] h-screen">
      <Palette onDragEnd={(type) => addNodeToCanvas(type)} />
      <div ref={containerRef} />
      {selectedId && <NodeConfigPanel value={nodeData[selectedId]} onChange={(p) => updateNode(selectedId, p)} />}
    </div>
  );
}

要点：

  • 唯一真源（single source of truth）：画布状态与业务状态要能双向同步。推荐业务状态（节点配置）为主，画布只作呈现；或用 graph.toJSON() 序列化为业务 DSL，避免「画布是唯一状态」导致难测试、难撤销。
  • 序列化格式要对齐后端：nodes[].id/type/position/config + edges[].source/target/ports，形成可持久化、可版本化的流程图 JSON。
  • 撤销/重做用 X6 History 或自建命令栈，注意属性面板的修改也要进历史栈（否则 undo 只撤画布操作，业务态不同步）。
  • 连线校验（DAG 校验）：工作流通常要求无环，在 validateConnection / validateMagnet 中或提交前用拓扑排序检测环。
  • 物料（节点类型）注册表：把每种业务节点（数据源/清洗/训练/输出）抽成注册项（icon + 默认配置 + 端口定义 + 表单 schema），是「低代码编排」可扩展的关键。

七、大数据量图的性能 ​

手段说明
WebGL 渲染器G6 v5 基于 @antv/g 可切 WebGL，万级节点首选
关闭动画animate: false，布局动画在大图上是灾难
简化节点用图片/文字替代复杂矢量，减少图元数
布局分片force 布局迭代多时用 Web Worker 或 layout 的异步模式
层级渲染视口外/远处节点降级为点或图片（LOD）
边简化合并同源同目标边、隐藏次要边、边用直线替曲线
ts
// 大数据量图的稳妥配置
const graph = new Graph({
  container,
  renderer: 'webgl',            // 万级节点用 WebGL
  animate: false,
  layout: { type: 'force', preventOverlap: true, nodeSize: 20 },
  node: { style: { size: 12, label: false } }, // 关闭标签，标签是最贵的
  behaviors: ['zoom-canvas', 'drag-canvas'],   // 去掉逐节点 drag，降低交互开销
});

八、常见坑清单 ​

  1. 把 X6/G6 当普通 DOM 组件用 → 它们是画布编程模型，需 dispose()，卸载不清会造成内存与事件泄漏。
  2. 画布作为唯一状态源 → 难撤销、难测试、难与后端对齐；应以业务状态为主，画布同步呈现。
  3. allowBlank: true 导致连到空气 → 工作流应 allowBlank: false + validateConnection 校验。
  4. 属性面板修改不进历史栈 → undo 后画布与业务态不一致。
  5. G6 布局在大图上同步跑 → force 万级节点卡死；应关闭动画、Web Worker/异步布局。
  6. 同一项目同时上 ECharts + G2 + G6 + X6 → 包体与维护成本翻倍；按需只选必要的库并 tree-shaking 按需引入。
  7. 忽略 X6 连接桩坐标 → 自定义节点尺寸/布局变化后端口位置错乱，需在节点重绘时重算 ports。
  8. 从 @antv/g6 4.x 迁 5.x → 5.x 是重写版，API（数据格式、behaviors、theme、渲染器）大改，需按迁移指南重写。

九、与目标 JD 的对应点 ​

  • #2 四方精创（算力调度 + 数据标注 + 中后台）：算力/任务调度常用 DAG 编排画布，X6 + dagre 校验是无环流程的标准解法。
  • #9 今天国际（AI 协作 + 组件库 + 架构）：把「节点物料 + 属性面板 + 序列化」封装成可复用编排组件，直接命中「公共能力建设」。
  • #4 中科创达（IoT 操作系统）：设备/资源拓扑用 G6（force/dagre + 状态高亮）展示节点在线状态与链路。
  • #1 星河视控（监控/IoT）：摄像头/终端关系拓扑、告警链路高亮用 G6 的 hover-activate / state 实现。

面试要点 ​

  1. AntV 里 G2、G6、X6、S2 各是什么？ 答：G2 是图形语法的统计图表库（画折线柱状），G6 是关系/拓扑图可视化（节点+边+布局），X6 是图编辑引擎（可编辑的工作流画布），S2 是多维透视表格。
  2. 图形语法（Grammar of Graphics）的核心是什么？ 答：把可视化拆成「数据 → 视觉通道 encode → 几何标记 mark → 尺度 scale → 坐标系 coordinate → 统计变换 transform → 分面」，G2 v5 用声明式语法链表达，组合性远强于单个大 option。
  3. G2 和 ECharts 怎么选？ 答：常规业务图表优先 ECharts（开箱即用、内置交互多）；需高度定制、与 G6/S2 联动或团队已有 AntV 栈用 G2；同一项目尽量统一，避免引入两套引擎。
  4. G6 有哪些常用布局？分别用在什么场景？ 答：force/d3-force 用于无层级关系网，dagre 用于有向无环的流程/依赖，circular/concentric 用于强调分组，grid/radial 用于整齐/辐射排布。
  5. X6 的连接桩（ports）是什么？为什么重要？ 答：ports 定义节点上可连线的锚点位置（left/right/top/bottom），配合 allowBlank:false 与 validateConnection 保证连线只能落在合法锚点，是工作流合法性的基础。
  6. 工作流编辑器怎么设计状态管理？ 答：业务配置（节点数据/连线）为唯一真源，画布只作呈现并双向同步；用 toJSON/fromJSON 对齐后端 DSL，属性面板修改也要进入 History 撤销栈。
  7. React Flow 和 X6 怎么选？ 答：React 技术栈 + 快速交付的流程图用 React Flow（声明式、极简）；要企业级、框架无关、强自定义的复杂工作流用 X6；偏分析展示、布局复杂用 G6。
  8. 如何保证工作流图无环？ 答：连线时用 validateConnection/validateMagnet 实时阻止成环，或在提交前对图做拓扑排序/DFS 环检测。
  9. 大规模关系图（万级节点）怎么优化？ 答：切 WebGL 渲染器、关闭动画与标签、节点用图片/点降级（LOD）、布局异步或放 Web Worker、合并/隐藏次要边。
  10. 为什么画布必须 dispose？ 答：X6/G6 是长生命周期的画布对象，持有 canvas、事件监听与内部模型；切换/卸载不 dispose() 会内存泄漏并残留事件回调。
