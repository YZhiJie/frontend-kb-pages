ECharts 图表开发 ​

ECharts 命中 5 份 JD 的「数据可视化」要求，且在 #7 润信智能（智慧能源大屏）、#1 星河视控（监控/IoT）、#2 四方精创（算力调度看板）中直接对应业务。读者用过 echarts5 做大屏与 IoT 实时图表，本页把「option 驱动模型 → 生命周期 → 大数据量与实时刷新 → 体积与响应式」讲透。大屏级适配与调度另见大屏与大数据可视化性能，三维与地图另见地图与三维数字孪生，实时通信链路见实时通信：WebSocket / SSE。

一、ECharts 架构与实例生命周期 ​

ECharts 是基于配置（option）驱动的声明式图表库，底层用 zrender 做 Canvas/SVG 渲染。运行时结构：

  • ComponentModel（组件模型）：axis、legend、tooltip、dataZoom、visualMap、toolbox、grid 等，各自解析 option 中的配置。
  • SeriesModel（系列模型）：line/bar/pie 等，负责数据 → 视觉编码（visual encoding）。
  • ComponentView / ChartView：把模型转换为 zrender 图元（graphic element）。
  • zrender：统一渲染层，管理 canvas 上下文、事件（DOM + 图元命中）、脏矩形。

一个图表的完整生命周期：

ts
import * as echarts from 'echarts';

// 1. init：绑定 DOM，指定主题与渲染器；同一 DOM 重复 init 会打印警告并复用
const chart = echarts.init(document.getElementById('chart')!, 'dark', {
  renderer: 'canvas',        // 'canvas' | 'svg'
  useDirtyRect: true,        // 脏矩形渲染，多图表场景降开销
  devicePixelRatio: Math.min(window.devicePixelRatio, 2), // 4K 屏防显存爆炸
});
// 2. setOption：解析并合并配置，触发一次渲染
chart.setOption(option);
// 3. 交互：dispatchAction 主动触发，或 on 监听用户交互
chart.dispatchAction({ type: 'highlight', seriesIndex: 0, dataIndex: 3 });
chart.on('click', (p) => console.log(p.seriesName, p.name, p.value));
// 4. resize：容器尺寸变化必须手动调用（除非 autoResize）
chart.resize({ width: 800, height: 400 });
// 5. dispose：销毁实例，释放 canvas/事件/定时器
chart.dispose();

实例管理要点：

  • echarts.getInstanceByDom(el) 拿到已有实例，避免重复 init（重复 init 返回同一实例但会告警）；echarts.getInstanceById(id) 按 init 时传入的 opts 无用，需配合 chart.id。
  • clear() 不等于 dispose()：clear() 只清内容，实例与事件监听、DOM 引用仍在，长期切换会内存泄漏；图表容器被销毁时必须 dispose()，组件卸载（React useEffect 清理 / Vue onBeforeUnmount）也要一并 dispose() 并 ResizeObserver.disconnect()。

二、option 驱动与 setOption 的 merge 语义 ​

setOption(option, notMerge?, lazyUpdate?)，实际签名是 setOption(option, opts?: SetOptionOpts)：

参数类型作用
notMergeboolean（默认 false）true 时不合并旧配置，完全替换（危险，会丢弃未声明的组件）
replaceMergestring[]白名单式替换，如 ['series']，只替换这些组件，其余合并
lazyUpdatebooleantrue 时不同步渲染，等下次 rAF 一起刷（批量 setOption 提速）
silentboolean不触发事件

合并规则（这是最容易被问的细节）：

  1. 组件用 id 或 name 对齐：xAxis.id='a' 的组件在后续 setOption 中按 id 复用；未声明 id 则按顺序 + 类型匹配。
  2. series 是数组，默认按数组下标与 id 匹配。切换图表类型（如折线→柱状）时，旧 series 不会自动消失，必须 replaceMerge: ['series']。
  3. 数据整体替换只在传了新 data 时发生；不传 data 则沿用旧数据。深层配置按需合并：只传 series[0].itemStyle.color 不影响同 series 其他项，但传 series[0] 整体对象会与旧对象递归合并。
ts
// 正确：切换多组数据但保留图表类型，只替换 series（不会残留旧 series）
chart.setOption({ series: buildSeries(nextGroups) }, { replaceMerge: ['series'] });
// 正确：批量多次 setOption 用 lazyUpdate 合并到一帧
for (const part of parts) chart.setOption(part, { lazyUpdate: true });
chart.setOption({ }, { lazyUpdate: true }); // 最后一次触发 flush（或依赖 rAF）
// 错误：切换类型时直接覆盖却期望旧类型消失
// chart.setOption({ series: [{ type: 'bar', data }] }); // 旧 line series 仍在（同 index 被合并）

四、dataset 与 dataZoom / brush 交互 ​

4.1 dataset：数据与配置分离 ​

ts
const option: echarts.EChartsOption = {
  dataset: {
    source: [
      ['时间', '进线', '出线', '温度'],
      ['00:00', 120, 98, 26.5],
      ['01:00', 132, 110, 26.8],
    ],
    // 列定义维度名与类型，便于 encode / 转换
    dimensions: [{ name: '时间', type: 'ordinal' }, '进线', '出线', '温度'],
  },
  xAxis: { type: 'category' },
  yAxis: {},
  series: [
    { type: 'line', encode: { x: '时间', y: ['进线', '出线'], tooltip: ['进线', '出线'] } },
  ],
};
  • dataset.source 支持二维数组或对象数组；dataset.transform 内置 filter / sort 转换。
  • encode 把维度语义（x/y/tooltip/itemName）映射到列，避免手写 data: [[...]]。
  • 多个图表共用同一 dataset 时用 datasetIndex 复用，减少内存与解析开销。

4.2 dataZoom 与 brush ​

ts
const option: echarts.EChartsOption = {
  dataZoom: [
    { type: 'inside', xAxisIndex: 0, throttle: 100, zoomOnMouseWheel: true }, // 滚轮/拖拽缩放
    { type: 'slider', xAxisIndex: 0, start: 0, end: 30 },                       // 底部滑块
  ],
  toolbox: { feature: { brush: { type: ['rect', 'polygon', 'lineX'] } } },
  brush: {
    xAxisIndex: 0,
    brushType: 'lineX',
    brushMode: 'multiple',           // 多选区域
    transformable: true,
  },
};
chart.on('brushSelected', (params) => {
  // params.batch[].selected[].dataIndex 拿到被框选的原始索引
  const idx = params.batch[0]?.selected[0]?.dataIndex ?? [];
  setSelectedPoints(idx.map((i) => rawData[i]));
});
chart.on('datazoom', throttle(() => reloadVisibleWindow(chart), 150));
  • dataZoom 交互与后端分页结合：监听 datazoom 事件（务必节流），按 start/end 换算时间窗重新拉数据，实现「大数据量只加载视窗」。
  • brush 是框选交互：brushSelected 拿到的是 dataIndex（原始数据索引），不是坐标；多 dataZoom/多 grid 时索引映射要当心。
  • brush 与 dataZoom 叠加时，注意 brush 的坐标系绑定（xAxisIndex / geoIndex / gridIndex）。

五、按需引入与体积优化 ​

全量 import * as echarts from 'echarts' 打包约 1MB+（gzip 后 300KB+）。生产环境应走 echarts/core + 按需注册：

ts
// 按需引入：只注册用到的图表、组件、渲染器
import * as echarts from 'echarts/core';
import { LineChart, BarChart, PieChart, GaugeChart, HeatmapChart } from 'echarts/charts';
import { TitleComponent, TooltipComponent, GridComponent, LegendComponent,
  DataZoomComponent, VisualMapComponent, ToolboxComponent, MarkLineComponent } from 'echarts/components';
import { CanvasRenderer } from 'echarts/renderers';

echarts.use([
  LineChart, BarChart, PieChart, GaugeChart, HeatmapChart,
  TitleComponent, TooltipComponent, GridComponent, LegendComponent,
  DataZoomComponent, VisualMapComponent, ToolboxComponent, MarkLineComponent, CanvasRenderer,
]);

要点：

  • 用 echarts/core 后，类型也从 echarts/core 取（如 EChartsOption、ComposeOption）；想要精确类型可 ComposeOption<...>。
  • 地图 JSON 单独按需加载：echarts.registerMap('china', geoJson)；map 系列需额外注册 GeoComponent。大屏项目把 echarts 抽成与业务无关的 vendor chunk（见构建工具：Vite / Webpack），配合 splitChunks/manualChunks 缓存，体积可从全量 ≈1MB（raw）降到按需 ≈130KB gzip 级别。

六、响应式与 resize ​

ts
// 方式一：手动 resize（表格/面板联动、折叠面板展开时）
const ro = new ResizeObserver(throttle(() => chart.resize(), 150));
ro.observe(container);
// 方式二：autoResize（init 默认 true，靠容器尺寸变化自动 resize）；display:none 时尺寸为 0，需手动 resize
// 方式三：option 内置 media 响应式（类似 CSS 媒体查询）
const option: echarts.EChartsOption = {
  baseOption: { series: [{ type: 'bar', data }] },
  media: [
    { query: { maxWidth: 500 }, option: { legend: { show: false }, yAxis: { show: false } } },
    { query: { minWidth: 1000 }, option: { series: [{ type: 'bar', barWidth: 30 }] } },
  ],
};
  • 隐藏容器陷阱：display:none 时容器宽高为 0，图表以 0 尺寸渲染；tab 切换/弹窗打开后必须 chart.resize()。
  • 容器尺寸变化优先用 ResizeObserver（window.resize 会漏掉父容器变化，如侧边栏折叠），多个图表共用一次全局节流的 resize（见大屏性能）。

七、大数据量性能 ​

ts
const option: echarts.EChartsOption = {
  animation: false,                 // 大屏/实时一律关动画
  series: [{
    type: 'line',
    large: true,                    // 开启大数据量简化渲染路径
    largeThreshold: 2000,           // 超过 2000 点自动进入 large 模式
    sampling: 'lttb',               // 下采样保趋势（avg/max/min/lttb）
    showSymbol: false,              // 关闭点符号（最贵的绘制项）
    progressive: 2000,              // 分片渲染：每片 2000 点，拆到多帧
    progressiveThreshold: 3000,     // 超过 3000 点启用 progressive
    lineStyle: { width: 1 },
    data: hugeData,
  }],
};
手段作用何时开
large + largeThreshold走简化绘制路径，跳过逐点状态判断万级点
progressive + progressiveThreshold拆帧分片绘制，避免单帧长任务卡顿万级点
sampling: 'lttb'保极值的下采样，视觉近无损点数远超像素宽
showSymbol:false animation:false去掉最贵项所有大数据量
useDirtyRect: true脏矩形只重绘变化区多图表/局部刷新
canvas 渲染大数据量首选；svg 节点多则慢按数据量选
  • canvas vs svg：大数据量/实时 → canvas；节点少、需 CSS/无障碍交互 → svg。4K 大屏限制 devicePixelRatio ≤ 2 防显存爆炸；hoverLayerThreshold 阈值过高时 hover 图层（每元素一层 canvas）会拖慢低配机，可下调。
  • Web Worker 预聚合：可视宽仅约 1000px，1 万点与 1000 点视觉等价，先聚合/降采样再绘制永远比全量快（见大屏性能）。

八、动态数据与实时刷新：appendData vs setOption ​

ts
// A. appendData：仅尾部追加，开销最小，但有限制
chart.appendData({ seriesIndex: 0, data: [[ts, value]] });
// B. setOption 局部更新：滑动窗口替换（默认 merge，不整包 diff）
win.push([ts, value]);
if (win.length > MAX) win.shift();
if (++tick % 30 === 0) {
  chart.setOption({
    series: [{ data: win }],
    xAxis: { min: 'dataMin', max: 'dataMax' }, // 轴跟随数据，避免全量重算
  });
}

两者的差异与坑（高频追问点）：

维度appendDatasetOption
能力只追加到尾部任意更新（替换/局部/整包）
支持范围部分 series 明确支持（如 line 等），且维度与已有数据一致全类型
轴更新不自动更新坐标轴，需另 setOption 改 xAxis可一并声明
开销最小（不重建数据模型）传整包会逐项 diff，昂贵
删除/回退不支持支持
  • 最大坑：chart.setOption(option) 默认 merge（notMerge 默认 false），传整包会逐项 diff，万级点每次刷新都重建，必卡；应传局部 option 或 appendData。
  • appendData 后坐标轴不跟随 → 必须配合 xAxis.min/max = 'dataMin'/'dataMax' 或 setOption 更新时间范围，否则新点画到画布外。
  • 高频推送 → 攒批渲染：200ms 合并窗口或 rAF 对齐，按图表重要性分级刷新率（KPI 高频、趋势图低频），并做背压丢弃，防 buffer 无界增长（见大屏性能）。

十、常见坑清单 ​

  1. 整包 setOption 刷实时数据 → 万级点卡顿；改 appendData 或局部 option（默认 merge 会逐项 diff）。
  2. 切换图表类型不 replaceMerge: ['series'] → 旧 series 残留叠加。
  3. 只 clear() 不 dispose() → 内存/事件泄漏；组件卸载必须 dispose() + ResizeObserver.disconnect()。
  4. 隐藏容器（display:none）渲染为 0 尺寸 → tab/弹窗显示后必须 resize()。
  5. 全量引入 echarts → 包体 1MB+；用 echarts/core + use() 按需注册。
  6. appendData 后期望坐标轴自动延伸 → 轴不跟随，需手动更新 xAxis.min/max。
  7. 大数据量忘记 showSymbol:false / animation:false → 点符号与动画是最大开销。
  8. datazoom 事件未节流 → 拖拽时高频请求打爆后端。
  9. 4K 屏不限制 devicePixelRatio → canvas 显存爆炸、多次 dispose 后仍占内存。
  10. 地图 JSON 引 map 系列未注册 GeoComponent → 图表空白无报错（按需引入的隐蔽坑）。

十一、与目标 JD 的对应点 ​

  • #7 润信智能（智慧能源 + 数据大屏 + 数字孪生）：大数据量 series 配置、实时刷新 appendData/setOption、多重 grid 看板是硬考点；三维侧见地图与三维。
  • #1 星河视控（监控/IoT + 大屏 + SDK 交付）：WebSocket 高频推送 + 图表刷新，把「option 工厂 + 刷新调度」封装成可复用 SDK 组件是对口能力。
  • #2 四方精创（算力调度 + 数据标注看板）：dataset 复用、dataZoom/brush 联动、Web Worker 聚合是数据密集页面通用解法；#5 掌上智珠 / #9 今天国际 则关注把 <BaseChart>（统一主题、resize、dispose）封装进组件库，体现「公共能力建设」。

面试要点 ​

  1. ECharts 的 option 是命令式还是声明式？ 答：声明式——只描述「要什么」；setOption 内部解析成 ComponentModel/SeriesModel，再由 zrender 渲染，交互结果回写模型而非直接改 DOM。
  2. setOption 的 merge 语义是什么？ 答：默认 merge（notMerge:false），组件按 id/name 或「顺序+类型」对齐复用，series 按数组下标/id 匹配；传 replaceMerge:['series'] 可白名单替换，避免切换类型时旧 series 残留。
  3. clear() 与 dispose() 区别？ 答：clear() 只清内容，实例、事件、DOM 引用仍存在；dispose() 彻底销毁并释放资源。长时间切换图表必须 dispose，否则内存泄漏。
  4. appendData 与 setOption 怎么选？ 答：实时尾部追加优先 appendData（开销最小但不更新坐标轴、不支持删改）；需替换/删除用局部 setOption，避免整包 diff；appendData 后必须手动更新 xAxis.min/max。
  5. 10 万点折线怎么优化？ 答：large + largeThreshold:2000、showSymbol:false、animation:false、sampling:'lttb'、progressive 分片，配合 dataZoom 只加载视窗数据，必要时 Worker 预聚合。
  6. canvas 与 svg 渲染器怎么选？ 答：大数据量/实时刷新用 canvas（可开 useDirtyRect）；节点少、需 CSS/无障碍交互用 svg；高清屏限制 devicePixelRatio≤2 防显存爆炸。
  7. 图表包体怎么优化？ 答：用 echarts/core + use() 按需注册图表/组件/渲染器，地图 JSON 单独加载，配合 manualChunks 缓存 vendor。
  8. 容器隐藏后图表为什么变形？ 答：display:none 时容器尺寸为 0，图表按 0 尺寸渲染；显示后必须 chart.resize()，推荐用 ResizeObserver 而非 window.resize。
  9. 如何做响应式图表？ 答：三种方式——ResizeObserver 手动 resize、init 的 autoResize、option 的 media 配置（类似媒体查询切换系列/图例）。
  10. 多个实时图表怎么调度不卡？ 答：统一 30fps 调度器对齐 rAF、200ms 合并窗口攒批、按重要性分级刷新率、背压丢弃，多图表 resize 全局节流一次完成。
