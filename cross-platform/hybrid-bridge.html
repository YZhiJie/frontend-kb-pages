Hybrid 与 JSBridge ​

Hybrid + JSBridge 命中 4 份 JD（#8 鹏开信息 Hybrid + 音视频、#6 鹏业软件多端混合、#1 星河视控 SDK 交付、#5 掌上智珠移动端 H5），是「多端打包」这条主线的另一半。读者做过 React Native + H5 Hybrid 双端打包，本页把「Hybrid 架构 → JSBridge 双向通信 → 桥接设计 → 能力分层 → 登录态 → Deep Link → 联调与移动端坑」讲透。原生 App 侧见React Native 跨端，桌面容器见Electron 桌面端。

一、Hybrid 架构 ​

Hybrid = Native 容器 + WebView（H5）。它不是「二选一」，而是按能力分层：

┌─────────────────────────────────────────────┐
│  Native 容器（iOS WKWebView / Android WebView）│
│  ├─ 硬件与原生能力：相机 / 蓝牙 / 定位 / 支付 / 文件│
│  ├─ 系统能力：通知 / 唤起其它 App / 分享 / 权限   │
│  └─ WebView：加载 H5，暴露 JSBridge 给页面       │
│        └─ H5（业务内容）：页面 / 表单 / 图表 / 富文本│
└─────────────────────────────────────────────┘
层负责不负责
容器（Native）硬件、原生能力、系统级交互、性能敏感渲染具体业务页面
H5（WebView）业务内容、快速迭代、跨端复用直接调用系统 API

设计原则：「能力下沉到容器，内容上浮到 H5」。业务页面用 H5（发版快、可热更、跨端复用），凡涉及硬件/系统能力一律经桥接交给容器。这样同一套 H5 既能跑在 App 容器里，也能在浏览器独立运行（靠 mock 桥兜底）。移动端 H5 的适配细节见响应式与多端适配。

二、WebView 与 JSBridge：通信原理 ​

JS 与 Native 之间没有天然通道，需要桥。三大类实现：

2.1 JS → Native ​

方式原理平台
URL Scheme 拦截location.href = 'myapp://...'，原生 shouldInterceptRequest/decidePolicyFor 拦截通用（古老但兼容好）
注入式接口原生把对象注入全局：Android addJavascriptInterface(obj, 'name')、iOS WKScriptMessageHandler主流、可靠
prompt/console 拦截重写 prompt、console.log，原生拦截其内容iOS 旧方案、已不推荐

2.2 Native → JS ​

方式原理
同步执行 JSiOS evaluateJavaScript / Android evaluateJavascript
javascript: 伪协议loadUrl("javascript:fn(...)")（易被 CSP 拦截，慎用）

三、自定义 JSBridge 的双向协议 ​

裸用 location.href 或 evaluateJavascript 的问题：没有回调、没有错误、没有超时、无法并发。生产级桥需要设计一套「请求-响应」协议。

3.1 协议设计 ​

ts
interface BridgeRequest {
  method: string;          // 能力名，如 'getToken' | 'openCamera'
  params?: unknown;        // 参数（结构化克隆友好：JSON 可序列化）
  callbackId: string;      // 一次调用的唯一 id，用于回调匹配
}
interface BridgeResponse {
  callbackId: string;      // 回传对应请求 id
  code: number;            // 0 成功，非 0 为错误码
  data?: unknown;          // 成功数据
  msg?: string;            // 错误信息
}
interface BridgeEvent { event: string; data?: unknown; } // Native → JS 事件推送（无 callbackId，单向）

3.2 H5 侧实现（Promise 化 + 回调管理 + 超时） ​

ts
type BridgeMethod =
  | 'getToken' | 'getUserInfo' | 'openCamera' | 'scanQr'
  | 'getLocation' | 'pay' | 'setTitle' | 'closeWebView' | 'chooseFile';
class BridgeError extends Error { constructor(public code: number, msg?: string) { super(msg ?? `bridge error ${code}`); } }

class JSBridge {
  private callbacks = new Map<string, { resolve: (v: unknown) => void; reject: (e: unknown) => void; timer: number }>();
  private seq = 0;
  readonly isNative: boolean;
  constructor() {
    this.isNative = !!(window as any).myappNative || /myapp/i.test(navigator.userAgent);
    // 注入全局回调/事件函数：Native 执行 evaluateJavascript 时调用它们回传
    (window as any).__bridgeCallback = (json: string) => this.onResponse(JSON.parse(json) as BridgeResponse);
    (window as any).__bridgeEvent = (json: string) => this.emitEvent(JSON.parse(json) as BridgeEvent);
  }
  call<T = unknown>(method: BridgeMethod, params?: unknown, timeout = 10000): Promise<T> {
    if (!this.isNative) return this.mockProxy<T>(method, params);            // 浏览器兜底
    const callbackId = `cb_${Date.now()}_${++this.seq}`;
    return new Promise<T>((resolve, reject) => {
      const timer = window.setTimeout(() => {
        this.callbacks.delete(callbackId);
        reject(new BridgeError(-1, `bridge timeout: ${method}`));
      }, timeout);
      this.callbacks.set(callbackId, { resolve: resolve as (v: unknown) => void, reject, timer });
      this.invokeNative(JSON.stringify({ method, params, callbackId } satisfies BridgeRequest));
    });
  }
  private invokeNative(payload: string) {
    const api = (window as any).myappNative;
    if (api?.postMessage) return api.postMessage(payload);                    // 注入式（推荐）
    const iframe = document.createElement('iframe');                          // URL Scheme 兜底
    iframe.style.display = 'none';
    iframe.src = `myapp://bridge?payload=${encodeURIComponent(payload)}`;
    document.body.appendChild(iframe);
    setTimeout(() => iframe.remove(), 100);
  }
  private onResponse(resp: BridgeResponse) {
    const cb = this.callbacks.get(resp.callbackId);
    if (!cb) return;
    clearTimeout(cb.timer);
    this.callbacks.delete(resp.callbackId);
    resp.code === 0 ? cb.resolve(resp.data) : cb.reject(new BridgeError(resp.code, resp.msg));
  }
  // 事件订阅：容器推送（登录态变化、网络变化等）
  private listeners = new Map<string, Set<(d: unknown) => void>>();
  on(event: string, fn: (d: unknown) => void) {
    (this.listeners.get(event) ?? this.listeners.set(event, new Set()).get(event)!).add(fn);
    return () => this.listeners.get(event)?.delete(fn);
  }
  private emitEvent(e: BridgeEvent) { this.listeners.get(e.event)?.forEach((fn) => fn(e.data)); }
}
export const bridge = new JSBridge();

要点：

  • callbackId 是并发的关键：高并发调用（同时扫码 + 定位）靠它把原生响应匹配回正确的 Promise；超时与错误码：桥调用必须设超时，否则原生不回调时页面永久 pending（内存泄漏 + 逻辑卡死）。
  • isNative 探测 + mock：非容器环境用 mockProxy 兜底（见第五节），让 H5 可独立在浏览器调试。

3.3 Native 侧对接（伪代码） ​

swift
// iOS WKWebView
let controller = WKUserContentController()
controller.add(self, name: "myappNative")            // 注入消息处理器
let config = WKWebViewConfiguration()
config.userContentController = controller
// 接收 H5 请求
func userContentController(_ c: WKUserContentController, didReceive msg: WKScriptMessage) {
  guard let body = msg.body as? String,
        let req = try? JSONDecoder().decode(BridgeRequest.self, from: Data(body.utf8)),
        Self.allowed.contains(req.method) else { return }   // 白名单校验 + origin 校验
  handle(req.method, req.params) { data in
    let resp = BridgeResponse(callbackId: req.callbackId, code: 0, data: data)
    let json = String(data: try! JSONEncoder().encode(resp), encoding: .utf8)!
    self.webView.evaluateJavaScript("window.__bridgeCallback(\(json))")
  }
}

四、能力分层与桥能力设计 ​

桥暴露的不是「万能 exec」，而是分层白名单能力：

分层能力示例归属
系统交互setTitle、closeWebView、setRightButton、share容器
硬件openCamera、scanQr、getLocation、bluetooth、nfc容器
账号getToken、getUserInfo、login、logout容器
交易pay（唤起支付 SDK）、chooseFile、uploadFile容器
业务内容页面、表单、图表、富文本H5

设计要点：

  • 能力名稳定 + 版本协商：call('cardApi', ..., { version: 2 }) 或 getAppInfo() 拿容器版本，做新老端兼容（老版本 App 里 H5 要能降级）。
  • 参数规范化：桥参数必须 JSON 可序列化，二进制（图片）传 base64 或先上传后传 URL；安全上容器侧校验 调用来源 origin/URL 白名单 + 方法白名单，防止第三方页面（或 XSS）滥用原生能力，H5 侧校验容器消息来源，不信任任意 __bridgeCallback 调用者。

五、登录态同步与浏览器环境 mock ​

H5 在 App 容器里通常不自己维护登录，而是向容器取登录态：

ts
// 登录态同步：H5 启动时向容器要 token，并订阅变化
async function bootstrapAuth() {
  const { token, user } = await bridge.call<{ token: string; user: User }>('getUserInfo');
  setAuthHeader(token);                 // 注入到所有 API 请求头
  bridge.on('loginChanged', (u) => {
    if (!u) return bridge.call('closeWebView');
    refreshUser(u as User);
  });
}
ts
// mockProxy 示意（开发/浏览器环境）：非容器环境调用自动走这里返回假数据，H5 无需真容器即可跑通
private async mockProxy<T>(method: BridgeMethod, params?: unknown): Promise<T> {
  const mocks: Record<string, () => unknown> = {
    getToken: () => 'mock-token',                        // bridge.call('getToken') → 'mock-token'
    getUserInfo: () => ({ id: 'u1', name: 'Mock 用户' }),
    getLocation: () => ({ lng: 114.0579, lat: 22.5431 }),
    scanQr: () => 'https://example.com/scanned',
    openCamera: () => {/* 浏览器用 <input type="file" capture> 模拟 */},
  };
  if (import.meta.env.DEV) console.warn('[bridge-mock]', method, params);
  return (mocks[method]?.() ?? undefined) as T;
}

要点：

  • 桥兜底是 H5 可独立开发/测试的前提：没有 mock，前端每次改一行都要真机联调；登录态双通道：容器内由容器维护（getUserInfo + loginChanged 推送），浏览器下 H5 走自己登录流程，用 bridge.isNative 分流。cookie 与 token 的边界：若 WebView 与 H5 同域可能天然共享 Cookie，跨域场景则必须经桥取 token 再注入请求头，避免依赖 Cookie 同步。

六、Deep Link 与 Universal Link ​

Deep Link 用于「从 H5/短信/扫码/外部 App 跳回自己的 App」。

类型形式特点
Schememyapp://path?query=1简单通用；iOS 上若未安装无兜底、会弹确认
Universal Link（iOS）/ App Links（Android）https://app.example.com/path免确认、未安装可回退网页；需配置校验证书文件
ts
// 解析 Deep Link：scheme + host + path + query
function parseDeepLink(url: string) {
  const u = new URL(url);
  return {
    scheme: u.protocol.replace(':', ''),
    host: u.host,
    path: u.pathname.replace(/^\//, ''),
    query: Object.fromEntries(u.searchParams.entries()),
  };
}
// myapp://device/detail?id=123 → { path: 'device/detail', query: { id: '123' } }

关键点：

  • 回跳（return-to-app）：H5 内唤起微信/支付宝/其它 App 后，需显式回跳自己的容器 —— 收款类场景常靠 redirect_url 或 scheme 回跳，但 iOS 上 location.href = 'myapp://...' 可能受用户手势限制，需在用户点击的回调里同步调用。
  • 多入口冲突：同时配 Scheme 与 Universal Link 时，容器要统一由一个路由解析器分发，避免双触发；iOS Universal Link 配置需 Associated Domains + 服务器放置 apple-app-site-association（AASA），Android 用 assetlinks.json + intent-filter，配置错误会被当普通网页打开。

七、WebView 联调要点 ​

手段说明

真机远程调试（Android）Chrome chrome://inspect → 选设备上的 WebView 页面（需开 WebView.setWebContentsDebuggingEnabled(true)）

  • Android 远程调试要显式开：WebView.setWebContentsDebuggingEnabled(true)（release 包一般关，联调版开）。
  • iOS 调试需真机 + Safari（模拟器 WebView 行为与真机有差异），vConsole 只在内测环境引入，不要进生产包（体积与信息泄露）。

九、常见坑清单 ​

  1. 桥调用无回调/无超时，或并发调用响应串了 → 必须带 callbackId + 设超时，否则 Promise 永久 pending 或结果错位。
  2. iOS 与 Android 注入方式不统一 → H5 侧要做能力探测（myappNative.postMessage 存在性）+ URL Scheme 兜底。
  3. Android 忘记 @JavascriptInterface → JS 调原生方法静默失效。
  4. 容器不校验来源 → 任意页面可调原生能力，安全风险；容器侧做 origin + 方法白名单。
  5. H5 无法脱离容器开发 → 没有 mock 桥，改一行就要真机联调；必须提供浏览器 mock。
  6. 登录态依赖 Cookie 跨端同步 / AASA 配置错 → 前者改用桥取 token 注入请求头，后者会被当普通网页打开导致深链失效。
  7. 回跳受用户手势限制 / vConsole 进生产 → 前者在点击回调内同步触发 scheme，后者仅内测环境引入。
  8. 100vh/键盘布局错乱 / release 忘记关 WebView 调试 → 用 100dvh/visualViewport，调试开关只在联调包开启。

十、与目标 JD 的对应点 ​

  • #8 鹏开信息（IM + Electron + 音视频 + Hybrid）：JSBridge 双向通信 + 登录态同步 + Deep Link，是 Hybrid 岗位的核心考点。
  • #6 鹏业软件（PC/Android/iOS 多端混合）：能力分层 + 离线包热更 + 多端一致交付，对应「多端混合」要求。
  • #1 星河视控（监控/IoT + SDK 交付）：把桥能力（相机/扫码/定位）封装成可复用 SDK、带版本协商与 mock，直接命中「对外交付」；#5 掌上智珠（移动端 H5 优先）：移动端 H5 常见问题（100vh/键盘/滚动穿透/性能/缓存）是日常必答。

面试要点 ​

  1. Hybrid 架构里 Native 和 H5 的职责怎么划分？ 答：能力下沉、内容上浮——硬件/系统能力（相机、蓝牙、定位、支付）由 Native 容器承担，业务页面/表单/图表由 H5 承载；这样 H5 迭代快、可热更、可跨端复用。
  2. JS 调 Native 有哪几种方式？ 答：URL Scheme 拦截（location.href='myapp://...'）、注入式接口（Android addJavascriptInterface / iOS WKScriptMessageHandler）、以及早期的 prompt/console 拦截；现在主流是注入式 + Scheme 兜底。
  3. Native 怎么调 JS？ 答：iOS evaluateJavaScript、Android evaluateJavascript 同步执行；或 WebView/RN 的 postMessage 消息通道；javascript: 伪协议易被 CSP 拦，慎用。
  4. 生产级 JSBridge 协议要包含什么，为什么 callbackId 关键？ 答：method + params + callbackId 组成请求，响应带回对应 callbackId + code + data/msg；桥是异步的，并发调用（同时扫码+定位）必须有唯一 id 才能把原生响应匹配回正确请求，否则结果会串。
  5. H5 怎么在浏览器里脱离 App 调试？ 答：探测 isNative，非容器环境走 mock 桥（mockProxy）返回假数据（token/用户/定位），用 <input type=file capture> 模拟相机，让 H5 可独立开发。
  6. H5 里的登录态怎么和容器同步？ 答：H5 启动调用 getUserInfo/getToken 取容器登录态并注入请求头，同时订阅 loginChanged 事件处理登出；不要单纯依赖跨端 Cookie 同步。
  7. Deep Link 冷启动和热启动有什么区别？ 答：冷启动由 App 启动参数（didFinishLaunching/intent）拿 URL，热启动由 openURL/onNewIntent 拿；H5 要兼容「页面加载完才收到跳转」的情况并统一路由分发。
  8. Universal Link 比 Scheme 好在哪？配置要注意什么？ 答：免确认弹窗、未安装可回退网页；需在 Associated Domains 与服务器放置 AASA（iOS）/ assetlinks.json（Android），配置错会被当普通网页打开。
  9. 移动端 H5 有哪些典型坑？ 答：100vh 因地址栏/键盘不准（用 100dvh/visualViewport）、键盘遮挡输入、弹窗滚动穿透、字体字重跨端差异、首屏与长列表性能、缓存与离线包热更。
  10. Hybrid 如何既做到接近 Native 的首屏速度，又防住安全风险？ 答：首屏用离线包——产物预置容器本地、启动比对版本命中即 0 网络加载、未命中走远端并后台下载增量包；安全上容器侧校验调用来源（origin/URL 白名单）与方法白名单、不暴露万能 exec，H5 侧不信任任意消息来源。
