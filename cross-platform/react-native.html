React Native 跨端 ​

React Native 命中 3 份 JD（#10 欣农互联 AI 产品 + RN 跨端、#6 鹏业软件多端混合、#4 中科创达 IoT App），读者做过 iOS/Android 双端打包。本页按「架构 → 组件/样式 → 导航/表单/状态 → 硬件与原生化 → 性能 → 调试 → 双端打包 → 适配 → 坑」组织。原生容器侧的 H5 方案见Hybrid 与 JSBridge，双栈心智见双栈对比与同构组件库。

一、RN 架构：从 Bridge 到新架构 ​

1.1 旧架构（Bridge 时代） ​

RN 旧架构有三个线程 + 一条「桥（Bridge）」：

线程职责
JS 线程执行 JS 逻辑、React 组件、业务代码
Shadow 线程（后台）用 Yoga 计算 Flex 布局（Layout）
UI 线程（主线程）原生渲染、绘制、手势

通信方式：JS 与原生通过 Bridge 异步、批量、序列化（JSON） 传递消息。核心问题：

  • 异步不可同步：JS 调原生方法拿不到同步返回值；
  • 序列化开销：消息要 JSON 序列化，高频/大数据量时成为瓶颈；
  • 启动慢：JS 引擎（JSC）启动 + 模块全量加载，影响 TTI。

1.2 新架构（Fabric / TurboModules / JSI / Hermes） ​

组成作用
JSI（JavaScript Interface）让 C++ 对象直接暴露给 JS，能力同步调用，去掉 JSON 序列化桥
Fabric新渲染器，C++ 实现，支持同步布局与并发渲染（对齐 React 18 并发特性）
TurboModules原生模块按需懒加载、类型安全（Codegen）
Hermes默认 JS 引擎，支持 AOT 预编译字节码，启动/TTI 明显更快、内存更低
Bridgeless彻底去掉旧桥，新架构默认模式
ts
// TurboModule 原生模块（iOS/Android 各自实现，TS 定义契约）
// specs/NativeDevice.ts
import type { TurboModule } from 'react-native';
import { TurboModuleRegistry } from 'react-native';

export interface Spec extends TurboModule {
  getBatteryLevel(): Promise<number>;      // 原生能力契约
  startOta(url: string): void;
}
export default TurboModuleRegistry.getEnforcing<Spec>('NativeDevice');

要点：新架构的同步 JSI 调用让「读设备状态、布局查询」等不再需要异步等待，是 RN 性能提升的根本；面试能讲清「Bridge → JSI/Fabric/Hermes」的演进即可。

二、组件与样式 ​

RN 没有 CSS，用 JS 对象 + StyleSheet.create 描述样式，布局默认 Flex（且默认 flexDirection: 'column'，与 Web 的 row 不同）。

tsx
import { View, Text, StyleSheet, useWindowDimensions, PixelRatio } from 'react-native';

export function Card({ title, value }: { title: string; value: number }) {
  const { width } = useWindowDimensions();   // 响应式：屏幕旋转/尺寸变化
  return (
    <View style={[styles.card, { width: width - 32 }]}>
      <Text style={styles.title}>{title}</Text>
      <Text style={styles.value}>{value}</Text>
    </View>
  );
}

const styles = StyleSheet.create({
  card: {
    borderRadius: 12,                 // 数值是 density-independent 单位，非 CSS px
    padding: 16,
    backgroundColor: '#1b2b44',
    shadowColor: '#000',              // 阴影分平台
    shadowOffset: { width: 0, height: 2 }, shadowOpacity: 0.2, shadowRadius: 4, // iOS
    elevation: 4,                     // Android
  },
  title: { color: '#8aa0bd', fontSize: 13 },
  value: { color: '#fff', fontSize: 24, fontWeight: '600', fontFamily: 'PingFang SC' },
});

要点与坑：

  • 默认主轴是 column（flexDirection 默认 'column'），与 Web 相反；flex: 1 才是撑满。
  • 尺寸单位为密度无关单位，不是 CSS px；像素级换算用 PixelRatio.get()。
  • View 才能布局与样式，Text 是文本容器；文字必须包在 <Text> 里，不能裸文本。
  • 样式不继承（除 Text 嵌套部分继承字体），没有全局 CSS、没有 margin 折叠、没有 z-index（靠渲染顺序）。
  • 平台差异用 Platform.select：阴影（iOS shadow* / Android elevation）、组件（DatePickerIOS 等）。

tsx
// 表单：react-hook-form + zod（非受控，减少 re-render）
import { useForm, Controller } from 'react-hook-form';
import { zodResolver } from '@hookform/resolvers/zod';
import { z } from 'zod';

const schema = z.object({ deviceName: z.string().min(1).max(32), ssid: z.string().min(1) });
type FormData = z.infer<typeof schema>;

export function NetConfigForm({ onSubmit }: { onSubmit: (d: FormData) => void }) {
  const { control, handleSubmit, formState: { errors } } = useForm<FormData>({
    resolver: zodResolver(schema),
    defaultValues: { deviceName: '', ssid: '' },
  });
  return (
    <>
      <Controller control={control} name="ssid"
        render={({ field }) => <TextInput value={field.value} onChangeText={field.onChange} />} />
      {errors.ssid && <Text>{errors.ssid.message}</Text>}
      <Button title="提交" onPress={handleSubmit(onSubmit)} />
    </>
  );
}
ts
// 状态：zustand（选择器订阅，避免全量 re-render）
import { create } from 'zustand';
interface AppState { devices: Device[]; setDevices: (d: Device[]) => void; }
export const useAppStore = create<AppState>((set) => ({
  devices: [],
  setDevices: (devices) => set({ devices }),
}));
// 只订阅 devices，其它字段变化不触发本组件 re-render
const devices = useAppStore((s) => s.devices);

要点：表单用 react-hook-form（非受控 + 订阅式）而非手写受控 state，可显著减少表单重渲染；zod 做校验、类型推导一体；状态用 zustand 的细粒度选择器控制订阅范围。输入框要配 KeyboardAvoidingView 处理键盘遮挡。

四、硬件通信与原生能力 ​

RN 的跨端价值一半在「能调原生硬件」。典型场景：BLE 蓝牙、配网、OTA 升级。

ts
// BLE：react-native-ble-plx 扫描/连接/写特征值
import { BleManager } from 'react-native-ble-plx';
const manager = new BleManager();

function scanAndConnect(serviceUUID: string) {
  manager.startDeviceScan([serviceUUID], null, async (error, device) => {
    if (error || !device) return;
    manager.stopDeviceScan();
    const connected = await device.connect();
    await connected.discoverAllServicesAndCharacteristics();
  });
}
ts
// 配网 / OTA：通常封装原生模块（iOS 用 NetworkExtension/NEHotspotConfiguration，Android 用 WifiManager）
import NativeDevice from '../specs/NativeDevice';
async function startOta(firmwareUrl: string) {
  NativeDevice.startOta(firmwareUrl);   // 新架构 JSI 模块，契约见第一节
}

要点：

  • 权限：iOS 需在 Info.plist 声明 NSBluetoothAlwaysUsageDescription、NSCameraUsageDescription 等；Android 需 AndroidManifest.xml 声明 BLUETOOTH_SCAN/BLUETOOTH_CONNECT（Android 12+ 拆分权限）并运行时申请。
  • 配网属于强原生能力：RN 生态库覆盖有限，通常要自写原生模块（TurboModule / 旧 NativeModule），因此「会写原生模块」是跨端岗的关键分水岭。
  • 原生 UI 组件：需要在 RN 里嵌原生 View（如相机预览、地图 SDK）时，走 Fabric 的原生组件规范。
  • 前后台/连接生命周期：App 切后台长连接会被系统挂起，需处理重连与状态恢复。

五、性能优化 ​

手段说明
FlatList 虚拟化只渲染可视区，长列表绝不用 ScrollView + map
减少 re-renderReact.memo、useCallback、zustand 细选择器、稳定 key
InteractionManager把动画/交互之后的重活延后（runAfterInteractions）
原生动画驱动Animated / Reanimated 开 useNativeDriver: true
Hermes默认开启，AOT 字节码提速启动
图片react-native-fast-image（缓存/优先级）、按尺寸裁剪
长任务拆分到多帧，避免阻塞 JS 线程（10ms 内一帧原则）
tsx
// FlatList 关键配置（万级列表的标配）
<FlatList
  data={devices}
  keyExtractor={(item) => item.id}
  renderItem={({ item }) => <DeviceRow device={item} />}
  getItemLayout={(_, i) => ({ length: ROW_H, offset: ROW_H * i, index: i })} // 固定行高，跳过测量
  initialNumToRender={10}
  maxToRenderPerBatch={8}
  windowSize={5}                       // 可视区上下各保留的窗口倍数
  removeClippedSubviews={true}         // 移出屏幕的视图卸载（Android 收益更明显）
  onEndReached={loadMore}
  onEndReachedThreshold={0.5}
/>
  • getItemLayout 是长列表的加速关键：固定行高时它让列表跳过测量、支持精确 scrollToIndex。
  • 列表 item 用 React.memo + 稳定引用：renderItem 里内联箭头函数会导致每次父渲染都重建，加重子项 re-render。
  • useNativeDriver: true：把动画放到原生线程执行，不受 JS 线程卡顿影响；仅支持 transform/opacity 等有限属性。

七、iOS / Android 双端打包分发 ​

bash
cd ios && pod install && cd ..      # iOS：装 CocoaPods 依赖，随后 Xcode → Product > Archive → Distribute App（TestFlight 内测）
cd android
./gradlew assembleRelease           # Android：APK（signingConfigs 用 keystore 签名）
./gradlew bundleRelease             # Android：AAB（Google Play 要求，上传蒲公英/fir.im 生成二维码分发）

要点：

  • iOS 依赖 CocoaPods（pod install），原生依赖变更后需重新 install；Podfile 与 RN 版本强相关。
  • Android 签名：keystore + signingConfigs（storeFile/storePassword/keyAlias/keyPassword），密钥绝不能提交到仓库（用 CI 变量注入，见CI/CD 与自动化发布）。
  • iOS 上架需 Apple 开发者账号：证书/描述文件/App ID；内测走 TestFlight（构建数有限、需审核）；Android 内测可直接传蒲公英/fir.im。
  • 包体优化：开 Hermes、enableProguardInReleaseBuilds、按 ABI 拆分（splits.abi）、图片压缩。

八、App 适配 ​

tsx
import { SafeAreaProvider, useSafeAreaInsets } from 'react-native-safe-area-context';
import { StatusBar, Platform } from 'react-native';

export function Screen({ children }: { children: React.ReactNode }) {
  const insets = useSafeAreaInsets();         // 刘海/挖孔/底部 Home 指示条安全区
  return (
    <>
      <StatusBar barStyle="light-content" translucent backgroundColor="transparent" />
      <View style={{ flex: 1, paddingTop: insets.top, paddingBottom: insets.bottom }}>{children}</View>
    </>
  );
}
  • 安全区用 react-native-safe-area-context（比内置 SafeAreaView 更可靠，支持 Android）。
  • 字体：iOS 默认 San Francisco、Android Roboto；中文字体指定 PingFang SC（iOS）/Noto Sans CJK（Android），跨端字重可能不一致。
  • 机型差异：状态栏高度、导航栏、屏幕比例（长屏）都要用运行时测量，不要写死像素。
  • 深色模式：useColorScheme() 适配系统主题。

九、常见坑清单 ​

  1. 长列表用 ScrollView + map → 全量渲染卡死；必须用 FlatList/SectionList 虚拟化 + getItemLayout。
  2. renderItem 内联函数/匿名对象 → 每次父渲染重建，子项全量 re-render；用 memo + useCallback + 稳定 key。
  3. 动画未开 useNativeDriver → JS 线程一卡动画就掉帧。
  4. Bridge 时代思维：高频跨桥通信 → 序列化开销大；新架构用 JSI 同步能力，但同样要避免高频不必要调用。
  5. 样式依赖继承/默认 row → RN 默认 flexDirection: column、无样式继承，照搬 Web CSS 必错。
  6. 原生依赖改了没 pod install/没重建 → iOS 编译失败或运行崩溃。
  7. Android 12+ 蓝牙权限未拆分申请 → 扫描无结果；BLUETOOTH_SCAN/CONNECT 需运行时申请。
  8. keystore/密钥提交进仓库 → 安全与合规问题；用 CI 机密注入。
  9. 忽略键盘遮挡 → 表单输入被键盘盖住；用 KeyboardAvoidingView 或 react-native-keyboard-controller。
  10. 大图/未缓存图片 → 列表滚动卡顿、OOM；用 fast-image + 按需尺寸。

面试要点 ​

  1. RN 的架构是怎样的？ 答：旧架构是 JS 线程（逻辑）+ Shadow 线程（Yoga 布局）+ UI 线程（原生渲染），三者经 Bridge 异步批量 JSON 通信；新架构用 JSI 去掉桥、Fabric 做同步渲染、TurboModules 懒加载原生模块、Hermes 做 AOT 提速。
  2. Bridge 有什么问题，新架构怎么解决？ 答：旧 Bridge 异步、需 JSON 序列化、高频通信成瓶颈；JSI 让 C++ 对象直接暴露给 JS 支持同步调用，Fabric 支持同步布局与并发渲染，TurboModules 按需加载。
  3. Hermes 是什么，带来什么收益？ 答：RN 默认 JS 引擎，支持 AOT 预编译为字节码，显著降低启动时间、TTI 与内存占用。
  4. RN 的样式和 Web CSS 有什么不同？ 答：JS 对象 + StyleSheet.create，无 CSS；Flex 默认 flexDirection: column（Web 是 row）；尺寸为密度无关单位；无样式继承、无 margin 折叠、无 z-index（靠渲染顺序）；阴影分平台。
  5. 长列表怎么优化？ 答：用 FlatList/SectionList 虚拟化，配 getItemLayout（固定行高跳过测量）、windowSize/maxToRenderPerBatch/initialNumToRender/removeClippedSubviews，item 用 React.memo + 稳定 key。
  6. 怎么减少 RN 组件的 re-render？ 答：React.memo、useCallback/useMemo、状态库细粒度选择器（zustand）、避免内联函数与匿名对象、稳定 key，把动画交给原生线程。
  7. RN 怎么做蓝牙/配网/OTA？ 答：蓝牙用 react-native-ble-plx 扫描连接写特征；配网/OTA 属强原生能力，通常自写 TurboModule/NativeModule，并处理 iOS Info.plist 与 Android 12+ 运行时蓝牙权限。
  8. RN 和 Web 怎么共用逻辑？ 答：把纯逻辑（校验/转换/请求）抽成平台无关模块，通过环境判断或注入适配层（如 storage）在 Web/RN 复用，并用浏览器/Vitest 对纯逻辑单测。
  9. iOS/Android 打包发布流程？ 答：iOS 走 CocoaPods pod install → Xcode Archive → TestFlight；Android 走 Gradle assembleRelease/bundleRelease + keystore 签名，内测传蒲公英/fir.im，密钥用 CI 注入。
  10. App 适配要注意什么？ 答：用 react-native-safe-area-context 处理刘海/安全区、StatusBar、系统字体与字重差异、机型屏幕比例用运行时测量、支持深色模式。
