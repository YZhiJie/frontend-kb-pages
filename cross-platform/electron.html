Electron 桌面端 ​

Electron 命中 3 份 JD（#8 鹏开信息 IM + Electron + 音视频 + Hybrid、#6 鹏业软件多端混合 PC/Android/iOS + 信创、#9 今天国际桌面工具），属差异化加分项。读者做过 Electron 与双端打包，本页把「多进程架构 → IPC → 安全加固 → 原生能力 → 打包与更新 → 性能与崩溃恢复」讲透。Web/H5 侧联调见Hybrid 与 JSBridge，构建工具见构建工具：Vite / Webpack。

一、多进程架构：主进程 / 渲染进程 / 预加载脚本 ​

Electron = Chromium（渲染）+ Node.js（系统能力）+ 一个主进程做调度，本质是 Chromium 的多进程架构 + Node 运行时。

进程职责能力边界
主进程（main）唯一的应用入口，管理窗口/生命周期/菜单/托盘/原生模块完整 Node API，但不渲染页面
渲染进程（renderer）每个 BrowserWindow 一个，跑 Chromium 渲染页面默认无 Node（安全模式），类似普通网页
预加载脚本（preload）在渲染进程页面加载前执行，作为安全桥梁可用部分 Node API，通过 contextBridge 暴露白名单能力
ts
// main.ts —— 主进程：创建窗口
import { app, BrowserWindow } from 'electron';
import path from 'node:path';
function createWindow() {
  const win = new BrowserWindow({
    width: 1200, height: 800,
    show: false,                            // 先隐藏，等 ready-to-show 再显示，避免白屏
    webPreferences: {
      preload: path.join(__dirname, 'preload.js'),
      contextIsolation: true,               // 默认 true，必须保持
      nodeIntegration: false,               // 默认 false，必须保持
      sandbox: true,                        // 渲染进程沙箱
    },
  });
  win.once('ready-to-show', () => win.show());  // 首屏渲染完成再显示
  // 开发环境加载 Vite dev server，生产加载打包好的 HTML
  if (process.env.ELECTRON_RENDERER_URL) win.loadURL(process.env.ELECTRON_RENDERER_URL);
  else win.loadFile(path.join(__dirname, '../renderer/index.html'));
}
app.whenReady().then(createWindow);
app.on('window-all-closed', () => { if (process.platform !== 'darwin') app.quit(); });
app.on('activate', () => { if (BrowserWindow.getAllWindows().length === 0) createWindow(); });

要点：

  • 一个渲染进程 = 一个 BrowserWindow，主进程可用 BrowserWindow.getAllWindows() 管理多个窗口；主进程是单线程，任何同步阻塞操作（大文件同步读写、重计算）都会卡住整个应用。
  • ready-to-show 再显示窗口是白屏治理的第一原则（见后文性能）。

二、进程间通信 IPC ​

Electron 的 IPC 通过 ipcMain（主）/ ipcRenderer（渲染）/ contextBridge（预加载）协作。渲染进程不能直接 require('electron').ipcRenderer（安全模式下不可用），必须在 preload 里暴露。

模式API方向特点
双向（推荐）ipcRenderer.invoke ↔ ipcMain.handle渲染 → 主返回 Promise，最常用
单向ipcRenderer.send → ipcMain.on渲染 → 主不等结果，通知型
推送webContents.send → ipcRenderer.on主 → 渲染主进程主动推送（如进度、消息）
ts
// preload.ts —— 通过 contextBridge 暴露白名单 API
import { contextBridge, ipcRenderer } from 'electron';
contextBridge.exposeInMainWorld('native', {
  readFile: (p: string) => ipcRenderer.invoke('fs:read', p),
  saveFile: (p: string, data: string) => ipcRenderer.invoke('fs:write', { p, data }),
  // 推送：包一层，暴露取消订阅，避免渲染端直接拿到 ipcRenderer
  onDownloadProgress: (cb: (pct: number) => void) => {
    const handler = (_: unknown, pct: number) => cb(pct);
    ipcRenderer.on('download:progress', handler);
    return () => ipcRenderer.removeListener('download:progress', handler);
  },
});
ts
// main.ts —— 注册 handler（主进程）
import { ipcMain, dialog, BrowserWindow } from 'electron';
import fs from 'node:fs/promises';
ipcMain.handle('fs:read', async (event, p: string) => {
  // 安全：校验调用方窗口，防止任意渲染进程/被注入页面调用
  const win = BrowserWindow.fromWebContents(event.sender);
  if (!win) throw new Error('invalid sender');
  return fs.readFile(p, 'utf-8');
});
ipcMain.handle('fs:write', async (_e, { p, data }: { p: string; data: string }) => {
  await fs.writeFile(p, data, 'utf-8');
  return true;
});
ipcMain.handle('dialog:open', async (event) => {
  const win = BrowserWindow.fromWebContents(event.sender);
  return dialog.showOpenDialog(win!, { properties: ['openFile'] });
});
// 主 → 渲染推送
async function notifyProgress(win: BrowserWindow, pct: number) {
  win.webContents.send('download:progress', pct);
}

要点与坑：

  • IPC 参数走结构化克隆（structured clone）：不能传函数、类实例、DOM 对象；传 Date/Map/二进制（ArrayBuffer）可，传自定义类会丢原型。大对象反复传会很慢，大文件应传路径而非内容。
  • 通道命名规范：模块:动作（如 fs:read、dialog:open），避免裸字符串满天飞；不要暴露 ipcRenderer 本身——contextBridge.exposeInMainWorld('ipc', ipcRenderer) 等于把任意通道调用权交给页面，XSS 时可被滥用，应暴露具体白名单方法。
  • 主进程 handler 里校验 event.sender：确认来源窗口合法，防止嵌入 iframe/被注入脚本调用原生能力。

三、窗口管理 ​

ts
// 多窗口 + 无边框自定义标题栏
const main = new BrowserWindow({ /* ... */ });
// 无边框窗口（自定义标题栏）
const frameless = new BrowserWindow({
  frame: false,                                   // 完全无系统边框
  // 或 macOS 保留红绿灯按钮并隐藏标题栏：
  titleBarStyle: 'hiddenInset',
  trafficLightPosition: { x: 12, y: 12 },
  webPreferences: { preload },
});
// 窗口生命周期：拦截关闭做保存确认
main.on('close', (e) => { if (hasUnsavedWork) { e.preventDefault(); askSaveThenQuit(main); } });
main.on('closed', () => { /* 释放引用 */ });
css
/* 自定义标题栏：拖拽区域 */
.titlebar { height: 40px; -webkit-app-region: drag; }        /* 整条可拖窗口 */
.titlebar button { -webkit-app-region: no-drag; }           /* 按钮要排除，否则点不动 */
  • 无边框窗口拖拽区用 -webkit-app-region: drag，其中按钮/输入框必须 no-drag，否则无法点击（经典坑）；macOS 红绿灯按钮用 titleBarStyle: 'hidden' 隐藏标题只留按钮，trafficLightPosition 调位置，Windows 下 titleBarOverlay 可自定义。
  • 窗口间通信：多窗口共享同一主进程，可经主进程中转消息；win.webContents.send 定向发送。
  • 窗口状态持久化（大小/位置）：用 electron-window-state 或在 close 时存盘、启动时读取 bounds。

四、安全加固（面试高频） ​

Electron 的安全模型有明确的「默认安全」演变：从早期允许渲染进程直连 Node，到现在默认 contextIsolation: true / nodeIntegration: false / sandbox: true。

ts
// webPreferences 的安全基线
webPreferences: {
  contextIsolation: true,     // 预加载与页面隔离上下文（默认，勿关）
  nodeIntegration: false,     // 渲染进程禁用 Node（默认，勿开）
  sandbox: true,              // 渲染进程沙箱（默认，勿关）
  webSecurity: true,          // 同源策略生效（默认）
  allowRunningInsecureContent: false,
  preload: path.join(__dirname, 'preload.js'),
}
ts
// 主进程侧：限制导航与新窗口（防钓鱼/注入）
app.on('web-contents-created', (_e, contents) => {
  contents.setWindowOpenHandler(({ url }) => {
    // 只允许白名单域名在系统浏览器打开，其余一律拒绝
    if (isTrusted(url)) shell.openExternal(url);
    return { action: 'deny' };
  });
  contents.on('will-navigate', (e, url) => {
    if (!isTrusted(url)) e.preventDefault();  // 阻止页面内跳转到不可信地址
  });
});
html
<!-- 渲染页面 CSP：不用 unsafe-eval，限制资源来源 -->
<meta http-equiv="Content-Security-Policy"
      content="default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: https:; connect-src 'self' https://api.example.com">
  • CSP 必须设置（unsafe-eval / unsafe-inline 尽量不用），这是渲染进程 XSS 的最后一道闸。
  • 不用 @electron/remote：它把主进程对象暴露给渲染进程，等于放大攻击面，用 contextBridge + invoke/handle 替代；敏感能力（文件、系统命令、剪贴板）只在 preload 暴露最小白名单，不做通用 exec(cmd)。
  • 生产环境禁用 DevTools（webContents.openDevTools() 只在 dev 调用）、关闭 ELECTRON_DEBUG 相关开关。

五、原生能力集成（Node 侧） ​

Electron 的杀手锏是直接在主进程用 Node 生态：

ts
// 1) SQLite：本地数据（better-sqlite3 是同步 API，注意别在主进程阻塞太久）
import Database from 'better-sqlite3';
const db = new Database(path.join(app.getPath('userData'), 'app.db'));
db.exec('CREATE TABLE IF NOT EXISTS history (id INTEGER PRIMARY KEY, payload TEXT)');
db.prepare('INSERT INTO history (payload) VALUES (?)').run(JSON.stringify(record));
// 2) 音视频处理：fluent-ffmpeg 调用 ffmpeg 做转码/截图/合并
import ffmpeg from 'fluent-ffmpeg';
ffmpeg.setFfmpegPath(ffmpegPath); // 打包时需随应用分发 ffmpeg 二进制
ffmpeg('input.mp4')
  .on('progress', (p) => notifyProgress(win, p.percent ?? 0))
  .screenshot({ timemarks: ['00:00:03'], folder: thumbDir })
  .save('out.mp4');
// 3) 系统托盘
import { Tray, Menu } from 'electron';
const tray = new Tray(path.join(__dirname, 'tray.png'));
tray.setContextMenu(Menu.buildFromTemplate([
  { label: '显示主窗口', click: () => main.show() }, { label: '退出', role: 'quit' },
]));
tray.on('click', () => main.show());
  • 原生二进制（ffmpeg/sqlite）要随应用分发：开发环境 require 到系统库没问题，打包后需复制到 resources/asarUnpack，否则「开发能跑、打包就崩」。
  • 协议唤起（Deep Link）：app.setAsDefaultProtocolClient('myapp') 注册自定义协议，配合 open-url（macOS）与 second-instance（Windows）处理冷/热启动参数；单实例锁用 app.requestSingleInstanceLock()，第二个实例退出并把参数交给第一个。
  • 自动启动：app.setLoginItemSettings({ openAtLogin: true })（macOS/Windows 均支持）。
ts
// 单实例 + 协议唤起
if (!app.requestSingleInstanceLock()) { app.quit(); }
else {
  app.on('second-instance', (_e, argv) => {
    const url = argv.find((a) => a.startsWith('myapp://'));
    if (url) handleDeepLink(url);
    main.show(); main.focus();
  });
  app.setAsDefaultProtocolClient('myapp');
}

六、构建与打包 ​

现代 Electron 项目用 electron-vite 统一构建三份产物（main / preload / renderer），再用 electron-builder 打包分发。

ts
// electron.vite.config.ts
import { defineConfig } from 'electron-vite';
import vue from '@vitejs/plugin-vue';
export default defineConfig({
  main:    { build: { outDir: 'out/main' } },
  preload: { build: { outDir: 'out/preload' } },
  renderer: {
    plugins: [vue()], build: { outDir: 'out/renderer' },
    resolve: { alias: { '@': '/src/renderer' } },
  },
});
jsonc
// package.json 的 electron-builder 配置
{
  "build": {
    "appId": "com.example.myapp",
    "productName": "MyApp",
    "directories": { "output": "release" },
    "files": ["out/**/*", "package.json"],
    "asarUnpack": ["**/*.node", "resources/ffmpeg/**"],  // 原生模块不解压进 asar
    "mac":    { "target": ["dmg", "zip"], "category": "public.app-category.productivity", "hardenedRuntime": true, "entitlements": "build/entitlements.mac.plist" },
    "win":    { "target": ["nsis", "portable"], "icon": "build/icon.ico" },
    "linux":  { "target": ["AppImage", "deb"] },
    "publish": { "provider": "generic", "url": "https://dl.example.com/updates/" }
  }
}

命令：electron-vite build && electron-builder --mac --win。

  • asar：默认把应用打成只读归档，**.node（原生模块）与需外部访问的资源放 asarUnpack；图标 mac 用 .icns、win 用 .ico（含多尺寸）、linux 用 PNG。
  • 签名：macOS 分发必须代码签名 + 公证（notarize，否则 Gatekeeper 拦截）；Windows 建议 EV 证书签 NSIS，否则 SmartScreen 告警。
  • 多平台产物：本地一般只能打当前平台；跨平台（Windows 包在 mac 上打）通常靠 CI（见CI/CD 与自动化发布）。

七、自动更新（electron-updater） ​

ts
// main.ts
import { autoUpdater } from 'electron-updater';
autoUpdater.autoDownload = false;   // 让用户确认后再下载
autoUpdater.checkForUpdates();
autoUpdater.on('update-available', (info) => askUser(info.version));
autoUpdater.on('download-progress', (p) => notifyProgress(win, p.percent));
autoUpdater.on('update-downloaded', () => {
  // 提示重启安装（quitAndInstall 会带更新参数重开）
  if (confirmRestart()) autoUpdater.quitAndInstall();
});
autoUpdater.on('error', (err) => log(err));
  • 更新源（publish 的 provider）支持 generic（自建静态服务器）、GitHub Releases、S3 等；macOS 自动更新要求应用已签名且配置 entitlements，否则更新安装失败，Windows NSIS 同理需正确签名。
  • 灰度/强制更新：autoUpdater.channel 分流 + 业务侧版本号比较强制升级；注意开发环境默认不检查更新（app.isPackaged 判断）。

八、性能与稳定性 ​

问题治理手段
首屏白屏ready-to-show 再 show()；预加载脚本轻量；backgroundColor 与主题一致
启动慢延迟初始化重模块（如 DB、ffmpeg）；v8-compile-cache；减少 preload 依赖
内存占用定时清理（关窗口）后 webContents 释放；规避内存泄漏；process.memoryUsage() 监控
主进程阻塞重计算/大 IO 用 utilityProcess / Worker / 异步 API，勿用同步 fs.*Sync
渲染崩溃监听 render-process-gone，自动 reload() 或提示重启
崩溃上报crashReporter.start() + Sentry/自建上报
ts
// 崩溃恢复：渲染进程挂了自动重载
main.webContents.on('render-process-gone', (_e, details) => {
  logCrash(details.reason);          // 'crashed' | 'oom' | 'killed' ...
  main.webContents.reload();         // 或提示用户
});
process.on('uncaughtException', (err) => log(err)); // 主进程兜底
  • 白屏治理三件套：ready-to-show（首屏）、render-process-gone 自动重载（崩溃）、did-fail-load 错误兜底页（加载失败），是 Electron 面试「稳定交付」的高频追问；进程隔离把重活（视频转码/索引）放到 utilityProcess 或其他 Node 子进程，避免拖垮主进程与 UI。

九、常见坑清单 ​

  1. contextIsolation/nodeIntegration 被关开 → 渲染进程直连 Node，安全崩塌；保持默认安全配置。
  2. 暴露 ipcRenderer 全部通道 → XSS 可调用任意原生能力；只暴露白名单方法并校验 event.sender。
  3. -webkit-app-region: drag 未给按钮设 no-drag → 自定义标题栏按钮点不动；原生模块（ffmpeg/sqlite）打包后找不到 → 需 asarUnpack 或随 resources 分发。
  4. 无边框窗口拖拽/最大化异常 → 未处理 titleBarStyle/trafficLightPosition 与平台差异。
  5. 大对象/文件内容走 IPC → 结构化克隆开销大、易卡；应传路径让主进程读。
  6. 主进程同步阻塞 → dialog.showOpenDialogSync、fs.readFileSync 卡住 UI；改用异步/子进程。
  7. macOS 未签名/公证 → 升级或安装被拦截 → 配置 hardenedRuntime + entitlements + notarize。
  8. 开发能跑打包崩溃 → 多因路径/原生二进制/asar 差异，需在打包产物上回归验证；app.quit 未阻止未保存数据丢失 → 在 close 事件拦截并做保存确认。

十、与目标 JD 的对应点 ​

  • #8 鹏开信息（IM + Electron + 音视频 + Hybrid）：Electron 多窗口 + IPC + fluent-ffmpeg 音视频处理 + Deep Link 唤起，直接对口；IM 侧见IM 即时通讯前端、音视频与 WebRTC。
  • #6 鹏业软件（PC/Android/iOS 多端混合 + 信创）：Electron 打包多平台产物 + 更新分发，对应「多端一致交付」；**#9 今天国际（AI 协作 + 架构）**则关注把窗口/菜单/托盘/IPC 封装成内部框架，体现「公共能力建设」。

面试要点 ​

  1. Electron 有哪几个进程，各做什么？ 答：主进程（应用入口，管理窗口/生命周期/原生模块，单线程）、渲染进程（每个 BrowserWindow 一个，跑 Chromium 页面）、预加载脚本（页面加载前执行，用 contextBridge 暴露白名单原生能力的安全桥梁）。
  2. IPC 有哪几种方式？推荐哪种？ 答：invoke/handle（双向，返回 Promise，推荐）、send/on（单向通知）、webContents.send（主推渲染）；都经结构化克隆传参。
  3. contextBridge 为什么要用它而不是直接暴露 ipcRenderer？ 答：contextIsolation 下渲染进程拿不到 Node/electron，且直接暴露 ipcRenderer 会让页面 XSS 可调用任意原生通道；contextBridge 只暴露白名单方法，缩小攻击面。
  4. Electron 的安全基线是什么？ 答：contextIsolation:true、nodeIntegration:false、sandbox:true、设置 CSP、不用 @electron/remote、setWindowOpenHandler/will-navigate 限制导航、IPC 校验 event.sender。
  5. 无边框窗口怎么做？拖拽区为什么点不动？ 答：frame:false 或 titleBarStyle:'hidden'，用 -webkit-app-region: drag 做拖拽；按钮/输入必须 no-drag，否则被当成拖拽区点不动。
  6. 首屏白屏怎么治理？ 答：窗口先 show:false，ready-to-show 后再 show()；preload 保持轻量、backgroundColor 与主题一致，配合 did-fail-load 兜底页。
  7. 进程崩溃怎么恢复？ 答：主进程监听 render-process-gone 自动 reload 或提示重启，did-fail-load 显示错误页，主进程用 uncaughtException 兜底 + crashReporter 上报。
  8. 打包后原生模块（ffmpeg/sqlite）报错怎么办？ 答：原生 .node 与外部二进制放 asarUnpack 或 resources 随包分发，并在真实打包产物上回归，而非只在开发环境验证。
  9. 自动更新怎么做？有什么前提？ 答：用 electron-updater，configure publish 源，checkForUpdates → 下载 → quitAndInstall；macOS/Windows 都必须正确签名（mac 还需公证），否则更新安装失败。
  10. 主进程被卡住怎么办？ 答：主进程单线程，重计算/大 IO 用 utilityProcess/Worker/异步 API，避免 *Sync 同步调用；把耗时任务剥离出主线程。
