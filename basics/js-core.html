JavaScript 核心机制 ​

JS 面试的分水岭不在"会不会用 API"，而在能不能讲清运行时的机制：变量怎么查找、this 怎么确定、代码怎么排队执行、内存怎么回收。这些机制决定了你能写出没有泄漏的闭包、正确的异步并发控制，以及可解释的响应式系统。

对应 JD 要求 A2（JS ES6+ 基础）+ C 级"数据结构与算法 / 响应式原理"（3 份 JD）。

一、原型与原型链 ​

prototype（函数独有，指向原型对象）、__proto__ / [[Prototype]]（每个对象都有，指向构造函数的 prototype）、constructor（原型对象上指回构造函数）。

js
function Person(name) { this.name = name; }
Person.prototype.greet = function () { return `hi ${this.name}`; };

const p = new Person('Ann');
p.greet();                                       // 'hi Ann'（沿原型链找到）
Object.getPrototypeOf(p) === Person.prototype;   // true
Person.prototype.constructor === Person;         // true

new Person('Ann') 做四件事：建空对象 → 其 [[Prototype]] 指向 Person.prototype → 以它为 this 执行构造函数 → 返回该对象（构造函数返回对象则覆盖）。

读取 p.greet 沿 p → Person.prototype → Object.prototype → null 逐层查找，找到即停，否则 undefined；null 是终点。两个关键推论：

  • 写属性不沿链查找：p.x = 1 只在 p 自身创建。
  • in 查整条链，Object.hasOwn 只查自身；instanceof 检查 prototype 是否在链上。

class 是原型链语法糖：Child.prototype 的 [[Prototype]] 指向 Parent.prototype；但方法不可枚举、且声明存在 TDZ（无提升）。

二、闭包与内存 ​

闭包 = 函数 + 它能访问的外层词法环境；只要内层函数被外部引用，捕获的外层变量就不会被回收。

js
function counter() {
  let count = 0;                     // 被闭包捕获，常驻内存
  return { inc: () => ++count, get: () => count };
}
const c = counter(); c.inc(); c.inc(); c.get(); // 2

经典陷阱：循环里 var 共享同一变量。

js
for (var i = 0; i < 3; i++) setTimeout(() => console.log(i)); // 3 3 3
for (let i = 0; i < 3; i++) setTimeout(() => console.log(i)); // 0 1 2（每轮独立绑定）

闭包延长变量生命周期，但不等于泄漏：泄漏是"不再需要却仍可达"，如事件监听捕获大对象却从不 removeEventListener、定时器从不 clearInterval。

三、this 绑定规则 ​

优先级从高到低：new > 显式（call/apply/bind）> 隐式（对象方法）> 默认绑定。箭头函数不绑定 this，取定义时外层。

js
function who() { return this?.tag; }
const obj = { tag: 'obj', who };
obj.who();                 // 'obj'   隐式
who.call({ tag: 'call' }); // 'call'  显式
new who();                 // undefined  new（this 是新对象）

const loose = obj.who;     // 隐式丢失：方法被单独取出
loose();                   // undefined（严格模式；非严格为 globalThis）
  • bind 返回新函数且 this 永久固定，但 new 该 bind 函数时 this 会被 new 覆盖。
  • 事件回调用箭头函数可保留外层 this；ESM 默认严格模式，默认绑定 this 为 undefined（模块里"this 变 undefined"的原因）。

四、作用域、提升与执行上下文 ​

  • 作用域链在函数定义时确定（词法作用域），与调用位置无关；with / eval 会破坏它，禁用。
  • 提升：var 提升到函数顶部并初始化为 undefined；函数声明整体提升；let / const 提升但进入暂时性死区（TDZ），访问报 ReferenceError。
  • 执行上下文：调用函数时创建，含变量环境（var/function）、词法环境（let/const）、this 绑定；全局上下文只有一份。
js
console.log(a); // undefined（var 提升）
var a = 1;
console.log(b); // ReferenceError（TDZ）
let b = 2;
foo();          // 可调用（函数声明整体提升）
function foo() {}
// 函数表达式则不提升：bar() 会 TypeError
var bar = function () {};

五、事件循环 ​

5.1 浏览器：宏任务与微任务 ​

  • 宏任务：script 整体、setTimeout、setInterval、MessageChannel、I/O、UI 渲染；每轮取一个执行。
  • 微任务：Promise.then、queueMicrotask、MutationObserver；每个宏任务结束后清空微任务队列，再渲染、再取下一个宏任务。
js
console.log('1');
setTimeout(() => console.log('2'), 0);          // 宏
Promise.resolve().then(() => console.log('3')); // 微
queueMicrotask(() => console.log('4'));         // 微
console.log('5');
// 输出：1 5 3 4 2（`setTimeout(fn,0)` 也要排在微任务之后）

5.2 requestAnimationFrame 与 Node 差异 ​

rAF 在下一次重绘前执行（约 60fps / 16.7ms 一次），位于宏任务与渲染之间；requestIdleCallback 在帧空闲时执行。动画用 rAF 而非 setTimeout，才能对齐刷新、避免撕裂。

Node 的宏任务分阶段（timers → poll → check 等），每阶段之间清空微任务，且 process.nextTick 优先于 Promise；setImmediate（check 阶段）与 setTimeout(0) 的顺序受 I/O 影响，不稳定。

六、Promise 与 async/await ​

6.1 手写 Promise（状态机 + 链式） ​

状态单向 pending → fulfilled | rejected 不可逆，then 返回新 Promise 支持链式。

ts
class MyPromise<T> {
  private state: 'pending' | 'fulfilled' | 'rejected' = 'pending';
  private value?: T;
  private cbs: Array<() => void> = [];
  constructor(executor: (res: (v: T) => void, rej: (r: unknown) => void) => void) {
    const settle = (st: 'fulfilled' | 'rejected') => (v: unknown) => {
      if (this.state !== 'pending') return;             // 状态一旦确定不再变
      this.state = st; this.value = v as T;
      this.cbs.forEach((cb) => queueMicrotask(cb));     // 回调必须异步执行
    };
    try { executor(settle('fulfilled'), settle('rejected')); }
    catch (e) { settle('rejected')(e); }                // 同步抛错 → reject
  }
  then<U>(onF?: (v: T) => U, onR?: (r: unknown) => U): MyPromise<U> {
    return new MyPromise<U>((resolve, reject) => {
      const run = () => {
        try {
          if (this.state === 'fulfilled') resolve(onF?.(this.value as T) as U);
          else reject(onR ? onR(undefined) : this.value);
        } catch (e) { reject(e); }                      // 回调抛错 → 新 Promise reject
      };
      this.state === 'pending' ? this.cbs.push(run) : queueMicrotask(run);
    });
  }
}

完整实现还需：resolve 传入 Promise 时递归展开、then 返回自身致死循环（TypeError）、onFulfilled 非函数时透传。

6.2 async/await 是 Promise 的语法糖 ​

async 函数总返回 Promise；await 等价 then，把后续代码排入微任务。批量并发优先 Promise.allSettled（各自带 status，不因一个失败全崩），比 await 串行快得多；Promise.all 则一败全败。

6.3 并发控制（限制同时请求数） ​

ts
async function pool<T>(tasks: Array<() => Promise<T>>, limit = 4): Promise<T[]> {
  const results: T[] = new Array(tasks.length);
  let cursor = 0;
  async function worker() {
    while (cursor < tasks.length) {
      const i = cursor++;                 // 抢占式取任务
      results[i] = await tasks[i]();
    }
  }
  await Promise.all(Array.from({ length: Math.min(limit, tasks.length) }, worker));
  return results;
}

七、ES6+ 核心特性 ​

ts
const { data: list = [], page = 1 } = response;   // 解构 + 默认值 + 重命名
const [first, , third] = arr;                     // 跳过第二项
const city = user?.address?.city ?? '未知';        // 可选链 + 空值合并（0/'' 保留）
const port = config.port ?? 8080;                 // config.port=0 时取 0
opts.retries ??= 3;                               // 仅 null/undefined 才赋值

// Proxy + Reflect：拦截对象操作（响应式基础）
const reactive = <T extends object>(t: T) => new Proxy(t, {
  get(o, k, r) { /* track(o, k) */ return Reflect.get(o, k, r); },
  set(o, k, v, r) { const ok = Reflect.set(o, k, v, r); /* trigger(o, k) */ return ok; },
});

Proxy 配 Reflect 的原因：Reflect 提供可接收 receiver 的默认行为，保证原型链上的 getter/setter 中 this 指向代理而非原始对象。

八、深拷贝 ​

  • JSON.parse(JSON.stringify())：快，但循环引用抛错，丢失 Date/RegExp/Map/undefined 与函数。
  • 手写递归：需 WeakMap 处理循环引用、手动分支特殊类型，可保留函数引用。
  • structuredClone()：原生，支持循环引用与 Date/Map/Set/ArrayBuffer，但克隆函数/Symbol/DOM 抛 DataCloneError。
ts
const copy = structuredClone(original); // 现代浏览器与 Node 17+；克隆函数/Symbol/DOM 会抛错

function deepClone<T>(v: T, seen = new WeakMap<object, unknown>()): T {
  if (v === null || typeof v !== 'object') return v;
  if (seen.has(v as object)) return seen.get(v as object) as T;   // 循环引用
  if (v instanceof Date) return new Date(v.getTime()) as T;
  if (v instanceof RegExp) return new RegExp(v.source, v.flags) as T;
  const out: any = Array.isArray(v) ? [] : Object.create(Object.getPrototypeOf(v));
  seen.set(v as object, out);
  for (const k of Reflect.ownKeys(v as object)) out[k] = deepClone((v as any)[k], seen);
  return out;
}

坑：用 WeakMap 而非 Map（后者强引用拷贝源、阻止 GC）；structuredClone 会丢失自定义类实例的方法。

九、防抖与节流 ​

  • 防抖：高频事件停止 N ms 后执行一次（搜索输入、resize 重算）。
  • 节流：固定间隔最多执行一次（滚动监听、拖拽）。
ts
function debounce<F extends (...a: any[]) => void>(fn: F, wait = 300) {
  let timer: ReturnType<typeof setTimeout> | null = null;
  return (...args: Parameters<F>) => {
    if (timer) clearTimeout(timer);
    timer = setTimeout(() => { timer = null; fn(...args); }, wait);
  };
}

function throttle<F extends (...a: any[]) => void>(fn: F, interval = 200) {
  let last = 0;
  let timer: ReturnType<typeof setTimeout> | null = null;
  return (...args: Parameters<F>) => {
    const remain = interval - (Date.now() - last);
    if (remain <= 0) { last = Date.now(); fn(...args); }               // 立即执行
    else if (!timer) timer = setTimeout(() => {                        // 尾部补发
      last = Date.now(); timer = null; fn(...args);
    }, remain);
  };
}

React 中 useCallback 包裹防抖却未处理其内部 fn，会因闭包捕获旧 state 而"永远看到旧值"——用 useRef 保存最新回调。

十、垃圾回收与内存泄漏 ​

V8 分代回收：新生代用 Scavenge（Cheney 复制算法，存活对象晋升老生代）；老生代用标记-清除 + 标记-压缩。可达性用标记法（从 GC Roots 出发可达即存活），所以循环引用能被回收（非引用计数）。

泄漏源机理修复
未移除的监听捕获 DOM 与大对象removeEventListener（同一引用）
定时器未清理setInterval 引用闭包卸载时 clearInterval
游离 DOM被 JS 变量持有置空引用
闭包持有大对象长期可达置 null 或改 WeakMap / WeakRef

排查：DevTools Memory 面板堆快照对比，"Detached DOM tree" 定位游离节点；Performance monitor 看 JS heap 是否持续上升。

十一、数据结构与算法在前端 ​

  • 栈 / 队列：调用栈、撤销重做；消息队列、限流池、任务调度。
  • 哈希表（Map / Set）：去重、memoize、O(1) 查找；对象作 key 用 Map，基本类型用 Set。
  • 树 / 双指针：DOM 与权限树、vdom diff、虚拟滚动与滑窗统计。
ts
class LRU<K, V> {                                  // O(1)：利用 Map 插入序
  private map = new Map<K, V>();
  constructor(private cap: number) {}
  get(k: K): V | undefined {
    if (!this.map.has(k)) return undefined;
    const v = this.map.get(k)!;
    this.map.delete(k); this.map.set(k, v);        // 删除再插入 → 移到最新
    return v;
  }
  set(k: K, v: V): void {
    this.map.delete(k); this.map.set(k, v);
    if (this.map.size > this.cap) this.map.delete(this.map.keys().next().value!); // 汰最旧
  }
}

十二、Vue2 与 Vue3 响应式原理 ​

维度Vue2Vue3
核心 APIObject.definePropertyProxy + Reflect
新增 / 删除属性检测不到（须 Vue.set/delete）可检测
初始化递归遍历所有属性（慢）惰性，访问时才递归（get 中）
Map / Set不支持支持

defineProperty 初始化时一次性递归劫持已知键，是"新增属性不响应"的根因；Proxy 拦截整个对象的操作（get/set/has/delete/ownKeys）且惰性代理，只有被访问的嵌套对象才创建代理，初始化成本大降。

js
let activeEffect = null;                                   // 当前执行的副作用
const targetMap = new WeakMap();                           // target -> key -> effects
function track(t, k) {
  if (!activeEffect) return;
  let deps = targetMap.get(t) ?? (targetMap.set(t, (deps = new Map())), deps);
  let effs = deps.get(k) ?? (deps.set(k, (effs = new Set())), effs);
  effs.add(activeEffect);                                  // 建立依赖
}
function trigger(t, k) { targetMap.get(t)?.get(k)?.forEach((e) => e()); } // 派发更新
const reactive = (t) => new Proxy(t, {
  get(o, k, r) { track(o, k); return Reflect.get(o, k, r); },
  set(o, k, v, r) { const ok = Reflect.set(o, k, v, r); trigger(o, k); return ok; },
});

reactive 只代理对象；ref 用 RefImpl 包装任意值（含基本类型），经 .value 触发 track。shallowReactive / shallowRef 控制浅响应，避免大对象全量代理。

十三、实战要点与常见坑 ​

  1. 用 Object.hasOwn(obj, k) 代替 obj.hasOwnProperty(k)（后者可能被同名属性遮蔽）；Map 的 key 可为任意值，Object 的 key 只能是 string/symbol。
  2. Promise.all 一败全败，批量场景优先 allSettled；需要结果顺序用索引写入而非 push。
  3. structuredClone 不能克隆函数 / DOM / Symbol，会抛 DataCloneError。
  4. 移除监听必须传同一函数引用，addEventListener(fn) 后 removeEventListener(() => fn) 无效。
  5. async 里 try/catch 只能捕获 await 的错误，未 await 的 rejection 变成 unhandled rejection。
  6. 闭包捕获的是变量而非值，要固定值得在创建时用参数传入或用 let 块级作用域。
  7. Vue3 的 reactive 解构会丢响应性（需 toRefs）；Vue.set 在 Vue3 中不再需要。

面试要点 ​

  1. 原型链是什么？ 对象经 [[Prototype]] 连到构造函数 prototype，逐层查到 Object.prototype → null；读沿链查找，写只在自身。
  2. 闭包会内存泄漏吗？ 闭包本身不泄漏，是"长期可达却不再需要"的引用导致；用 WeakMap、及时解绑与置空规避。
  3. this 绑定优先级？ new > call/apply/bind > 隐式（对象方法）> 默认；箭头函数不绑定 this，取外层词法。
  4. var / let / const 区别？ var 函数作用域 + 提升为 undefined；let/const 块级 + TDZ；const 禁重新赋值（对象内部仍可变）。
  5. 微任务与宏任务顺序？ 每个宏任务后清空全部微任务，再渲染，再取下一个宏任务；setTimeout(fn,0) 排在微任务之后。
  6. 浏览器与 Node 事件循环差异？ Node 分阶段（timers/poll/check）且 process.nextTick 优先于 Promise；setImmediate 与 setTimeout(0) 顺序不稳定。
  7. async/await 原理？ async 返回 Promise，await 等价 then，后续代码进微任务队列。
  8. 深拷贝怎么做？ 优先 structuredClone；手写版用 WeakMap 处理循环引用并对 Date/RegExp/Map 分支。
  9. Vue2 与 Vue3 响应式差异？ defineProperty 递归劫持已知键（新增/删除/索引失效）vs Proxy 拦截整体操作 + 惰性递归（全支持）。
