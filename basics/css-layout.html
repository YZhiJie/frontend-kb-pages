CSS 布局与样式工程 ​

CSS 的难点不在"记属性"，而在布局计算规则（盒模型、格式化上下文、层叠）与样式工程化（命名、隔离、主题化）。面试常问"为什么 z-index 不生效""怎么居中"，日常则大量消耗在变量体系与冲突排查上。本页把机制与工程实践串起来。

对应 JD 要求 A2（扎实 CSS3 基础）；命中 C 级"Tailwind / Sass / Less / CSS Modules"样式方案条款。

一、盒模型与 box-sizing ​

1.1 两种盒模型 ​

标准盒模型 content-box（默认）：width / height 只算内容，padding 与 border 加到外面。IE 怪异模式与 border-box：width 包含 content + padding + border。

css
*,
*::before,
*::after {
  box-sizing: border-box;
}

现代项目一律全局 reset 成 border-box，原因是：给一个 width: 100px; padding: 10px 的元素，直觉上希望它占 100px 而非 120px；border-box 让"声明宽度 = 渲染宽度"，避免加 padding 就爆版的连锁修改。

1.2 margin 折叠（Collapsing Margin） ​

垂直方向相邻块级元素的 margin 会折叠（取较大值，不是相加）：

  • 相邻兄弟：A margin-bottom 与 B margin-top 折叠取 max。
  • 父子：父无 border/padding/BFC 时，子 margin-top 会"穿透"到父外面。

折叠只发生在垂直方向、块级格式化上下文内；行内格式化上下文、Flex / Grid 容器内的子项不折叠。这也是 Flex 常见"为什么父容器 padding 与子 margin 表现不同"的原因。规避手段：给父加 padding / border / overflow: hidden（创建 BFC）。

二、BFC（块级格式化上下文） ​

2.1 它解决什么问题 ​

BFC 是一块独立的布局环境，内部布局不影响外部。触发条件（满足任一）：

  • 根元素 <html>
  • float 不为 none
  • position: absolute / fixed
  • display: flow-root（专用方案，无副作用）
  • overflow 不为 visible（hidden / auto / scroll）
  • display: inline-block / table-cell / flex / grid 子项
  • contain: layout / content

2.2 三大经典用途 ​

  1. 清除浮动：父元素触发 BFC 后，会包含浮动子元素的高度（不会塌陷），无需 clearfix hack。
  2. 阻止 margin 折叠：父触发 BFC，子 margin-top 不再穿透。
  3. 避免文字环绕：实现两栏自适应——左栏 float: left，右栏触发 BFC，右栏宽度自适应且不与浮动重叠。
css
/* 现代清除浮动：优先 flow-root，语义清晰无副作用 */
.clearfix,
.layout {
  display: flow-root;
}

/* 两栏自适应：左侧固定，右侧撑满 */
.side { float: left; width: 200px; }
.main { overflow: hidden; } /* 触发 BFC，形成独立布局块 */

三、层叠上下文与 z-index ​

3.1 z-index 为什么"不生效" ​

根因是 z-index 只在同一层叠上下文（Stacking Context）内比较。若父元素自己创建了层叠上下文，子元素的 z-index 再大也无法超越父层级——它被"关"在父的上下文里。

创建层叠上下文的常见条件（不完整列举）：

  • 根元素
  • position: absolute/relative/fixed/sticky 且 z-index 不为 auto
  • opacity < 1
  • transform / filter / perspective / will-change 不为 none（最容易踩）
  • isolation: isolate
  • mix-blend-mode 不为 normal
  • Flex / Grid 子项且 z-index 不为 auto

3.2 实战案例 ​

html
<!-- 现象：.tip 是弹层，z-index 9999，却被 .card 里 z-index 1 的内容盖住 -->
<div class="card" style="transform: translateZ(0)"> <!-- 创建了层叠上下文 -->
  <div class="card-body" style="position: relative; z-index: 1">卡片内容</div>
  <div class="tip" style="position: absolute; z-index: 9999">提示</div>
</div>

因为 .card 因 transform 成了层叠上下文，.tip 的 9999 只在 .card 内部有效，整体 .card 的层级由它自身的 z-index（auto）决定，被 card-body 的 z-index:1 盖住。

解决：把弹层移到 body 直接子级（如 React 的 createPortal）、或用 popover / 原生 <dialog>、或统一用 isolation 与约定好的 z-index 分层变量。

css
/* 建立全局 z-index 分层变量，避免"数字军备竞赛" */
:root {
  --z-dropdown: 1000;
  --z-sticky: 1020;
  --z-modal-mask: 1050;
  --z-modal: 1060;
  --z-toast: 1080;
}

四、Flex 布局 ​

4.1 容器属性 ​

属性值说明
flex-directionrow(默认) column row-reverse column-reverse主轴方向
flex-wrapnowrap(默认) wrap wrap-reverse是否换行
justify-contentflex-start center space-between space-around space-evenly flex-end主轴对齐
align-itemsstretch(默认) flex-start center flex-end baseline交叉轴对齐
align-content同 align-items 值多行时的行间对齐（单行无效）
gap长度行列间距（代替 margin 方案）

4.2 项目属性 ​

  • flex: <grow> <shrink> <basis>，简写覆盖三者。flex: 1 = 1 1 0%；flex: auto = 1 1 auto；flex: none = 0 0 auto。
  • flex: 1 vs flex: auto 区别：1 1 0% 忽略内容基准尺寸，均分剩余空间；1 1 auto 以内容尺寸为基准再分配，内容多的一侧会更大。这也是"两栏等比"与"按内容自适应"的关键分水岭。
  • flex-shrink 默认 1，意味着内容会被压缩；想让某项不被压扁，设 flex-shrink: 0（经典"头像不被压扁"）。
  • min-width: 0 陷阱：Flex 项目默认 min-width: auto，内容（如长文本/表格）会撑爆容器不换行；给项目加 min-width: 0 才能让内部 text-overflow: ellipsis 生效。

4.3 常见布局 ​

css
/* 1. 水平垂直居中 */
.center { display: flex; align-items: center; justify-content: center; }

/* 2. 两栏：左右固定、中间自适应 */
.layout { display: flex; }
.aside { flex: 0 0 220px; }
.main { flex: 1; min-width: 0; } /* min-width:0 才能内部省略号生效 */

/* 3. 单行列表两端对齐 + 自动间距 */
.toolbar { display: flex; align-items: center; gap: 12px; }
.toolbar .spacer { flex: 1; } /* 弹性空隙把右侧推到尽头 */

/* 4. 等高列（Flex 默认 stretch 交叉轴拉伸，天然等高） */
.pricing { display: flex; }
.pricing > * { flex: 1; } /* 每列等高，无需 hack */

五、Grid 布局 ​

Grid 是二维（行列同时控制），与 Flex 的一维定位互补。

属性说明
grid-template-columns列定义，可用 repeat() / minmax() / fr
grid-template-rows行定义
grid-template-areas用名称"画"布局，可读性最高
gap行列间距
grid-column / grid-row项目跨行列（span 2 / 1 / 3）
css
/* 自适应卡片墙：无需媒体查询，列数随宽度自动增减 */
.card-wall {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(240px, 1fr));
  gap: 16px;
}

/* 经典页面骨架：命名区域一眼看懂 */
.app {
  display: grid;
  grid-template-columns: 220px 1fr;
  grid-template-rows: 56px 1fr 40px;
  grid-template-areas:
    "header header"
    "aside  main"
    "footer footer";
  min-height: 100vh;
}
.app > .header { grid-area: header; }
.app > .aside  { grid-area: aside; }
.app > .main   { grid-area: main; }

/* 跨行表头/大屏仪表盘：跨列跨行 */
.hero { grid-column: 1 / 3; }

选型建议：一维排列用 Flex，二维/骨架/仪表盘用 Grid。auto-fit 与 auto-fill 区别：容器宽时 auto-fit 会把空轨道折叠使现有项撑满；auto-fill 保留空轨道。卡片墙通常用 auto-fill 保持等宽，或用 auto-fit 让少量卡片撑满。

六、定位体系 ​

position参照物是否脱离文档流典型场景
relative自身原位置否（占位保留）建立定位上下文、微调
absolute最近的非 static 祖先（否则初始包含块）是弹层、角标、悬浮按钮
fixed视口（有 transform 祖先时改为该祖先）是固定导航、回到顶部
sticky最近滚动容器否（滚动到阈值前占位）吸顶表头、侧边目录

sticky 失效三兄弟：父容器 overflow: hidden/auto（滚动容器变了）、没有可滚动的父级空间、或祖先有 transform 导致参照系偏移。移动端 iOS 上 fixed 与软键盘、position: fixed 在 transform 父级下的行为也常出问题——这是 Hybrid 联调（见 Hybrid 与 JSBridge）的常见 bug 来源。

七、居中方案大全 ​

css
/* 1. Flex（首选，兼容好） */
.a { display: flex; align-items: center; justify-content: center; }

/* 2. Grid（最简） */
.b { display: grid; place-items: center; } /* place-items = align + justify */

/* 3. absolute + transform（不知宽高，脱离流） */
.c { position: absolute; top: 50%; left: 50%; transform: translate(-50%, -50%); }

/* 4. absolute + inset 0 + margin auto（固定宽高） */
.d { position: absolute; inset: 0; margin: auto; width: 200px; height: 120px; }

/* 5. line-height 单行文本垂直居中 */
.f { height: 40px; line-height: 40px; }

优先级：能 Flex/Grid 就别 absolute+transform（后者在小数像素下可能产生半像素模糊）。

八、样式工程化 ​

8.1 BEM 命名 ​

block__element--modifier：块、块内元素（__）、修饰状态（--）。

css
.card {}
.card__title {}
.card__title--highlight {}
.card--disabled {}

价值：扁平化 + 可预测，避免嵌套选择器带来的特异性（specificity）战争。缺点：类名冗长，深层嵌套时 card__header__icon 这类命名会失控（BEM 只允许一层 __）。现代项目常由 CSS Modules / Tailwind 部分替代。

8.2 CSS 变量与主题化 ​

css
:root {
  --color-bg: #ffffff;
  --color-text: #1f2937;
  --color-primary: #2563eb;
  --radius-md: 8px;
}

/* 暗色主题：只覆盖变量值，组件样式零改动 */
[data-theme="dark"] {
  --color-bg: #0f172a;
  --color-text: #e5e7eb;
  --color-primary: #3b82f6;
}

.card {
  background: var(--color-bg);
  color: var(--color-text);
  border-radius: var(--radius-md);
}
ts
// 主题切换：写 data-theme 到 <html>，并持久化
type Theme = 'light' | 'dark';
function setTheme(theme: Theme) {
  document.documentElement.dataset.theme = theme;
  localStorage.setItem('theme', theme);
}
// 首屏防闪烁：在 <head> 内联脚本先读 localStorage 设 data-theme，
// 避免 SSR/首帧还是 light 后跳 dark（FOUC）

坑：Tailwind v3 的 darkMode: 'class' 配 dark: 前缀同理；变量作用域是继承的，所以能在任意子树覆盖做局部主题（如"深色侧边栏 + 浅色内容区"）。

8.3 各方案对比 ​

方案隔离粒度运行时开销动态能力学习成本适用
原生 / BEM约定，无强制无变量/data-*低中小项目、老系统
Sass / Less编译期，无运行隔离无（编译后为普通 CSS）嵌套/变量/mixin中需要 mixin/函数/循环
CSS Modules局部作用域（hash 类名）无组合 composes低组件化项目、React 首选
CSS-in-JS（emotion/styled）强（组件级）有（运行时生成）props 驱动样式中高强动态主题、设计系统
Tailwind 原子化约定，靠工具排序无（构建期生成）响应式/状态前缀中快速搭建、设计约束强

Tailwind 优缺点：优点是命名问题消失、样式与结构同处、内置设计约束（spacing 刻度）、按需生成未用类可摇树；缺点是类名冗长、复杂组件可读性差、抽象要通过 @apply 或组件封装，且团队需统一"何时抽组件"的共识。

8.4 样式隔离与冲突治理 ​

  • CSS Modules：import styles from './card.module.css'，类名编译为 card__title___a1b2c，天然局部，不改全局。跨模块复用的公共类放 :global(.reset) 或单独 global 文件。
  • Scoped（Vue SFC）：给元素加 data-v-xxx 属性 + 属性选择器实现隔离；::v-deep / :deep() 才可穿透子组件。
  • 特异性（specificity）冲突：!important、#id、深层嵌套是三大"雾霾"来源。治理手段：用 @layer 显式声明层叠层优先级，让 reset < base < components < utilities 顺序固定，不再比选择器权重。
css
@layer reset, base, components, utilities; /* 顺序即优先级，越靠后越高 */

@layer components {
  .btn { padding: 8px 16px; border-radius: 6px; }
}
@layer utilities {
  .mt-2 { margin-top: 8px; } /* 永远能覆盖 components，无需 !important */
}

九、实战要点与常见坑 ​

  1. z-index 出问题先查祖先是否创建了层叠上下文（transform / opacity / filter 是惯犯），而不是盲目加数字。
  2. Flex 项目要省略号生效，必须给项目 min-width: 0，否则内容撑破容器。
  3. gap 优先于 margin：Flex / Grid 的 gap 不产生首尾多余间距，也避免 margin 折叠。
  4. aspect-ratio 已可替代 padding-top hack：aspect-ratio: 16 / 9 一行搞定，兼容现代浏览器（含 Safari 15+）。
  5. @layer 是治理 !important 泛滥的正解，配合 Tailwind 的 base/components/utilities 天然分层。
  6. 暗色主题在 <head> 内联脚本里先定 data-theme，避免首帧 FOUC 闪白。
  7. will-change 不要滥用：它会创建层叠上下文并常驻合成层，用多了反而吃显存。

面试要点 ​

  1. content-box 与 border-box 区别？ 前者 width 只含内容，后者含 padding + border；现代项目全局 reset 为 border-box。
  2. margin 折叠的条件？ 仅垂直方向、块级格式化上下文内的相邻兄弟或父子（父无 border/padding/BFC 时）折叠取 max。
  3. BFC 是什么、触发条件与用途？ 独立布局环境；flow-root / overflow!=visible / float / absolute / flex-grid 子项等触发；用于清浮动、阻折叠、两栏自适应。
  4. z-index 为什么不生效？ z-index 只在同一层叠上下文内比较；祖先的 transform/opacity/filter 会把子元素"锁"在较低层级。
  5. flex: 1 和 flex: auto 区别？ 1 = 1 1 0%（忽略内容基准均分），auto = 1 1 auto（按内容尺寸分配）。
  6. Flex 里文字省略号失效怎么修？ 给项目加 min-width: 0（默认 min-width: auto 被内容撑开）。
  7. auto-fill 与 auto-fit 区别？ 列足够宽时 auto-fit 折叠空轨道让现有项撑满，auto-fill 保留空轨道。
  8. sticky 失效的原因？ 父级 overflow 非 visible 改了滚动容器、无滚动空间、或祖先 transform 改变参照系。
  9. CSS Modules / Scoped / CSS-in-JS 隔离原理？ 分别靠 hash 类名、data-v- 属性选择器、运行时生成唯一类名。
  10. 如何治理 !important 与特异性冲突？ 用 @layer 显式分层固定优先级顺序，约定 reset < base < components < utilities。
