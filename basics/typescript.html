TypeScript 工程实践 ​

TS 的价值不在"给变量贴标签"，而在把约束前移到编译期：接口契约、状态机、跨端类型推导，都能在运行前拦住错误。对双栈组件库而言，TS 更是"一份契约、双端推导"的技术底座。本页从类型系统原理讲到工程落地。

对应 JD 要求 A2（TS 基础，9 份 JD）+ A5（组件库公共能力）+ 简历已具备"TS 严格模式"能力。

一、类型系统与类型推导 ​

TS 是**结构化类型（structural typing）**系统：只要结构兼容就可赋值，与类型名无关（对比 Java/C# 的 nominal typing）。

ts
interface Point { x: number; y: number }
class Vec2 { constructor(public x: number, public y: number) {} }
const p: Point = new Vec2(1, 2); // 合法：结构一致，无需显式 implements

类型推导（inference）让多数场景不用手写类型，但推导有边界：

ts
const n = 1;                 // 1（字面量类型，const 推导最窄）
let m = 1;                   // number（let 推导放宽）
const arr = [1, 'a'];        // (string | number)[]（联合）
const tuple = [1, 'a'] as const; // readonly [1, 'a']（断言成元组常量）

function id<T>(x: T): T { return x; }
const r = id({ a: 1 });      // { a: number }（泛型由实参推导）

注意 widening（拓宽）：let x = 1 变 number，因为后续可能被改；若想要字面量用 as const 或 const x: 1 = 1。

unknown vs any vs never：unknown 是安全顶层类型，使用前必须收窄；any 关闭类型检查（传染）；never 是底层类型，表示"不可能的值"，用于穷尽性检查。

ts
function assertNever(x: never): never {
  throw new Error(`Unexpected: ${JSON.stringify(x)}`);
}

type Status = 'idle' | 'loading' | 'success' | 'error';
function label(s: Status) {
  switch (s) {
    case 'idle': return '待机';
    case 'loading': return '加载中';
    case 'success': return '成功';
    case 'error': return '失败';
    default: return assertNever(s); // 漏掉分支时编译报错
  }
}

二、泛型：约束、默认值与泛型组件 ​

ts
// 约束（extends）：T 必须带 id
function pluck<T extends { id: string }, K extends keyof T>(list: T[], key: K): T[K][] {
  return list.map((item) => item[key]);
}
  • 默认类型参数：<T = string>，调用时可省略。
  • keyof T 取键的联合；T[K] 是索引访问类型（indexed access）。
  • 泛型组件 / 泛型 Hook：列表组件让 columns 与 data 同源推导，避免 any。
tsx
interface Column<T> { key: keyof T & string; title: string; render?: (row: T) => React.ReactNode }
// 列定义与数据类型联动：使用时 key 拼错会立即报错
function DataTable<T extends { id: string }>(p: { data: T[]; columns: Column<T>[]; rowKey: keyof T }) {}
ts
// Vue 3 泛型组件（<script setup lang="ts" generic="T">）
// defineProps<{ items: T[]; keyField: keyof T }>()

三、条件类型与分布式条件类型 ​

ts
type IsString<T> = T extends string ? true : false;
type A = IsString<'a'>;   // true
type B = IsString<1>;     // false

分布式条件类型（distributive）：当条件类型作用于裸类型参数且传入联合类型时，会对每个成员分别求值再合并。

ts
type ToArray<T> = T extends unknown ? T[] : never;
type R1 = ToArray<string | number>;   // string[] | number[]（分布式）

// 阻止分布：用元组包裹
type ToArrayNonDist<T> = [T] extends [unknown] ? T[] : never;
type R2 = ToArrayNonDist<string | number>; // (string | number)[]

Exclude 与 Extract 正是用这个特性实现的——分布式正是"从联合里筛掉/筛选成员"的原理。

ts
type MyExclude<T, U> = T extends U ? never : T;  // Exclude 的分布式实现
type MyExtract<T, U> = T extends U ? T : never;  // Extract 的分布式实现

四、映射类型与键重映射 ​

ts
type MyPartial<T> = { [K in keyof T]?: T[K] };
type MyReadonly<T> = { readonly [K in keyof T]: T[K] };
type Nullable<T> = { [K in keyof T]: T[K] | null };

// 修饰符增删：-readonly 去只读，-? 去可选
type Mutable<T> = { -readonly [K in keyof T]: T[K] };

**键重映射（key remapping，TS 4.1+）**用 as 改写键名，可做 getter/setter 转换或过滤：

ts
type Getters<T> = { [K in keyof T as `get${Capitalize<string & K>}`]: () => T[K] }; // 加前缀，如 { getName }
type FunctionsOf<T> = { [K in keyof T as T[K] extends (...a: any[]) => any ? K : never]: T[K] }; // 过滤键

键重映射是"类型体操"的核心工具，配合模板字面量类型（`get${Capitalize<K>}`）可生成大量结构化类型。

五、infer 推断 ​

infer 在条件类型里声明一个待推断的类型变量，从结构中"提取"类型。

ts
// 提取函数返回值
type MyReturnType<T> = T extends (...args: any[]) => infer R ? R : never;
type P = MyReturnType<() => { id: number }>; // { id: number }

// 提取 Promise 内部值
type MyAwaited<T> = T extends Promise<infer U> ? MyAwaited<U> : T;
type V = MyAwaited<Promise<Promise<string>>>; // string

// 提取数组元素类型
type ElementOf<T> = T extends (infer U)[] ? U : never;

// 提取元组首元素
type Head<T extends any[]> = T extends [infer H, ...any[]] ? H : never;

多个 infer 可同时使用（如 infer H, infer T 拆解 [head, ...tail]）。infer 只能出现在条件类型的 extends 子句中。

六、内置工具类型深入 ​

工具类型定义用途
Partial<T>{ [K in keyof T]?: T[K] }可选配置、patch 更新
Required<T> / Readonly<T>加 -? / 加 readonly强制补全 / 不可变
Pick<T, K>{ [P in K]: T[P] }摘取字段（白名单）
Omit<T, K>Pick<T, Exclude<keyof T, K>>排除字段建 DTO
Record<K, V>{ [P in K]: V }字典 / 映射
Exclude<T, U> / Extract<T, U>T extends U ? never : T / T extends U ? T : never联合剔除 / 筛选
ReturnType<T> / Parameters<T>infer R / infer P取返回值 / 参数元组
Awaited<T>递归展开 Promise取 async 结果

Pick 与 Omit 的取舍：Pick 是"白名单"（只保留 K），Omit 是"黑名单"（排除 K）。组件 props 从契约派生时，白名单更安全——新增字段不会意外泄漏到 props。

ts
interface UserDTO { id: string; name: string; password: string; createdAt: Date }
type SafeUser = Omit<UserDTO, 'password'>;                        // 排除敏感字段
type UserPreview = Pick<UserDTO, 'id' | 'name'>;                  // 白名单
type ApiResult = Awaited<ReturnType<typeof fetchUser>>;           // 从函数签名反向派生

七、类型体操实战 ​

1. 深层只读（DeepReadonly）：递归处理对象与数组。

ts
type DeepReadonly<T> = T extends (infer U)[]
  ? readonly DeepReadonly<U>[]
  : T extends object
    ? { readonly [K in keyof T]: DeepReadonly<T[K]> }
    : T;

2. 联合转交叉（UnionToIntersection）：把 A | B 合成 A & B，常用于合并多源配置。

ts
type UnionToIntersection<U> = (U extends any ? (k: U) => void : never) extends (k: infer I) => void ? I : never;
type Merged = UnionToIntersection<{ a: 1 } | { b: 2 }>; // { a: 1 } & { b: 2 }

3. 联合穷尽：配合 never 做编译期分支穷尽检查（见第一节 assertNever）。

八、声明文件与三方类型扩展 ​

  • d.ts 三类：全局声明（declare global）、模块声明（declare module 'x'）、环境变量 / 资源（vite-env.d.ts）。
  • 模块声明：给无类型的包补声明，declare module 'legacy-lib' { export function run(cb: (n: number) => void): void }。
  • 声明合并（Declaration Merging）：同名 interface 会自动合并，用于扩展三方类型。
ts
// 1) 给无类型 JS 包补声明
declare module 'untyped-widget' {
  export interface WidgetOptions { el: HTMLElement | string; theme?: 'light' | 'dark' }
  export default function init(opts: WidgetOptions): { destroy(): void };
}

// 2) 全局扩展（Electron preload 注入 / 环境变量）
declare global {
  interface Window { __APP_VERSION__: string; electronAPI?: { openFile(): Promise<string> } }
  interface ImportMetaEnv { readonly VITE_API_BASE: string; readonly VITE_USE_MOCK: 'true' | 'false' }
}
export {}; // 让文件成为模块，declare global 才生效

坑：declare module 只对无类型或纯 JS 的包生效，已带类型的包要用模块增强（在 import 后再 declare module）而非重写整个模块，否则会覆盖原有类型。

九、严格模式 ​

tsconfig.json 的关键开关：

jsonc
{
  "compilerOptions": {
    "strict": true,                     // 下列大多数检查的总开关
    "strictNullChecks": true,           // null/undefined 不可隐式赋值给其他类型
    "noUncheckedIndexedAccess": true,   // obj[k] / arr[i] 结果加上 undefined
    "exactOptionalPropertyTypes": true, // 可选属性不接受显式 undefined
    "useUnknownInCatchVariables": true, // catch 变量推断为 unknown
    "isolatedModules": true,            // 每文件可独立编译（Vite/esbuild 需要）
    "verbatimModuleSyntax": true,       // type 导入必须显式 import type
    "moduleResolution": "bundler"       // 现代打包器解析
  }
}

strict 是多个子开关的集合，最重要的是 strictNullChecks——没有它，null / undefined 能赋给任意类型，TS 的保护形同虚设。

noUncheckedIndexedAccess 的影响最"痛"也最真实：

ts
const cache: Record<string, number> = {};
const v = cache['a'];   // 开启后类型为 number | undefined，必须先判空
if (v !== undefined) { /* 安全使用 v */ }

对 4 年经验的双栈工程师，建议新项目直接 strict + noUncheckedIndexedAccess；老项目可按模块渐进开启（tsconfig 分层 + // @ts-expect-error 定点豁免），避免"全量报错"劝退团队。

十、契约驱动类型设计（ComponentSpec 唯一契约） ​

组件库最大的类型风险是类型漂移：React 版与 Vue 版 props 各写各的，字段名/可选性逐渐不一致，文档也对不上。解法是把组件契约抽成一份与框架无关的 ComponentSpec，双端从同一份契约推导类型。

ts
// packages/spec/src/button.ts —— 唯一契约，零框架依赖
export interface ButtonSpec {
  props: {
    type: 'primary' | 'default' | 'danger';
    size: 'small' | 'medium' | 'large';
    disabled: boolean;
    loading: boolean;
    onClick?: (e: { native: unknown }) => void | Promise<void>;
  };
  slots: { default: { text: string }; icon: { name: string } };
  events: { click: { timestamp: number } };
}
export const buttonDefaults: Partial<ButtonSpec['props']> = {
  type: 'default', size: 'medium', disabled: false, loading: false,
};
ts
import type { ButtonSpec } from '@ui-kit/spec';

type ButtonProps = ButtonSpec['props'];                // 公共 props 契约
// React：复用契约，框架特有字段单独扩展
type ReactButtonProps = ButtonProps & { className?: string; children?: React.ReactNode };
// Vue：defineProps<ButtonProps>()，事件名从 events 派生
type ButtonEmits = { (e: 'click', payload: ButtonSpec['events']['click']): void };

关键收益与约束：

  • 单一事实来源：改一次 ButtonSpec.props.type 的联合，两端 props 与文档同步更新。
  • 防止类型漂移：用 Spec['props'] 派生而非手抄，编译期即可发现两端不一致。可加类型测试（expectType / tsd）断言 React 与 Vue 的 props 互为子集。
  • 契约测试：ComponentSpec 也是 E2E（Playwright）与单测的断言依据——插槽名、事件名、默认值都从契约取。

用 expectTypeOf<ReactButtonProps>().toMatchTypeOf<ButtonProps>()（vitest / tsd）做类型测试，断言两端 props 与契约兼容。

底线：契约只描述"是什么"（数据形状），不描述"怎么做"（渲染实现），否则会把框架细节泄漏进公共包。

十一、常见坑 ​

  1. any 传染：any 参与运算后结果仍是 any，会静默吞掉后续所有类型错误。用 unknown 替代，使用前收窄；noImplicitAny 只拦"隐式"，显式 any 仍需 Code Review 兜底（可加 ESLint @typescript-eslint/no-explicit-any）。
  2. 枚举 vs 联合类型：enum 会生成运行时代码、与 isolatedModules/const enum 约束冲突，且数字枚举可被任意数字赋值（Direction.Left = 3 也通过）。优先用联合字面量或 as const 对象：
ts
enum Dir { Up, Down }        // 不推荐：生成运行时对象、数字枚举可被任意数字赋值
type Dir2 = 'up' | 'down';   // 推荐：零运行时、穷尽检查友好
const STATUS = { Idle: 'idle', Busy: 'busy' } as const; // 需要常量映射时用 as const 对象
type Status = (typeof STATUS)[keyof typeof STATUS];      // 'idle' | 'busy'
  1. 类型断言滥用：as 会关闭检查，x as Foo 与 x as unknown as Foo 都危险。优先用类型守卫（type guard） 或 satisfies（TS 4.9）。
ts
// satisfies：既校验又保留最窄推导，不改动类型
const routes = {
  home: { path: '/', title: '首页' },
  user: { path: '/user/:id', title: '用户' },
} satisfies Record<string, { path: string; title: string }>;
type RouteKey = keyof typeof routes; // 'home' | 'user'（保留字面量键）
  1. interface vs type：interface 支持声明合并、适合公共 API/扩展；type 能表达联合、条件、元组。约定：对象形状用 interface，需要联合/映射/条件时用 type。
  2. readonly 只在编译期，不产生运行时冻结（真要不可变需 Object.freeze）；exactOptionalPropertyTypes 开启后 { a?: number } 不接收 a: undefined。

面试要点 ​

  1. TS 是结构化还是名义类型？ 结构化（structural）——只看结构兼容，不看类型名，与 Java/C# 的 nominal 不同。
  2. any / unknown / never 区别？ any 关闭检查并传染；unknown 安全顶层，使用前须收窄；never 是底层，用于穷尽性检查与不可能值。
  3. 条件类型的"分布式"是什么？ 裸类型参数接收联合时逐成员求值再合并；用 [T] extends [U] 可阻止分布，Exclude/Extract 就基于此。
  4. infer 怎么用？ 在条件类型 extends 中声明待推断变量，从函数/数组/Promise 结构中提取类型（如 ReturnType）。
  5. 映射类型能做什么？ 基于 keyof 批量改写属性（增删 readonly/?），键重映射 as 可改键名或用 never 过滤键。
  6. Pick 与 Omit 怎么选？ Pick 是白名单（更安全，新增字段不泄漏），Omit 是黑名单（排除敏感字段如 password）。
  7. strictNullChecks 为什么重要？ 没有它 null/undefined 可隐式赋值给任意类型，TS 核心保护失效；它也是 strict 里最关键的子开关。
  8. noUncheckedIndexedAccess 带来什么？ 索引访问结果加上 undefined，强制判空，避免运行时 undefined 崩溃。
  9. enum 为什么建议少用？ 生成运行时代码、数字枚举可被任意数字赋值、与 isolatedModules 冲突；优先联合字面量或 as const。
  10. 组件库如何避免类型漂移？ 抽一份框架无关的 ComponentSpec 作唯一契约，双端从 Spec['props'] 派生，并用类型测试断言两端兼容。
