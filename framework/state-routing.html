状态管理与路由 ​

本页对应 JD 要求 B1（B 端中后台 RBAC/复杂表单）、B6（Redux/Zustand/Pinia/Vuex + 路由）。中后台面试里，"状态怎么分层""动态路由与权限怎么落地""为什么用 Zustand 不用 Redux"是三大高频追问。

一、状态分类：先想清楚"状态属于谁" ​

在写任何 store 之前，先按作用域与生命周期给状态分类，这能避免 80% 的过度设计：

类别例子生命周期推荐载体
组件态弹窗开关、输入框值、Tab 选中组件存活期useState / ref
全局态用户信息、主题、权限、全局 loading应用级Redux/Zustand/Pinia/Context
服务端态列表、详情、分页数据有缓存与陈旧概念TanStack Query / SWR（或 store + 缓存策略）
URL 态路由参数、query、筛选条件随浏览器历史路由（search params）

原则：能放进 URL 的不放进 store（可分享、可刷新、可回退）；能从服务端态推导的不另存（避免双份数据不一致）。

二、Redux Toolkit（RTK） ​

2.1 心智模型 ​

Redux 是单向数据流 + 不可变更新：dispatch(action) → reducer 返回新 state → 订阅者收到通知。RTK 用 createSlice 把 action 与 reducer 合并，并内置 Immer（可写式不可变更新）。

ts
// store/counter.ts
import { createSlice, createAsyncThunk, configureStore, type PayloadAction } from '@reduxjs/toolkit';

const counterSlice = createSlice({
  name: 'counter',
  initialState: { value: 0, status: 'idle' as 'idle' | 'loading' },
  reducers: {
    incremented(state) { state.value++; },            // Immer：直接改
    amountAdded(state, action: PayloadAction<number>) { state.value += action.payload; },
  },
});

export const fetchCounter = createAsyncThunk('counter/fetch', async (id: string) => {
  const res = await fetch(`/api/counter/${id}`);
  return (await res.json()) as { value: number };
});

export const { incremented, amountAdded } = counterSlice.actions;
export const selectCount = (s: { counter: { value: number } }) => s.counter.value;

export const store = configureStore({
  reducer: { counter: counterSlice.reducer },
  middleware: gdm => gdm({ serializableCheck: false }), // 自定义中间件链
});
export type RootState = ReturnType<typeof store.getState>;

2.2 关键点 ​

  • middleware：thunk 默认启用，处理异步；logger、immutableCheck、serializableCheck 为默认开发中间件。生产环境可关闭串行化检查。
  • selector：useSelector(selectCount) 精确订阅；返回新对象会每次触发重渲染，需 reselect（createSelector）做记忆化。
  • 不可变陷阱：Immer 下允许"直接改"，但不能在同一个 reducer 里既改又返回新对象（会报错）。
  • 配合 React 18 并发：Redux 订阅通过 useSyncExternalStore 实现，天然兼容并发渲染。
ts
import { useSelector, useDispatch } from 'react-redux';
const count = useSelector(selectCount);      // 只订阅 value
const dispatch = useDispatch();
dispatch(incremented());

三、Zustand：极简 store ​

Zustand 用闭包 + useSyncExternalStore 实现，无 Provider、无 action 常量、无 reducer：

ts
import { create } from 'zustand';
import { subscribeWithSelector } from 'zustand/middleware';

interface BearState {
  bears: number;
  increase: (by: number) => void;
}
export const useBearStore = create<BearState>()(
  subscribeWithSelector((set) => ({
    bears: 0,
    increase: (by) => set(s => ({ bears: s.bears + by })), // 局部更新
  })),
);

精确订阅避免无关重渲染是最关键的用法：

tsx
// 只订阅 bears，其他字段变化不触发本组件重渲染
const bears = useBearStore(s => s.bears);

// 派生多字段：必须合并为一次选择（避免返回新对象）
import { useShallow } from 'zustand/react/shallow';
const { bears, increase } = useBearStore(useShallow(s => ({ bears: s.bears, increase: s.increase })));

陷阱：useBearStore(s => ({ a: s.a, b: s.b })) 每次返回新对象 → 无限重渲染；必须 useShallow 或分成多个 selector。

与 React 18 并发：Zustand 的 set 走 useSyncExternalStore，并发下安全；但如果 store 里放"每次读都新建的快照"，同样要遵循 getSnapshot 稳定原则。

四、Pinia ​

Pinia 是 Vue 官方推荐，替代 Vuex。两种定义风格，setup 风格与组合式 API 一致：

ts
import { defineStore } from 'pinia';
import { ref, computed } from 'vue';

export const useCartStore = defineStore('cart', () => {
  const items = ref<CartItem[]>([]);
  const total = computed(() => items.value.reduce((s, i) => s + i.price * i.qty, 0));
  function add(item: CartItem) {
    const found = items.value.find(i => i.id === item.id);
    found ? (found.qty += item.qty) : items.value.push(item);
  }
  return { items, total, add };
});

要点：

  • 无需 namespaced，storeToRefs 解构保持响应式；直接改 state 合法（无 mutation 概念）。
  • 模块化天然：多个 defineStore 即多个模块，可互相 useXxx() 调用。
  • 内置 DevTools、热更新（HMR）、SSR 支持。

Vuex 到 Pinia 迁移 ​

VuexPinia
stateref/reactive
getterscomputed
mutations直接改 state（或封装成方法）
actions普通函数（可 async）
modules + namespaced多个 defineStore + storeToRefs
commit/dispatch直接调用方法

五、React Router ​

5.1 动态路由与懒加载 ​

tsx
import { createBrowserRouter, RouterProvider } from 'react-router-dom';
import { lazy, Suspense } from 'react';

const Detail = lazy(() => import('./pages/Detail'));

const router = createBrowserRouter([
  {
    path: '/',
    element: <Layout />,
    errorElement: <ErrorPage />,
    children: [
      { index: true, element: <Home /> },
      {
        path: 'users',
        loader: async () => (await fetch('/api/users')).json(), // 数据与路由同源
        element: (
          <Suspense fallback={<Skeleton />}>
            <Detail />
          </Suspense>
        ),
        children: [{ path: ':id', element: <UserDetail /> }],
      },
    ],
  },
]);

export default function App() {
  return <RouterProvider router={router} />;
}

5.2 loader / action 与守卫 ​

  • loader：进入路由前取数据，组件用 useLoaderData() 读；配合 <Await> 处理 deferred 数据。
  • action：处理表单提交，返回重定向或错误。
  • 守卫思路：在 loader 中读取权限，throw redirect('/login') 实现"未登录跳转"；或用 <Navigate> 包裹 element。
tsx
function RequireAuth({ children }: { children: React.ReactNode }) {
  const { user } = useAuth();
  const location = useLocation();
  if (!user) return <Navigate to="/login" state={{ from: location }} replace />;
  return <>{children}</>;
}

六、Vue Router ​

ts
import { createRouter, createWebHistory } from 'vue-router';

const router = createRouter({
  history: createWebHistory(),
  routes: [
    { path: '/users', component: () => import('./pages/Users.vue'), meta: { roles: ['admin'] } },
  ],
});

router.beforeEach(async (to) => {
  const auth = useAuthStore();
  if (to.meta.requiresAuth && !auth.isLogged) return { name: 'login', query: { redirect: to.fullPath } };
  if (to.meta.roles && !to.meta.roles.some(r => auth.roles.includes(r))) return { name: '403' };
});

要点：

  • 懒加载：component: () => import(...) 做路由级分包。
  • meta：携带 requiresAuth/roles/title，守卫统一读取。
  • <KeepAlive>：缓存列表页保住滚动/筛选；include 按组件名缓存。
  • 组件内守卫：onBeforeRouteLeave（阻止未保存离开）、onBeforeRouteUpdate。

七、动态权限路由与按钮级权限 ​

后端返回权限码，前端据此动态注册路由 + 渲染菜单 + 控制按钮：

ts
// 权限拉取后再 addRoute
const accessRoutes = transformRoutes(backendRoutes, componentMap);
accessRoutes.forEach(r => router.addRoute(r));
router.addRoute({ path: '/:pathMatch(.*)*', name: '404', component: NotFound });
tsx
// 按钮级：一个权限 Hook + 指令/组件
function usePermission() {
  const codes = useUserStore(s => s.permissionCodes);
  return { has: (code: string) => codes.includes(code) };
}
const { has } = usePermission();
return has('user:delete') ? <Button danger>删除</Button> : null;

按钮级另一种实现是"权限指令"：Vue 用 v-permission="'user:delete'" 指令卸载无权限元素；React 用 <Auth code="user:delete">{children}</Auth> 组件或 usePermission().has() 包裹。

关键坑：

  • 必须兜底 404：addRoute 反复追加会导致同名路由残留，登出要 removeRoute 或重建 router。
  • 菜单与路由单一数据源：由路由表推导菜单，避免两处维护不一致。
  • addRoute 后需要 next({ ...to, replace: true }) 重进一次，否则首次进入可能匹配不到新路由。

八、状态设计原则与常见反模式 ​

原则：

  1. 单一数据源：同一状态只存一份，派生用 selector/computed。
  2. 就近管理：能从组件态解决就别提升到全局。
  3. 不可变/响应式一致性：Redux 侧永远不可变更新的语义，Vue 侧可直接改但注意 ref 替换。
  4. 服务端态交给缓存层：把 loading/error/陈旧度交给 TanStack Query/SWR，而非塞进 Redux。

反模式：

  • 把服务端数据当全局态：手动管理 loading/error/缓存，代码爆炸。
  • 巨型 slice/store：一个 store 塞所有状态，改一处全应用重渲染。
  • selector 返回新对象：Redux/Zustand 里每次重渲染。
  • URL 状态塞 store：筛选/分页放 store，刷新即丢、无法分享。
  • store 之间循环依赖：Pinia store 互调需注意初始化顺序。
  • 过度 useMemo：为性能到处 memo，反而增加复杂度与内存。

面试要点 ​

  1. Redux、Zustand、Pinia 怎么选？ 答：复杂可预测、需中间件/DevTools 与团队规范用 RTK；轻量局部全局态、追求少样板用 Zustand；Vue 项目用 Pinia。
  2. Zustand 如何避免无关重渲染？ 答：用 selector 只订阅用到的字段；多字段合并须 useShallow 或拆多个 selector，避免返回新对象。
  3. RTK 的 selector 返回新对象为什么会重渲染？ 答：useSelector 默认按引用比较，需 reselect 记忆化或返回原始值。
  4. 服务端态为什么不该放进 Redux？ 答：它有缓存/陈旧/失效语义，交给 TanStack Query/SWR 更合适，避免手写 loading/error。
  5. 动态权限路由的落地步骤？ 答：拉权限 → 转换后端路由 → addRoute 注册 → 推导菜单 → 兜底 404 → 登出清理。
  6. 按钮级权限怎么做？ 答：权限码集合 + has() 判断或权限指令/组件，无权限则不渲染。
  7. Vue Router 守卫的执行顺序？ 答：全局 beforeEach → 路由独享 beforeEnter → 组件内 beforeRouteEnter/Update/Leave。
  8. keep-alive 与路由如何配合？ 答：<KeepAlive :include="names"> 按组件名缓存，用 onActivated/onDeactivated 处理刷新与清理。
  9. Vuex 迁移 Pinia 的关键差异？ 答：去 mutation、getters→computed、modules→多 defineStore、namespaced 由 storeToRefs 天然解决。
  10. URL 态与全局态怎么分工？ 答：可分享/可刷新/可回退的放 URL；跨页共享的身份/主题/权限放全局 store。
