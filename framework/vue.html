Vue 3 深入 ​

本页对应 JD 要求 A1（Vue 双栈）、B1（B 端中后台）、B6（状态管理与路由）、C7（响应式原理）。Vue 3 的响应式基于 Proxy 的重写是面试必问项，此外 <script setup> 编译产物、Props/Emits 的编译期行为、3.5 的响应式解构也是高频追问点。

一、Composition API 与 <script setup> ​

<script setup> 是编译期语法糖，编译后等价于 setup() 函数返回一个渲染函数：

vue
<script setup lang="ts">
import { ref, computed } from 'vue';
const count = ref(0);
const double = computed(() => count.value * 2);
function inc() { count.value++; }
</script>

<template>
  <button @click="inc">{{ count }} / {{ double }}</button>
</template>

编译产物（简化）：

ts
export default {
  setup() {
    const count = ref(0);
    const double = computed(() => count.value * 2);
    return { count, double, inc }; // 顶层绑定自动暴露给模板
  },
};

要点：

  • 顶层绑定自动暴露，不再需要 return；defineProps/defineEmits/defineExpose 是编译宏，无需 import。
  • <script setup> 组件默认关闭（inheritAttrs 仍可继承属性），需显式 defineExpose 才暴露实例方法。
  • 顶层 await 会让组件变成 async setup，必须配合 <Suspense> 使用。

二、响应式原理 ​

2.1 三件套：Proxy + effect + 依赖收集 ​

Vue 3 用 reactive() 把对象包成 Proxy，读取时 track 收集当前活跃 effect，写入时 trigger 派发更新：

ts
let activeEffect: Function | null = null;                 // 当前正在收集依赖的 effect
const targetMap = new WeakMap<object, Map<PropertyKey, Set<Function>>>();
function track(t: object, k: PropertyKey) {
  if (!activeEffect) return;
  let m = targetMap.get(t);
  if (!m) targetMap.set(t, (m = new Map()));
  let deps = m.get(k);
  if (!deps) m.set(k, (deps = new Set()));
  deps.add(activeEffect);                                 // 记录：该属性依赖了该 effect
}
function trigger(t: object, k: PropertyKey) {
  targetMap.get(t)?.get(k)?.forEach(fn => schedule(fn));  // schedule 决定同步/批量刷新
}
function reactive<T extends object>(obj: T): T {
  return new Proxy(obj, {
    get(t, k, r) { track(t, k); return Reflect.get(t, k, r); },
    set(t, k, v, r) { const ok = Reflect.set(t, k, v, r); trigger(t, k); return ok; },
  });
}

2.2 与 Vue 2 Object.defineProperty 的对比 ​

维度Vue 2 definePropertyVue 3 Proxy
拦截范围只能劫持已声明的属性整个对象（含新增/删除属性）
数组需重写 7 个变更方法 + $set原生拦截索引与 length
嵌套初始化时递归遍历，成本高惰性代理，访问到才递归
Map/Set/WeakMap不支持支持
性能大对象初始化慢按需响应，内存更省

局限（Vue 2）：obj.newKey = 1 不触发更新需 Vue.set；arr[0] = x 无响应；无法监听 delete。

2.3 ref / reactive / shallowRef / toRefs / computed 选型 ​

API适用注意
ref基本类型、需整体替换的对象模板中自动解包（.value 不用写）；ref(obj) 内部用 reactive
reactive对象/数组等复合结构解构会丢失响应式，整体替换（state = {}）会断开
shallowRef只关心整体替换的大对象不深追踪，性能好，适合大列表/第三方实例
toRefs解构 reactive 保持响应返回一组 ref
toRef取单个属性为 ref可用于 props 解构
computed派生值，带缓存依赖不变不重算；computed 内勿做副作用
watch明确依赖的副作用默认惰性；可 { immediate, deep, flush }
watchEffect自动收集依赖立即执行；依赖不清时容易过度触发
ts
import { reactive, toRefs, shallowRef } from 'vue';
const state = reactive({ count: 0, name: 'a' });
const { count, name } = toRefs(state); // 解构仍响应
const big = shallowRef<any[]>([]);
big.value = await fetchList(); // 整体替换触发，内部字段改动不触发

computed 与 watch 的关键区别：computed 是有缓存的派生值（只读，可写需 get/set），watch 是副作用（不返回值，可用于发请求/写日志）。

2.4 响应式解构与 Vue 3.5 的 props 解构快照陷阱 ​

Vue 3.5 起，reactive 对象解构、defineProps 解构会保持响应式——编译器把 const { count } = defineProps<{ count?: number }>() 重写为对 props.count 的属性访问，因此可在 <script setup> 顶部直接解构，无需 toRefs。但要注意"快照"语义：

陷阱：在 3.5 之前，const { count } = props 是一次性快照，后续 props.count 变化不会更新页面；必须用 toRef(props, 'count')。若项目无法升级到 3.5，务必用 toRefs/toRef。

另一陷阱：watch 监听解构后的值需用 () => count（getter 形式），不能直接 watch(count, ...)，因为解构变量不是 ref（3.5 中被编译为 getter，直接 watch(count) 在部分场景仍失败，稳妥做法是 getter）。

三、生命周期与组合式函数 ​

<script setup> 中生命周期钩子以 onXxx 形式调用：onMounted、onUpdated、onUnmounted、onBeforeUnmount、onActivated/onDeactivated（配合 keep-alive）、onErrorCaptured。

组合式函数（composable）是把"有状态的逻辑"抽成 useXxx：

ts
// useCounter.ts
import { ref, onUnmounted } from 'vue';
export function useInterval(cb: () => void, ms: number) {
  const id = ref<number | undefined>();
  onMounted(() => { id.value = window.setInterval(cb, ms); });
  onUnmounted(() => { if (id.value) clearInterval(id.value); });
  return { stop: () => id.value && clearInterval(id.value) };
}

要点：composable 必须在 setup 同步阶段调用，才能正确注入到当前组件实例的生命周期队列。

四、模板编译与虚拟 DOM diff ​

Vue 的模板不是字符串运行时解析（除运行时编译版），而是编译期转成渲染函数，并做静态分析优化：

  • 静态提升（hoistStatic）：静态节点提取到 render 外，复用 VNode。
  • 补丁标记（PatchFlag）：动态节点携带标记（如 TEXT、CLASS、PROPS），diff 时只比对变化部分，跳过静态结构。
  • Block Tree：动态节点收集成 block，diff 只遍历动态子树，把 diff 复杂度从"全树"降到"动态节点数"。
  • 缓存事件：@click="fn" 编译为内联函数并缓存，避免每次渲染重建。
ts
// 模板：<div>静态<span>{{ msg }}</span></div>
// 编译产物（简化）
const _hoisted_1 = createElementVNode('div', null, '静态');
function render() {
  return (openBlock(), createElementBlock('div', null, [
    _hoisted_1,
    createElementVNode('span', null, toDisplayString(msg.value), 1 /* TEXT */),
  ]));
}

对比 React：React 每次渲染都执行 createElement 重建整棵 VNode 树（编译器优化后可减少），Vue 靠 PatchFlag 做靶向 diff；key 在两者中都用于同层身份识别。

五、Props 与 Emits ​

5.1 defineProps 与 withDefaults ​

vue
<script setup lang="ts">
interface Props {
  title: string;
  count?: number;
  items?: string[];
  onChange?: (v: string) => void; // 函数类型 prop 也是 prop
}
// withDefaults 的默认值在编译期被内联到 props 选项
const props = withDefaults(defineProps<Props>(), {
  count: 0,
  items: () => [],
});
</script>

编译产物中，withDefaults 的默认值被内联为 props 选项的 default（如 count: { type: Number, default: 0 }），required 由类型推断。 常见坑：引用类型默认值必须用工厂函数（items: () => []），否则所有实例共享同一个数组。

5.2 defineEmits ​

支持两种写法，推荐元组形式（3.3+ 更简洁且类型安全）：

vue
<script setup lang="ts">
// 元组形式
const emit = defineEmits<{
  change: [value: string];
  submit: [id: number, ok: boolean];
}>();

// 或对象形式（类型 + 校验）
const emit2 = defineEmits<{
  (e: 'change', value: string): void;
}>();

emit('change', 'hello');
</script>

事件在模板中用 @change="onChange" 监听；React 里对应 onChange 回调 prop。

5.3 defineProps 完整类型回调被编译进 props 的坑 ​

若 interface Props 中包含 onXxx 形式的回调（如 onChange?: () => void），Vue 编译器会把整个类型（包括回调）作为 props 声明，而 onChange 又恰是 Vue 的事件监听约定名（等价于 @change），于是产生双重语义：

  • 父组件写 @change="fn" 会被当成 emit 监听；
  • 同时 onChange 又被声明成 prop，值可能被 props 覆盖。

解决：不要把回调定义成 onXxx 命名放进 Props 类型，改用 change?: (v: string) => void 或直接用 defineEmits 声明事件；若必须传回调函数 prop，命名避开 on 前缀。

六、插槽：具名/作用域与 React 映射 ​

vue
<!-- Child.vue -->
<template>
  <header><slot name="header" :user="user" /></header>
  <main><slot :item="item" /></main>
</template>
vue
<!-- Parent.vue -->
<Child>
  <template #header="{ user }">{{ user.name }}</template>
  <template #default="{ item }">{{ item.title }}</template>

这在双栈同构组件库中是可机器化对齐的契约（见 双栈对比与同构组件库）。

七、性能优化 ​

  • v-memo：只在依赖数组变化时更新子树，等价于"局部 memo"，适合长列表行。
  • v-once：只渲染一次，永不更新。
  • shallowRef/shallowReactive：数据只需整体替换时避免深追踪。
  • 精确依赖：computed/watch 只依赖必要字段，避免 deep: true 全量遍历大对象。
  • v-if vs v-show：频繁切换用 v-show，条件少变用 v-if。
  • 大列表虚拟滚动：vue-virtual-scroller。
  • <KeepAlive>：缓存组件，配合 onActivated/onDeactivated。
vue
<template>
  <div v-for="item in list" :key="item.id" v-memo="[item.id, item.selected]">
    {{ item.name }} - {{ item.selected }}
  </div>
</template>

八、Teleport 与 Transition ​

  • <Teleport to="body"> 把子节点渲染到 DOM 其他位置（如全局弹窗/抽屉），逻辑与 DOM 位置解耦，规避 overflow: hidden、z-index 层叠上下文问题。
  • <Transition> / <TransitionGroup> 提供进入/离开过渡，靠 CSS 类名（v-enter-from 等）或 JS 钩子（@enter/@leave）驱动。
vue
<Teleport to="body">
  <Transition name="fade">
    <div v-if="open" class="modal">...</div>
  </Transition>
</Teleport>

React 中对应 createPortal 与手写过渡逻辑（或 framer-motion）。

九、Vue Router 与 Pinia 集成要点 ​

  • Vue Router：创建时用 createRouter + createWebHistory；路由记录支持 meta、props、beforeEnter；全局守卫 router.beforeEach，组件内 onBeforeRouteLeave（需 <script setup> 中用组合式函数）。
  • 动态路由：router.addRoute() 在权限校验后追加路由，退出登录用 router.removeRoute(name) 清理。
  • Pinia：defineStore(id, setupFn | options)，setup 形式与组合式 API 一致；需在 app.use(createPinia()) 后使用。Pinia 内部基于 Vue 的 reactive/ref，因此天然享受响应式与 DevTools。
ts
import { defineStore } from 'pinia';
import { ref, computed } from 'vue';

export const useUserStore = defineStore('user', () => {
  const token = ref('');
  const roles = ref<string[]>([]);
  const isLogged = computed(() => !!token.value);
  async function login(payload: { u: string; p: string }) {
    const res = await api.login(payload);
    token.value = res.token;
    roles.value = res.roles;
  }
  return { token, roles, isLogged, login };
});

Vuex 到 Pinia 迁移：去掉 mutations（直接改 state 或 action 里改）、actions 语义统一、modules 改为多 defineStore、getters 改为 computed，无需 namespaced。

面试要点 ​

  1. Vue 3 响应式相比 Vue 2 的核心改进？ 答：Proxy 替代 defineProperty，可监听新增/删除属性、数组索引、Map/Set，且惰性依赖收集，初始化更快。
  2. ref 与 reactive 的区别与选型？ 答：ref 适配基本类型与整体替换，模板自动解包；reactive 适配复合结构但解构/替换会断链。需要整体替换用 ref。
  3. computed 与 watch / watchEffect 的区别？ 答：computed 是有缓存的派生值，watch 是明确依赖的副作用且惰性，watchEffect 自动收集依赖并立即执行。
  4. 为什么 reactive 解构会丢响应式，Vue 3.5 如何解决？ 答：解构取值即快照；3.5 通过编译器把解构重写为属性访问，保持响应，旧版本用 toRefs。
  5. <script setup> 编译后是什么？ 答：编译为 setup() 返回渲染函数，顶层绑定自动暴露，defineXxx 为编译宏。
  6. Vue 的 PatchFlag / Block Tree 解决什么？ 答：编译期标记动态节点，diff 只遍历动态子树，把全树 diff 降为动态节点数。
  7. defineProps 里含 onChange 回调为什么会出问题？ 答：onXxx 是事件约定名，会被编译器当作 props 与事件双语义处理，建议改命名或改用 defineEmits。
  8. 具名/作用域插槽如何映射到 React？ 答：具名插槽 = renderXxx 回调 prop，作用域插槽 = 接收参数的 render prop，默认插槽 = children。
  9. withDefaults 的默认值在编译期发生什么？ 答：被内联进组件 props 选项的 default，引用类型必须写工厂函数。
  10. Teleport / KeepAlive 各解决什么？ 答：Teleport 解耦逻辑与 DOM 位置（弹窗挂 body 规避层叠与裁剪）；KeepAlive 缓存组件实例，配合 onActivated/onDeactivated。
