JavaScript 高频题 ​

本页汇总一面淘汰赛中最高频的 JavaScript 题目，统一采用 [问法] → [要点] → [深度补充] 的结构。每题要点控制在能"30 秒讲清"，深度补充用于体现区分度。对应 JD 要求 A2（JS ES6+ 基础）+ C 级"数据结构与算法 / 响应式原理"（3 份 JD）。

配合 JavaScript 核心机制 深读机制，本页侧重"面试怎么答"。

一、变量、作用域与提升 ​

Q1. var / let / const 的区别？ ​

要点：var 是函数作用域、提升后初始化为 undefined、可重复声明；let/const 是块级作用域、存在暂时性死区（TDZ）、不可重复声明；const 禁止重新赋值，但对象内部属性仍可变（浅层不可变）。

深度补充：TDZ 的本质是"变量已创建但未初始化"，访问抛 ReferenceError；同一作用域内 let 声明前访问报错，之后正常。const 的不可变只是绑定不可变，用 Object.freeze 才冻结属性（且是浅冻结）。

Q2. 什么是变量提升与暂时性死区？ ​

问法：console.log(a); var a = 1; 输出什么？console.log(b); let b = 1; 呢？

要点：提升发生在执行上下文创建阶段——var 提升到函数顶部并置 undefined；函数声明整体提升（可提前调用）；let/const 提升但不初始化，进入 TDZ，访问报 ReferenceError。所以第一段输出 undefined，第二段抛错。

深度补充：函数表达式不提升（var bar = function () {}），提前调用是 TypeError（bar 是 undefined，不是函数）。TDZ 是块级的，块内 let 声明前访问都会报错，即便外层有同名变量。

Q3. 什么是词法作用域与作用域链？ ​

要点：作用域在函数定义时根据代码位置确定（词法/静态作用域），与调用位置无关。访问变量时沿作用域链从内向外查找，找到即停。

深度补充：with / eval 会破坏词法作用域、影响 V8 优化，应禁用。闭包之所以"记住"外层变量，正是因为它保留了定义时的词法环境引用。

二、this 与对象 ​

Q4. this 的绑定规则与优先级？ ​

要点：优先级从高到低为 new > 显式（call/apply/bind）> 隐式（对象方法）> 默认。默认绑定在非严格模式是 globalThis，严格模式是 undefined；箭头函数不绑定 this，取定义时外层。

深度补充：bind 返回新函数且 this 永久固定，但用 new 调用该绑定函数时，this 会被新建对象覆盖（bind 失效）。"隐式丢失"指方法被单独取出调用（const f = obj.method; f()），this 不再指向 obj。

Q5. 箭头函数与普通函数的区别？ ​

要点：箭头函数无自己的 this（取外层词法）、无 arguments（用 rest 参数替代）、不能作构造函数（无 prototype、new 报错）、无 new.target。

深度补充：箭头函数适合"回调需要外层 this"的场景（如类方法里的事件回调，免去 bind(this)）；不适合需要动态 this 的场合。与 var 无关，箭头函数不提升，只能先定义后使用。

Q6. call / apply / bind 的区别？ ​

要点：三者都能显式指定 this。call 逐个传参，apply 传数组，两者立即执行；bind 返回新函数（不立即执行），参数可预绑定（偏函数）。

深度补充：手写 bind 要处理 new 调用（此时 this 应为新对象）、保留原型链。Function.prototype.bind 的 this 一旦绑定不可再改。

Q7. 手写 call / apply / bind。 ​

要点：核心是"把函数临时挂到 thisArg 上再调用"，用 Symbol 生成唯一 key 避免覆盖。

ts
Function.prototype.myCall = function (ctx: any, ...args: unknown[]) {
  ctx = ctx ?? globalThis;
  const key = Symbol('fn');
  ctx[key] = this;
  const res = ctx[key](...args);
  delete ctx[key];
  return res;
};
// myApply 同上，只是把 args 改为数组；myBind 返回闭包并支持 new
Function.prototype.myBind = function (ctx: any, ...bound: unknown[]) {
  const fn = this;
  function boundFn(this: any, ...rest: unknown[]) {
    const isNew = this instanceof boundFn;               // new 调用时 this 被覆盖
    return fn.apply(isNew ? this : ctx, [...bound, ...rest]);
  }
  boundFn.prototype = Object.create(fn.prototype);        // 保留原型链
  return boundFn;
};

深度补充：真实 bind 还要校验 this 是函数（否则 TypeError），并让绑定函数 length 准确（可用 Object.defineProperty 修正）。

三、闭包与内存 ​

Q8. 什么是闭包？会内存泄漏吗？ ​

要点：闭包 = 函数 + 它能访问的外层词法环境；只要内层函数被外部引用，捕获的变量就不会被回收。闭包本身不泄漏，泄漏是"不再需要却仍可达"。

深度补充：典型泄漏源是——事件监听捕获大对象却从不 removeEventListener、定时器从不 clearInterval、闭包长期持有大数组。排查用 DevTools Memory 面板堆快照对比。WeakMap 的键是弱引用，适合做"可被 GC 的关联数据"。

Q9. 循环里用 var 和 let 输出有什么不同？ ​

要点：for (var i = 0; i < 3; i++) setTimeout(() => console.log(i)) 输出 3 3 3，因为 var 共享同一变量；改用 let 输出 0 1 2，因为块级作用域每轮创建独立绑定。

深度补充：另一种修复是 IIFE 传参固定值：(function (j) { setTimeout(() => console.log(j)); })(i)。核心是"闭包捕获的是变量而非值"。

四、原型与继承 ​

Q10. 原型、原型链是什么？ ​

要点：每个对象有 [[Prototype]]（浏览器里是 __proto__），函数独有 prototype 指向原型对象。读取属性时沿 对象 → 构造函数.prototype → Object.prototype → null 逐层查找，找到即停，否则 undefined。

深度补充：写属性不沿链查找（obj.x = 1 只在自身创建）；in 查整条链、Object.hasOwn 只查自身；instanceof 检查构造函数的 prototype 是否在链上。class 是原型链语法糖，但方法不可枚举且声明有 TDZ。

Q11. new 操作符做了什么？手写实现。 ​

要点：四步——创建空对象；其 [[Prototype]] 指向构造函数 prototype；以它为 this 执行构造函数；若构造函数返回对象则覆盖，否则返回该对象。

ts
function myNew(Ctor: Function, ...args: unknown[]) {
  const obj = Object.create(Ctor.prototype);     // 1+2：建对象并挂原型
  const res = Ctor.apply(obj, args);              // 3：以 obj 为 this 执行
  return typeof res === 'object' && res !== null ? res : obj; // 4：返回对象则覆盖
}

深度补充：Object.create(null) 创建无原型对象，不继承 Object.prototype，常用作纯净字典（但无 hasOwnProperty）。__proto__ 是访问器，Object.getPrototypeOf 更规范。

五、异步与事件循环 ​

Q12. 解释浏览器事件循环（宏任务/微任务）。 ​

要点：宏任务含 script 整体、setTimeout、I/O、UI 渲染；微任务含 Promise.then、queueMicrotask、MutationObserver。每执行完一个宏任务就清空整个微任务队列，再渲染，再取下一个宏任务。

js
console.log('1');
setTimeout(() => console.log('2'), 0);          // 宏
Promise.resolve().then(() => console.log('3')); // 微
console.log('5');
// 输出：1 5 3 2

深度补充：requestAnimationFrame 在下一次重绘前执行（约 60fps），动画用它而非 setTimeout 以对齐刷新。Node 是分阶段事件循环，process.nextTick 优先于 Promise，setImmediate 与 setTimeout(0) 顺序受 I/O 影响、不稳定。

Q13. setTimeout(fn, 0) 真的立即执行吗？ ​

要点：不是。它至少延迟到下一个宏任务阶段，且在所有微任务之后执行。浏览器还有 4ms 最小间隔（嵌套超过 5 层时）。

深度补充：requestIdleCallback 在帧空闲时执行，适合低优先级任务。要"尽快但不打断当前同步代码"，用 queueMicrotask 或 Promise.resolve().then。

Q14. Promise 与 async/await 的关系？ ​

要点：async 函数总返回 Promise；await 等价 .then，把后续代码排入微任务。async/await 是 Promise 的语法糖，写法同步但本质异步。

深度补充：await 的 rejection 可用 try/catch 捕获；未 await 的 Promise rejection 会变成 unhandled rejection。Promise.allSettled 各自带 status、不因一个失败全崩，优于 Promise.all（一败全败）。

Q15. 手写 Promise。 ​

要点：状态单向 pending → fulfilled | rejected；then 返回新 Promise 支持链式；回调必须异步执行（queueMicrotask）。

ts
class MyPromise<T> {
  state: 'pending' | 'fulfilled' | 'rejected' = 'pending';
  value?: T; cbs: Array<() => void> = [];
  constructor(executor: (res: (v: T) => void, rej: (r: unknown) => void) => void) {
    const settle = (st: typeof this.state) => (v: unknown) => {
      if (this.state !== 'pending') return;            // 状态一旦确定不再变
      this.state = st; this.value = v as T;
      this.cbs.forEach((cb) => queueMicrotask(cb));
    };
    try { executor(settle('fulfilled'), settle('rejected')); }
    catch (e) { settle('rejected')(e); }               // 同步抛错 → reject
  }
  then<U>(onF?: (v: T) => U, onR?: (r: unknown) => U): MyPromise<U> {
    return new MyPromise<U>((resolve, reject) => {
      const run = () => {
        try { resolve(this.state === 'fulfilled' ? onF?.(this.value as T) as U
              : (onR ? onR(this.value) : this.value) as U); }
        catch (e) { reject(e); }
      };
      this.state === 'pending' ? this.cbs.push(run) : queueMicrotask(run);
    });
  }
}

深度补充：完整实现还要处理——resolve 传入 Promise 时递归展开、then 返回自身致死循环（抛 TypeError）、onFulfilled 非函数时透传值。真实的 Promise 是 Promise/A+ 规范实现，需通过其 872 个测试用例。

Q16. 实现 Promise 并发控制（限制并发数）。 ​

要点：用共享游标 + 若干 worker 抢占任务，Promise.all 等全部 worker 结束。

ts
async function pool<T>(tasks: Array<() => Promise<T>>, limit = 4): Promise<T[]> {
  const results: T[] = new Array(tasks.length);
  let cursor = 0;
  async function worker() {
    while (cursor < tasks.length) {
      const i = cursor++;                     // 抢占式取任务
      results[i] = await tasks[i]();
    }
  }
  await Promise.all(Array.from({ length: Math.min(limit, tasks.length) }, worker));
  return results;
}

深度补充：结果按索引写入以保证顺序（不能用 push）。同类还有"请求重试（指数退避）""超时中断（AbortController）"。

六、手写题 ​

Q17. 手写防抖与节流。 ​

要点：防抖 = 停止触发 N ms 后执行一次；节流 = 固定间隔最多执行一次。

ts
function debounce<F extends (...a: any[]) => void>(fn: F, wait = 300) {
  let timer: ReturnType<typeof setTimeout> | null = null;
  return (...args: Parameters<F>) => {
    if (timer) clearTimeout(timer);
    timer = setTimeout(() => { timer = null; fn(...args); }, wait);
  };
}
function throttle<F extends (...a: any[]) => void>(fn: F, interval = 200) {
  let last = 0; let timer: ReturnType<typeof setTimeout> | null = null;
  return (...args: Parameters<F>) => {
    const remain = interval - (Date.now() - last);
    if (remain <= 0) { last = Date.now(); fn(...args); }        // 立即执行
    else if (!timer) timer = setTimeout(() => {                 // 尾部补发
      last = Date.now(); timer = null; fn(...args);
    }, remain);
  };
}

深度补充：React 中 useCallback 包裹防抖却未处理内部 fn，会因闭包捕获旧 state 而"永远看到旧值"——需用 useRef 保存最新回调。

Q18. 手写深拷贝。 ​

要点：JSON 法简单但丢失 Date/RegExp/Map/undefined/函数且循环引用报错；手写版用 WeakMap 处理循环引用并对特殊类型分支；structuredClone 原生支持循环引用与 Date/Map/Set，但克隆函数/Symbol/DOM 抛 DataCloneError。

ts
function deepClone<T>(v: T, seen = new WeakMap<object, unknown>()): T {
  if (v === null || typeof v !== 'object') return v;
  if (seen.has(v as object)) return seen.get(v as object) as T;   // 循环引用
  if (v instanceof Date) return new Date(v.getTime()) as T;
  if (v instanceof RegExp) return new RegExp(v.source, v.flags) as T;
  const out: any = Array.isArray(v) ? [] : Object.create(Object.getPrototypeOf(v));
  seen.set(v as object, out);
  for (const k of Reflect.ownKeys(v as object)) out[k] = deepClone((v as any)[k], seen);
  return out;
}

深度补充：用 WeakMap 而非 Map（后者强引用拷贝源、阻止 GC）；structuredClone 会丢失自定义类实例的方法。Reflect.ownKeys 能取到 symbol 键（Object.keys 取不到）。

七、其他核心机制 ​

Q19. 隐式类型转换规则？ ​

要点：+ 只要有字符串就转字符串拼接；算术运算符（- * /）转数字；== 会做类型转换（null == undefined 为 true，NaN 不等于任何值）。推荐一律用 ===。

深度补充：[] == false 为 true（都转数字 0）；{} + [] 是 "[object Object]"（{} 被当作块语句）而 [] + {} 是 "[object Object]"。转换顺序：ToPrimitive（先 valueOf 后 toString）。Number('') 是 0，Number(null) 是 0，Number(undefined) 是 NaN。

Q20. Proxy 与 Reflect 的作用？ ​

要点：Proxy 拦截对象操作（get/set/has/delete/ownKeys 等 13 种陷阱）；Reflect 提供这些操作的默认行为。Vue3 的响应式正是 Proxy + Reflect。

深度补充：配 Reflect 的原因是它把 receiver 传给默认行为，保证原型链上 getter/setter 里的 this 指向代理而非原始对象。Proxy 相比 defineProperty 的优势：能拦截新增/删除/in/ownKeys，且惰性代理。

Q21. 垃圾回收机制与常见内存泄漏。 ​

要点：V8 分代回收——新生代用 Scavenge（Cheney 复制算法），老生代用标记-清除 + 标记-压缩。可达性用标记法（从 GC Roots 可达即存活），因此循环引用能被回收（不是引用计数）。

深度补充：常见泄漏：未移除的监听、未清理的定时器、被 JS 变量持有的游离 DOM、闭包长期持有大对象。排查用 DevTools Memory 面板对比堆快照，看 "Detached DOM tree"；WeakMap/WeakRef 可解。

Q22. CommonJS 与 ES Module 的区别？ ​

要点：CJS——运行时加载、require/module.exports、值拷贝、this 指向 module.exports；ESM——编译时确定依赖（静态分析）、import/export、值引用（活绑定）、模块顶级 this 为 undefined。

深度补充：CJS 可动态 require，ESM 的 import 必须顶层静态（import() 动态导入返回 Promise）。ESM 默认严格模式，且支持 tree-shaking（因为依赖静态）。Node 中 ESM 需 .mjs 或 "type": "module"。

八、常见输出结果题 ​

Q23. this 输出题。 ​

js
const obj = {
  name: 'obj',
  getName() { return this.name; },
  getNameArrow: () => this.name,          // 箭头函数取外层（模块顶层 this 为 undefined）
};
console.log(obj.getName());        // 'obj'   隐式绑定
const f = obj.getName;
console.log(f());                  // undefined 隐式丢失（严格模式）
console.log(obj.getNameArrow());   // undefined 箭头不绑定 this

要点：先判断调用形式（obj.f() 还是裸 f()），再判断函数类型（普通/箭头）。"隐式丢失"是最高频陷阱。

Q24. 异步顺序输出题。 ​

js
async function async1() {
  console.log('1');
  await async2();
  console.log('2');           // await 后的代码进微任务
}
async function async2() { console.log('3'); }
console.log('4');
setTimeout(() => console.log('5'));           // 宏
async1();
new Promise((r) => { console.log('6'); r(); }).then(() => console.log('7')); // 微
console.log('8');
// 输出：4 1 3 6 8 2 7 5

要点：同步代码先跑完（4/1/3/6/8），再按入队顺序清空微任务（2 先于 7，因为 async1 的 await 在 async2 调用后立即让出），最后宏任务（5）。

深度补充：new Promise 的 executor 是同步执行的，所以 6 在 8 前；await 把后续代码排入微任务，async1 里 await async2() 相当于等待一个已 resolve 的 Promise，其 .then 回调排在 new Promise(...).then 之前。

Q25. 闭包输出题。 ​

function create() { let n = 0; return { inc: () => ++n, get: () => n }; } 后各自 inc：c1.inc(); c1.inc(); c2.inc(); 则 c1.get() 是 2、c2.get() 是 1。要点：每次调用 create() 创建独立的词法环境，c1 与 c2 的 n 互不影响。

面试要点 ​

  1. 提升与 TDZ 的本质？ 执行上下文创建阶段——var 提升为 undefined，let/const 提升但不初始化进入 TDZ。
  2. this 优先级？ new > call/apply/bind > 隐式 > 默认；箭头函数取外层词法。
  3. 闭包会泄漏吗？ 本身不会，是"长期可达却不再需要"的引用导致；WeakMap、及时解绑可解。
  4. 宏微任务顺序？ 每个宏任务后清空全部微任务再渲染；setTimeout(0) 在微任务之后。
  5. 手写 Promise 的关键？ 状态机单向不可逆 + 回调异步执行 + then 返回新 Promise。
  6. 深拷贝首选？ structuredClone；手写版用 WeakMap 处理循环引用并对 Date/RegExp 分支。
  7. Proxy 为什么配 Reflect？ Reflect 提供带 receiver 的默认行为，保证代理下 this 指向正确。
  8. 输出题的解题步骤？ 先区分同步/宏/微，再按执行阶段与入队顺序排列。
