按岗位差异化准备 ​

本页把 10 份深圳前端 JD（#1-#10）逐一拆成"岗位画像 + 面试官重点问什么 + 短板应对话术 + 投递前必补清单 + 一句打招呼语"，用于投递前的定向补强。编号、投递排序与补强清单均与 能力地图、备战路线 保持一致。

使用方式：投递某个岗位前，只读该岗位一节；"必补清单"里的链接是站在面试官视角的最短板，务必点开预习。

二、第一梯队（优先投递） ​

#9 今天国际 · AI 协作 + 组件库 + 前端架构（匹配度约 96%） ​

  • 岗位画像：已上市公司，500-999 人；要 AI 协作能力 + 组件库 + 前端架构，AI 协作是硬性第 2 条。
  • 面试官重点问：AI 辅助研发流程、组件库设计、跨域表述、架构分层与质量门禁。
  • 最大短板与话术：组件库有实战，但"架构方法论"易讲虚。话术："我把架构落到可执行的约束上——用 ESLint 规则守住依赖方向、用质量门禁卡住 AI 产出，而不是只谈分层名词。"
  • 投递前必补：AI 辅助研发方法论 + 跨域速查。
  • 打招呼语："我做过双栈同构组件库并对外交付，也用 AI 工具链 + 质量门禁做研发提效，正好契合贵司对 AI 协作与前端架构的要求。"

#7 润信智能 · 智慧能源 + 数据大屏 + 数字孪生（匹配度约 92% · 16-20K·14薪） ​

  • 岗位画像：100-499 人未融资；智慧能源方向，数据大屏 + 数字孪生。
  • 面试官重点问：大屏适配方案、大数据量渲染性能、ECharts/DataV/Cesium 概念、WebGL/三维基础。
  • 最大短板与话术：数字孪生/三维是短板。话术："三维我项目里深度用得不深，但我知道数字孪生是三维场景 + 实时数据驱动的映射，底层是 WebGL/Cesium；渲染侧的性能思路（降采样、按需渲染、实例化）我在大屏里用过。"
  • 投递前必补：DataV 组件列表 + Cesium 入门 + 大屏适配。
  • 打招呼语："我做过数据大屏与大数据量渲染优化，也系统了解过 DataV/Cesium 与数字孪生的实现路径。"

#8 鹏开信息 · IM + Electron + 音视频 + Hybrid（匹配度约 93%） ​

  • 岗位画像：500-999 人；IM + Electron 桌面端 + 音视频 + Hybrid。
  • 面试官重点问：IM 消息流与离线补偿、Electron IPC 与打包发布、WebRTC 概念、Hybrid/JSBridge 联调。
  • 最大短板与话术：IM 是 P0 缺口、企微是 D 级盲区。话术："IM 的消息不重不漏我很清楚——单调序号 + 客户端幂等去重 + 重连补偿拉取；企微 JS-SDK 我了解免登三跳的流程，细节会快速对齐。"
  • 投递前必补：IM 技术链 + 企微概念 + Electron 深度。
  • 打招呼语："我做过 Electron 桌面端与 Hybrid 联调，也理解 IM 的离线消息补偿与 WebRTC 音视频链路。"

#2 四方精创 · 算力调度 + 数据标注 + 中后台（匹配度约 88%） ​

  • 岗位画像：1000-9999 人已上市；算力调度 + 数据标注 + 门户 + 中后台。
  • 面试官重点问：中后台复杂表单/表格、抗量级渲染、AntV 图表、Node.js/BFF、部署概念。
  • 最大短板与话术：AntV 生态与 Docker/K8s 是短板。话术："AntV 的 G2/G6/X6 我了解定位——分别是统计图表、图编辑、流程图；容器化我理解 CI 构建镜像 → 部署到 K8s 的基本链路。"
  • 投递前必补：AntV + Docker/K8s 概念。
  • 打招呼语："我熟悉 B 端中后台的复杂表单/表格与权限体系，也掌握 AntV 图表与前端工程化部署。"

三、第二梯队（补 1-2 项技术后投递） ​

#1 星河视控 · React 管理后台 + 监控/IoT + SDK 交付（匹配度约 90%） ​

  • 岗位画像：0-20 人智能硬件；React 管理后台 + 监控/IoT + SDK 交付，团队小、要求全栈感强。
  • 面试官重点问：React 管理后台经验、实时数据（WebSocket）、WebRTC/音视频架构、SDK 交付。
  • 最大短板与话术：WebRTC 是 P1 缺口。话术："WebRTC 我理解核心链路——getUserMedia 采集 → RTCPeerConnection 建连（信令交换 SDP/ICE）→ 媒体流传输；架构上会用 SFU/MCU 做多人。"
  • 投递前必补：WebRTC + 音视频架构。
  • 打招呼语："我有 React 管理后台 + IoT 跨端 + SDK 交付经验，也了解 WebRTC 音视频与实时监控链路。"

#4 中科创达 · 前端全栈 + IoT 操作系统（匹配度约 80% · 12-20K） ​

  • 岗位画像：10000+ 人已上市；前端全栈 + IoT 操作系统。
  • 面试官重点问：Node.js/服务端、接口设计与 BFF、IoT 设备侧交互、跨端。
  • 最大短板与话术：Node.js 深度是 P2 缺口。话术："我主力在前端，Node 侧做过 BFF 聚合接口与脚本工具；给我一周能把 Nest.js 最小 CRUD 落地。"
  • 投递前必补：Nest.js 最小 CRUD Demo + Node.js。
  • 打招呼语："我前端全栈能力较均衡，熟悉 IoT 跨端交互，也能用 Node 做 BFF 与工具脚本。"

#10 欣农互联 · AI 产品（问答/Agent/RAG）+ RN 跨端（匹配度约 78% · 18-25K） ​

  • 岗位画像：100-499 人未融资；AI 产品 + React Native 跨端，薪资高。
  • 面试官重点问：AI 产品界面（流式/Agent/RAG）、SSE/流式渲染、React Native 独立交付、跨端性能。
  • 最大短板与话术：RN 深度是短板。话术："RN 我理解是用 React 写原生，与 Web 的差异在布局（Flex 默认）、样式（无级联）、原生模块桥接；性能瓶颈靠 FlatList 虚拟化与 InteractionManager。"
  • 投递前必补：流式渲染 + React Native。
  • 打招呼语："我做过 AI 产品界面与流式渲染，也了解 RN 跨端与原生桥接，能快速承接 AI 产品前端。"

#6 鹏业软件 · 多端混合开发（PC/Android/iOS）+ 信创（匹配度约 86% · 11-21K） ​

  • 岗位画像：100-499 人；多端混合开发 + 信创国产化。
  • 面试官重点问：Hybrid/JSBridge、多端打包、浏览器/多端兼容、信创环境适配、公众号网页。
  • 最大短板与话术：信创与公众号是 D 级盲区。话术："信创环境的差异主要在内核与浏览器版本（如国产 OS + 特定浏览器），我会用特性检测 + polyfill + 降级方案兼顾；公众号授权我了解网页授权的基本流程。"
  • 投递前必补：公众号/信创概念 + 多端打包。
  • 打招呼语："我做过 Hybrid 与多端打包，也了解信创环境与公众号网页授权的适配要点。"

四、保底与谨慎 ​

#5 掌上智珠 · 标准中小团队前端（Vue 优先）（匹配度约 95% · 10-15K） ​

  • 岗位画像：20-99 人未融资；标准中小团队，Vue 优先，无短板但薪资偏低。
  • 面试官重点问：Vue 熟练度、业务落地速度、组件化、沟通协作。
  • 最大短板与话术：无技术硬短板。注意淡化炫技，多讲"能快速稳定交付业务"。话术："我 Vue 很熟，也做 React，落到具体业务我更关注交付质量与协作顺畅，不追求过度设计。"
  • 投递前必补：无需额外补强，按 Vue 3 深入 复习即可。
  • 打招呼语："我 Vue/React 双栈熟练，能快速稳定落地业务，也有组件化与工程规范经验。"

#3 腾讯外包 · 可观测平台 + 监控 SDK + AI Agent（匹配度约 83% · 10-13K） ​

  • 岗位画像：10000+ 已上市；外包身份，可观测平台 + 监控 SDK + AI Agent，薪资带宽 10-13K。
  • 面试官重点问：监控 SDK/可观测体系、性能采集、AI Agent 界面、SDK 交付。
  • 最大短板与话术：监控 SDK 是 P0 缺口。话术："监控 SDK 关键有三点——可靠上报（sendBeacon）、异常隔离（不拖垮宿主）、可插拔插件（异常/性能/埋点分模块）。"
  • 投递前必补：监控三件套 + WebRTC。
  • 打招呼语："我做过 SDK 交付与性能采集，理解可观测体系与监控 SDK 的可靠上报与异常隔离。"
  • 注意：外包身份与薪资带宽需权衡，建议在 HR 面确认转正/归属/成长后再定。

五、D 级单岗特化概念预习 ​

以下均为1 份 JD 的加分项，属"面试前临时预习"，会讲清核心概念即可，不要求项目经验。

概念是什么一句话讲清
企微 JS-SDK 免登三跳企业微信免登流程三跳 = ①跳转企微授权页拿 code → ②用 code 换 access_token/用户身份 → ③带上身份进入业务页并免登（服务端配合）
公众号网页授权微信网页授权snsapi_base（静默拿 openid）与 snsapi_userinfo（弹窗拿用户信息）两种 scope；流程：跳授权页 → 回调带 code → 换 access_token 与用户信息
信创兼容国产化环境适配国产 OS + 特定浏览器内核，差异在内核版本/特性支持；用特性检测 + polyfill + 降级，避免依赖新语法
AntV蚂蚁可视化体系G2（统计图表）、G6（图关系/图编辑）、X6（流程图/图编辑）、L7（地理空间）
Docker / K8s容器化与编排Docker 把应用打包成镜像；K8s 编排容器（Pod/Service/Deployment），前端关注"构建镜像 → 部署"链路
WebRTC实时音视频采集（getUserMedia）+ 建连（RTCPeerConnection + 信令 SDP/ICE）+ 传输；多人用 SFU/MCU 架构
监控 SDK可观测采集端采集（异常/性能/埋点）+ 可靠上报（sendBeacon）+ 异常隔离 + 采样 + sourcemap 还原

预习策略：每个概念记"定义 + 一个关键机制 + 一个应用场景"三句话即可；被深挖时用 面试总览 的"讲不清"补救话术过渡。

六、投递顺序与演练节奏 ​

按 备战路线 的三梯队推进，先练手找手感、再冲刺最想去的岗位：

阶段目标岗演练重点
练手#5 掌上智珠打磨自我介绍、答题节奏、项目叙述的"问题-方案-权衡-结果"四段式
找手感#1 / #4 / #10 / #6暴露短板、验证"必补清单"里的概念能否讲顺
冲刺#9 / #7 / #8 / #2用最好状态投递最想去的岗位，匹配度与回报综合最优
权衡#3 腾讯外包若考虑，先在 HR 面确认归属/成长/转正，再决定是否投

面试前 30 分钟热身清单 ​

  1. 复述一遍统一叙事主线：双栈同构组件库 + IoT 跨端 + AI 工具链质量门禁。
  2. 默背 3-5 个量化项目战绩（首屏耗时、包体大小、缺陷率、复用率）。
  3. 复习该岗"必补清单"里的 1-2 个概念，各准备"三句话"讲法。
  4. 想好 2 个反问问题（优先问业务目标与技术演进）。
  5. 过一遍"讲不清"补救话术，避免遇到盲区后心态崩盘。
  6. 确认岗位编号与方向画像，把打招呼语的第一句对准该岗最强标签。

三遍法结合使用 ​

  1. 第一遍 · 全局：通读 面试总览 建立答题方法论与叙事主线。
  2. 第二遍 · 补弱：对照各页题库只攻薄弱项，重点补 js-questions 与 browser-network-questions。
  3. 第三遍 · 表达：按本页逐岗演练，把知识打磨成"被问到能讲 3 分钟"的口语化表达。

面试要点 ​

  1. 第一梯队怎么准备？ 按 #9 → #7 → #8 → #2 顺序，各自点开"必补清单"定向预习，优先投递。
  2. 第二梯队补什么？ #1 补 WebRTC、#4 补 Node/Nest、#10 补 RN/流式、#6 补信创/公众号，各补 1-2 项即可投。
  3. 保底与谨慎？ #5 无硬短板、淡炫技重交付；#3 外包需在 HR 面确认归属与成长。
  4. D 级盲区怎么答？ 记"定义 + 关键机制 + 应用场景"三句话，能讲清概念即可，深挖时用补救话术过渡。
  5. 打招呼语的作用？ 一句话命中该岗最强标签（组件库/大屏/IM/AI），让面试官快速给你"对口"定位。
  6. 表达一致性？ 所有岗位都复用统一叙事主线（双栈同构组件库 + 跨端 + AI 工具链），只按岗调整重点。
