音视频媒体前端专项：MSE / Web Audio / 播放器 ​

对应 JD：思维巡航 #11 优先考虑第 1 条（MSE / Web Audio API、音视频播放器、编解码或传输）。WebRTC 实时通话 另有专页，本页聚焦流媒体播放与媒体处理。

一、音视频前端全景图 ​

text
采集 getUserMedia / getDisplayMedia
  ↓
处理 Web Audio API(音频) / Canvas + WebGL(视频帧)
  ↓
编码/解码 硬编硬解(MediaRecorder / WebCodecs / video 标签)
  ↓
传输 WebRTC(实时低延迟) / MSE + HLS/DASH(流媒体播放)
  ↓
消费 <video> 播放器 / Web Audio 输出

两条主线：实时通信走 WebRTC（毫秒级延迟，见专页）；流媒体播放走 MSE（秒级~十秒级延迟，点播/直播拉流）。

二、<video> 播放器原理 ​

原生 video 事件流是播放器开发的地基：

ts
video.addEventListener("loadedmetadata", () => {
  // 拿到 duration/videoWidth/videoHeight，可做封面与比例适配
});
video.addEventListener("timeupdate", () => {
  // 播放进度（约 250ms 一次），驱动进度条
});
video.addEventListener("waiting", () => bufferEl.show()); // 卡顿中
video.addEventListener("playing", () => bufferEl.hide()); // 恢复
video.addEventListener("error", (e) => {
  // video.error.code: 1=中断 2=网络 3=解码 4=格式不支持
});

自研播放器 = 状态机（idle/loading/playing/paused/seeking/ended）+ UI 层 + 缓冲策略。成熟的几件事：倍速、清晰度切换（换 src 会断流，MSE 可无缝切）、循环、画中画、全屏、弹幕同步。

三、MSE（Media Source Extensions） ​

MSE 让 JS 可以把媒体分片手动喂给 video，从而实现：自定义加载策略（边下边播、预加载 N 秒）、无缝清晰度切换、直播拉流、加密播放。

ts
const mediaSource = new MediaSource();
video.src = URL.createObjectURL(mediaSource);

mediaSource.addEventListener("sourceopen", () => {
  const sb = mediaSource.addSourceBuffer('video/mp4; codecs="avc1.64001f"');
  fetchSegment(0).then((seg) => {
    sb.addEventListener("updateend", () => fetchSegmentNext(), { once: true });
    sb.appendBuffer(seg); // 追加 fMP4 分片
  });
});

要点：

  • 分片必须是 fMP4（fragmented MP4）或 WebM 容器，普通 MP4 不能直接 append；
  • 播放器基于 video.buffered 判断可播区间，缓冲不足触发 waiting；
  • 直播低延迟方案：HLS（切片 + m3u8 索引，延迟 6-30s）→ LL-HLS（亚秒级）；DASH 是国际版 HLS；hls.js / dash.js 就是「HLS/DASH 清单解析 + MSE 喂流」的实现。

四、Web Audio API ​

AudioContext 是一个音频处理图：源节点 → 处理节点 → 目的地。

ts
const ctx = new AudioContext();
const src = ctx.createMediaElementSource(audioEl);
const gain = ctx.createGain(); // 音量
const analyser = ctx.createAnalyser(); // 频谱分析（可视化）
src.connect(gain).connect(analyser).connect(ctx.destination);

// 实时频谱（音乐可视化/语音波形）
const data = new Uint8Array(analyser.frequencyBinCount);
analyser.getByteFrequencyData(data);

常用能力：音量/淡入淡出（GainNode）、均衡器（BiquadFilterNode）、变声与混响（ConvolverNode）、录音（MediaRecorder 或 ScriptProcessor/AudioWorklet）、可视化（AnalyserNode + Canvas）。

注意：AudioContext 必须在用户手势后才能 resume()（自动播放策略），否则状态停在 suspended。

五、编解码常识（讲清概念即可） ​

概念一句话
编码格式视频 H.264（通用）/ H.265 / VP9 / AV1；音频 AAC（通用）/ Opus（WebRTC 默认）
码率每秒数据量，越高越清晰越大；直播推流常 2-8 Mbps
帧率每秒画面数；24/30/60fps
GOP两个 I 帧间的距离；GOP 越大压缩率越高，但 seek/入会越慢
转码解码 → 处理 → 重编码；CPU 软编通用慢，GPU 硬编快（NVENC/AMD VCE）
WebCodecs新 API，JS 直接调用底层编解码器，帧级控制（AI 推理/剪辑场景）

与简历的桥接：视频合成工具项目用 fluent-ffmpeg 做过混剪/滤镜/水印/转码（含显卡硬编加速），说明对编解码管线与转码参数（码率/帧率/分辨率）有实操理解——面试时把 ffmpeg 经验翻译成这条叙事。

六、常见坑 ​

  1. 自动播放被拦：带声播放必须有用户手势；策略是先 muted 自动播 + 覆盖「点击开启声音」。
  2. 移动端全屏强制：iOS 需 playsinline 属性才允许内联播放，否则自动全屏接管。
  3. MSE 内存泄漏：SourceBuffer 只进不出会撑爆内存，长时播放需定期 remove() 已播区间（abort() → remove(start, end)）。
  4. 清晰度切换断流：直接换 src 会重载黑屏；用 MSE 双 SourceBuffer 预缓冲新清晰度后再无缝切换。
  5. AudioContext 不出声：忘了在手势里 resume()；或 createMediaElementSource 后忘了 connect 到 destination（接走后 video 原始输出会静音，属正常现象）。

面试要点 ​

  1. MSE 是什么、解决什么？ 让 JS 手动向 video 喂数据分片，实现自定义缓冲、无缝切清晰度、直播拉流与加密播放。
  2. HLS 和 WebRTC 怎么选？ 点播/直播观看选 HLS/DASH（延迟秒级、CDN 友好）；连麦/会议/语音助手选 WebRTC（亚秒级、P2P/SFU）。
  3. Web Audio 的模型？ AudioContext 图：源节点 → 处理节点（Gain/Filter/Analyser）→ destination，声明式连线。
  4. 自研播放器核心？ 状态机 + 事件驱动（loadedmetadata/timeupdate/waiting/playing/error）+ buffered 缓冲管理。
  5. GOP/码率是什么？ GOP 是 I 帧间隔（影响 seek 速度与压缩率）；码率决定清晰度与体积的平衡。
  6. 你的媒体处理经验？ ffmpeg 实战：混剪/滤镜/水印/转码 + 硬编加速；前端侧理解 MSE 播放链路与编解码参数含义。
