Nest.js 后端框架 ​

本页对应 JD 要求 B9（Node.js / 服务端基础）、模块 12（全栈与后端协作，#4 中科创达、#10 欣农互联），以及 JD 整合总纲的 P2 补强策略："面试前做 Nest.js 最小 CRUD Demo（模块 / 控制器 / 服务 / DI + JWT + Prisma/TypeORM），挂 GitHub；措辞从『了解』升级为『熟悉 + 工具链级能力』"。Nest 的装饰器 + 依赖注入 + 分层，几乎是"组件化思维的后端映射"，是前端补齐全栈短板性价比最高的选择。

一、定位与整体架构 ​

Nest.js 是渐进式 Node 服务端框架，底层默认 Express（可切 Fastify），上层提供模块化 + 依赖注入 + 装饰器 + 分层的企业级架构，借鉴 Angular 的工程组织方式，TypeScript 优先。

概念职责前端类比
Module组织单元，声明 controllers/providers/imports/exports功能目录 / workspace 包
Controller路由入口，解析请求与响应页面 / API 路由
Service（Provider）业务逻辑，可被注入hook / store / service 层
DTO数据传输对象，定义入参形状请求参数类型 + 校验
Entity数据库表映射后端侧数据模型

请求自上而下：Client → Middleware → Guard → Interceptor → Pipe → Controller → Service → (DB) → Interceptor → Filter。脚手架：npx @nestjs/cli new nest-demo（选 pnpm），nest g resource user 一键生成 module/controller/service/dto/entities。

二、模块、控制器、服务与依赖注入 ​

Nest 的 DI（依赖注入） 靠装饰器 + 元数据反射：@Injectable() 标记可注入，构造参数类型被反射记录，容器按类型解析并实例化。

ts
// user.module.ts —— 组织单元
import { Module } from '@nestjs/common';
import { TypeOrmModule } from '@nestjs/typeorm';
import { UserController } from './user.controller';
import { UserService } from './user.service';

@Module({
  imports: [TypeOrmModule.forFeature([User])], // 该模块可用的实体仓库
  controllers: [UserController],               // 路由
  providers: [UserService],                    // 容器负责实例化
  exports: [UserService],                      // import 本模块后可注入
})
export class UserModule {}
ts
// user.controller.ts —— 只做路由与参数解析，不写业务
import { Controller, Get, Post, Body, Param, ParseIntPipe } from '@nestjs/common';
import { UserService } from './user.service';
import { CreateUserDto } from './dto/create-user.dto';

@Controller('user')                                          // 路由前缀 /user
export class UserController {
  constructor(private readonly userService: UserService) {} // 构造器注入

  @Get(':id')
  findOne(@Param('id', ParseIntPipe) id: number) {           // Pipe 把 string 转 number
    return this.userService.findOne(id);
  }

  @Post()
  create(@Body() dto: CreateUserDto) { return this.userService.create(dto); }
}
ts
// user.service.ts —— 业务逻辑与数据访问
import { Injectable, NotFoundException } from '@nestjs/common';
import { InjectRepository } from '@nestjs/typeorm';
import { Repository } from 'typeorm';

@Injectable()
export class UserService {
  constructor(@InjectRepository(User) private readonly repo: Repository<User>) {}
  async findOne(id: number) {
    const user = await this.repo.findOneBy({ id });
    if (!user) throw new NotFoundException(`user ${id} not found`);
    return user; // 返回对象即自动序列化为 JSON
  }
  create(dto: CreateUserDto) { return this.repo.save(this.repo.create(dto)); }
}

要点：Provider 默认单例（Scope.DEFAULT），可选 REQUEST/TRANSIENT；未注册进 providers 会在注入时报 Nest can't resolve dependencies；循环依赖用 forwardRef(() => Mod) 打破，但优先重构分层。

三、请求生命周期与管道 ​

完整顺序（先注册先执行）：

  1. Middleware：最外层，日志 / raw body。
  2. Guard（CanActivate）：鉴权与权限，返回 boolean / Promise / Observable。
  3. Interceptor（前置）：next.handle() 之前，计时、日志。
  4. Pipe：参数校验与转换（@Body/@Param/@Query）。
  5. Controller → Service：执行处理器。
  6. Interceptor（后置）：next.handle() 之后 tap/map，包装响应或缓存。
  7. ExceptionFilter（catch）：捕获异常，决定状态码与响应体。
ts
// 全局管道：自动校验 DTO，未声明字段被剥离（防参数污染）
app.useGlobalPipes(new ValidationPipe({ whitelist: true, forbidNonWhitelisted: true, transform: true }));

// 统一响应拦截器：包装成 { code, data, message }
@Injectable()
export class ResponseInterceptor implements NestInterceptor {
  intercept(_ctx: ExecutionContext, next: CallHandler) {
    return next.handle().pipe(map((data) => ({ code: 0, data, message: 'ok' })));
  }
}

// 全局异常过滤器：把 HTTP 异常转成统一错误体
@Catch(HttpException)
export class HttpErrorFilter implements ExceptionFilter {
  catch(e: HttpException, host: ArgumentsHost) {
    const res = host.switchToHttp().getResponse();
    res.status(e.getStatus()).json({ code: e.getStatus(), message: e.message, data: null });
  }
}

四、DTO 与 class-validator 参数校验 ​

DTO 必须用 class 而非 interface，因为 class-validator 依赖运行时元数据（interface 编译后被擦除，无法挂装饰器）。

ts
// dto/create-user.dto.ts
import { IsEmail, IsString, MinLength, IsOptional, IsInt, Min } from 'class-validator';
import { Type } from 'class-transformer';

export class CreateUserDto {
  @IsEmail({}, { message: '邮箱格式不正确' }) email: string;
  @IsString()
  @MinLength(6, { message: '密码至少 6 位' }) password: string;
  @IsOptional() @IsInt() @Min(0)
  @Type(() => Number) // query/path 是 string，显式转 number
  age?: number;
}

坑：嵌套对象需 @ValidateNested({ each: true }) + @Type(() => ChildDto) 才会递归校验；@Query() 值默认全为 string，数字字段必须转换。

维度TypeORMPrisma
风格装饰器 Entity + Repository 模式schema.prisma 声明式 + 生成强类型 Client

ts
// entities/user.entity.ts（TypeORM）
@Entity('users')
export class User {
  @PrimaryGeneratedColumn() id: number;
  @Column({ unique: true }) email: string;
  @Column() password: string;
  @CreateDateColumn() createdAt: Date;
}

// prisma.service.ts（Prisma）
@Injectable()
export class PrismaService extends PrismaClient implements OnModuleInit {
  async onModuleInit() { await this.$connect(); }
}

通用要点：密码绝不入库明文（bcrypt.hash）；查询明确 select 字段，避免全表与 N+1。

六、JWT 鉴权与 Guard ​

JWT = Header.Payload.Signature 三段 Base64URL，签名防篡改，Payload 可被解码。流程：登录签发 → 客户端带 Authorization: Bearer <token> → 守卫校验 → 挂到 req.user。

ts
// auth/strategies/jwt.strategy.ts（@nestjs/passport + passport-jwt）
@Injectable()
export class JwtStrategy extends PassportStrategy(Strategy) {
  constructor() {
    super({
      jwtFromRequest: ExtractJwt.fromAuthHeaderAsBearerToken(),
      ignoreExpiration: false,
      secretOrKey: process.env.JWT_SECRET, // 从配置注入，勿硬编码
    });
  }
  // 返回值挂到 req.user
  validate(payload: { sub: number; email: string }) {
    return { userId: payload.sub, email: payload.email };
  }
}

// 也可不用 passport：自写 JwtAuthGuard implements CanActivate，canActivate 内
// jwt.verify(token) 成功后把 payload 挂到 req.user 并 return true，失败抛 UnauthorizedException。
// 用法：控制器或全局生效；角色控制 = @Roles(...) + RolesGuard 读 @SetMetadata('roles')
@UseGuards(JwtAuthGuard)
@Controller('user')
export class UserController {}

八、RESTful 与 GraphQL ​

  • RESTful：资源用名词、动作用方法（GET/POST/PUT/PATCH/DELETE），状态码语义化（200/201/204/400/401/403/404/422/500）。接口契约细节见 数据库与 BFF。
  • GraphQL（@nestjs/graphql）：@ObjectType/@Field 定义 schema，@Query/@Mutation/@ResolveField 写解析器。优势是按需取字段、单端点，代价是缓存/限流更复杂，适合字段裁剪强的聚合层。
ts
@Resolver(() => User)
export class UserResolver {
  constructor(private userService: UserService) {}
  @Query(() => [User]) users() { return this.userService.findAll(); }        // ≈ GET /user
  @Mutation(() => User) createUser(@Args('input') dto: CreateUserDto) {      // ≈ POST /user
    return this.userService.create(dto);
  }
}

九、与前端工程习惯的类比 ​

Nest前端对应物说明
Module业务目录 / workspace 包imports/exports = 依赖与对外 API
Controller路由组件 / API 路由只做输入输出
Servicehook / store / service可复用逻辑，走 DI 注入
DTO + class-validatorZod / TS 类型 + 表单校验运行时校验
Guard路由守卫 beforeEach鉴权拦截
Interceptoraxios 拦截器请求前后统一处理
ExceptionFilter全局错误处理 / ErrorBoundary统一错误响应
Pipe表单校验 + 类型转换参数级处理

一句话：Nest 把前端的"路由 + 状态 + 拦截 + 校验"分层规范搬到了服务端，前端理解成本极低。

// auth.service.ts —— 登录校验并签发 token（JwtModule.register 配 global / secret / expiresIn）
@Injectable()
export class AuthService {
  constructor(private jwt: JwtService, private userService: UserService) {}
  async login(email: string, password: string) {
    const user = await this.userService.findByEmail(email);
    if (!user || !(await bcrypt.compare(password, user.password))) {
      throw new UnauthorizedException('账号或密码错误');
    }
    return { token: this.jwt.sign({ sub: user.id, email: user.email }), expiresIn: '2h' };
  }
}

十一、常见坑速查 ​

坑现象解法
provider 未注册Nest can't resolve dependencies加入 providers 或 exports 后 import
DTO 用 interface校验不生效必须 class + 装饰器
@Query 数字是 string比较失败@Type(() => Number) / ParseIntPipe
synchronize: true生产改表丢数据一律 false + migration
循环依赖启动报错forwardRef 或重构分层
全局管道未开校验静默失效useGlobalPipes(new ValidationPipe())
密码明文存储安全隐患bcrypt/argon2 加盐哈希
JWT secret 硬编码泄露即可伪造ConfigService + 环境变量
异常未统一前端拿到多种结构全局 ExceptionFilter
依赖注入用 new单例被破坏、无生命周期一律走容器注入

面试要点 ​

  1. Nest 的依赖注入如何实现？ 答：@Injectable + 反射元数据记录构造参数类型，IoC 容器按类型解析实例化，默认单例，非类 token 用 @Inject。
  2. Nest 请求生命周期顺序？ 答：Middleware → Guard → Interceptor(前) → Pipe → Controller/Service → Interceptor(后) → ExceptionFilter。
  3. Pipe / Guard / Interceptor / Filter 各管什么？ 答：Pipe 参数校验转换；Guard 鉴权；Interceptor 前后横切（日志/缓存/响应包装）；Filter 统一异常响应。
  4. DTO 为什么必须是 class？ 答：class-validator 依赖运行时元数据，interface 编译后被擦除，无法挂装饰器校验。
  5. TypeORM 和 Prisma 怎么选？ 答：要装饰器实体与 Repository 深度定制选 TypeORM；要声明式 schema 与极致类型安全、快速上手选 Prisma。
  6. JWT 的结构与安全性？ 答：Header.Payload.Signature，Payload 可解码但签名防篡改，密钥保密并设过期时间，靠 Guard 校验。
  7. 中间件和拦截器的区别？ 答：中间件在 Express 层、无 Nest 上下文、最先执行；拦截器在 Nest 管线上、可拿 ExecutionContext、能包夹处理器前后。
  8. 如何统一后端响应格式？ 答：全局 Interceptor 包 { code, data, message }，ExceptionFilter 统一错误体，前端只处理一种结构。
  9. 模块的 imports / exports 作用？ 答：imports 引入其它模块的 provider，exports 决定本模块 provider 对外可见范围，类似前端包依赖与对外 API。
  10. 为什么前端转全栈适合从 Nest 入手？ 答：装饰器 + DI + 分层与前端组件化/模块化心智一致，TypeScript 优先，最小 CRUD + JWT 即可产出可展示的 GitHub 项目。
